# Confirmed UI scope

Maintainer requests unified UI based on supplied design archives, new icons
including Presenter, borderless/backgroundless Launcher shortcuts with closer
labels, settings/delete menu on right-click and long touch/click, grid movement,
consistent list states while preserving Presenter thumbnails, dark toolbar glow,
and no main-bar form inputs. They agree to include shared forms/Preferences and
reusable menus/dialogs, then explicitly say “agreed, lets do that”. The grid
question is answered “Reorder a responsive grid”. Existing CYC242 is accepted,
merged and pushed before this cycle. Supplied archive source is retained under
design/; neither its prototype JavaScript nor bundled vendor CSS is a production
runtime requirement.


The maintainer extends this active UI cycle to browser tab titles: prefer the
current document/file/folder name, remove repeated app branding, and retain
useful text for accessibility (app name last where needed). WCAG 2.2 SC 2.4.2
requires descriptive topic/purpose, not a repeated app name; reviewed
https://www.w3.org/WAI/WCAG22/Understanding/page-titled.html . Existing Notebook
and Presenter views already expose document names; other apps mostly retain a
fixed app-plus-suite title. Use content names for resources/workspaces, person
name plus trailing app context for Contacts/Profile, section then Preferences,
and a descriptive app fallback when no content is selected. Preserve static
nonempty HTML titles before startup and leave visible app headings independent.

During review the maintainer reports inconsistent in-window app-title sizes and
main-toolbar backgrounds. They request uniform title/bar/button height, including
dialogs, and preservation of the original slanted colored backgrounds on dialog
close and account/Preferences dropdown controls. Current evidence confirms
separate generic, compact, Presenter and Notebook header rules; the newly added
quiet button class overrides the dropdown marker background. Correct the shared
owners, retain empty embedded collapse, and verify header/control geometry.

Review correction: the maintainer rejects 14px titles and requires titles larger than body text. App and dialog titles now use 1.125rem (18px at the default 16px body scale), preserving 44px control rows and shared chrome. This supersedes the earlier 14px title choice.

Latest review: the maintainer specifies 20px titles. Use 1.25rem for app
and dialog titles, keeping 44px control rows. This supersedes 18px.

Files width review: maintainer reports subtoolbar/content narrower than the
main bar. Shared content has an 80rem cap. Give that existing shell constraint
a configurable maximum and let Files select none, filling the viewport.
Verify both 390px and 1920px layouts, including navigation and list/details.

Maintainer requests all-app review of the shared width limit. None of the
nine shells needs the 80rem cap. Notebook owns its 58rem document width,
Notebook/Presenter own 80rem collection widths, and the profile editor owns
its 48rem form width. Remove the shell cap and temporary Files override;
retain those local content constraints. Verify all nine shells at 390/1920px.

Files message review: maintainer requests the message/error row match the
subtoolbar surface. Add a status-background styling property and map Files
to the same DS background as its navigation; retain status role and marker.

Presenter review: maintainer requests two toolbar levels, moving deck title
and Deck menu into slide actions. Replace live title input with text and an
Edit button opening the shared native dialog. Apply uses existing local RDF
persistence; Cancel/Escape leave the deck unchanged. Deck controls remain
available for empty decks, while slide-only actions hide without selection.
Phone actions wrap, keyboard focus returns to Edit, and no new dependency or
network writer is added. Existing reload/offline coverage follows Apply.

Contacts search review: preserve its inline icon/input composition as an
exception to stacked form labels. Put the decorative icon inside the field,
reserve text padding to its right, and use transparent field/toolbar surfaces.
Keep the accessible search label, native control, focus and filtering command.

Maintainer requests reusable search styling for future list-details search.
Move the compact field/icon/input styles to solid-design list-details, use
prefixed shared classes in Contacts, and document the composition. No new
search behavior is added to other apps. Model filtering stays app-owned.

Contacts action review: move Edit profile and Delete contact into one toolbar
at the top of the selected profile pane. Contacts uses the existing shared
edit command and opts out of the embedded profile edit button through
showEditButton:false. Hide this toolbar while editing; existing Save/Cancel
remain. Profile standalone keeps its default action. Persistence is unchanged.

Presenter dropdown review: maintainer reports the moved Deck menu leaves
the left viewport edge and explicitly prefers CSS anchor positioning. Both
Deck and View options use scoped summary anchors, fixed positioned sheets,
inline/block flipping and full-width-area fallbacks with bounded scrolling.
Checked CSS Anchor Positioning Level 1, sections on anchor scope, position-area
and position-try-fallbacks: https://www.w3.org/TR/css-anchor-position-1/ .
No JavaScript menu-placement path is introduced.

Dropdown lifecycle review: maintainer explicitly requires Escape/outside
click dismissal through native Popover API. Audit finds suite account, Files,
Launcher context menus and Notebook/Presenter status popups already use auto
popovers (including empty popover attributes). Presenter Deck/View options
were details; replace with button/popovertarget and popover=auto, preserving
CSS anchors. Other details are inline disclosures rather than dropdown menus.
Check WHATWG HTML sections 6.12 and 6.12.2 (2026-11-16 living standard),
https://html.spec.whatwg.org/multipage/popover.html . Test native Escape and
outside pointer dismissal plus resize positioning for both Presenter menus.

Popup surface review: maintainer requests no white border and medium shadow
or glow according to light/dark mode. Apply one shared popup appearance class
to native popover surfaces across apps, with medium DS shadow in light mode
and medium DS glow in dark mode. App features retain positioning and content;
remove local shadow overrides. Focus outlines on controls remain unchanged.

Iframe dismissal: maintainer identifies native light-dismiss not crossing
iframe documents and requests a shared small fix. A shell event component
listens for window blur, then checks the settled active element next frame.
If it is an iframe within this shell, hide open auto popovers outside that
iframe. Preserve popovers containing the iframe and manual popovers. Uses
native focus/hidePopover and existing event cleanup; no frame DOM access,
message protocol, content renderer or persistence change is introduced.

Notebook collection review: maintainer requires the collection list/details
to fill the width while document content may stay bounded, and matching list
border/link styles. Remove the document-class treatment and 80rem cap from
Notebook overview. Its document editor retains its 58rem width. Shared category
links drop the old 13px collection-link styling and use only the shared list
row/state classes. This also corrects shared category typography in Presenter
without changing its slide thumbnail composition. Compare Notebook alongside
Contacts/Files/Preferences, including row border and text decoration.

Maintainer clarifies styling ownership: mostly shared components, sparing
app/utility exceptions, and no added nested selectors to achieve that. Move
anchored popup geometry and explicit scope/trigger classes to shared theme;
remove Presenter selector chains and redundant input/toolbar overrides. Share
the title-size token and toolbar title/quiet variants, and remove unused old
Contacts/Files state tokens. App styles retain domain layout and sizing only
where required by their workflow. This is a focused cleanup within CYC248,
not an unrelated rewrite of legacy styles.

Slanted-button review: maintainer requests removal of dropdown hover/focus
shadow while retaining its background transition, and the same transition on
dialog close buttons. Use one directly applied shared marker-button class for
the polygon, marker/accent colors, shadow-free states and keyboard outline.
Shell/dialog styles retain geometry only; remove duplicated pseudo-elements.

List-pane width review: maintainer reports remaining differences. Files had
a 210px grid column and catalog a 13rem override. Remove both and rely on
shared list-details grid sizing. Set the existing suite DS list-width token
to 20rem rather than font-context-dependent 20em; retain phone full-pane
behavior and Presenter slide-thumbnail layout. Compare actual pane bounds
across Preferences, Contacts, Notebook and Files in the browser.

Launcher drop preview: maintainer requests a visual landing marker during
icon drag. Bind a shared insertion-marker class to the destination shortcut
through SimplyFlow; show the before-target position matching actual reorder.
Reuse it for Move-to pointer/keyboard targeting. Clear on leave, cancellation
or completion. Preview does not mutate ordering or persisted native RDF.

Shortcut label review: maintainer requests at most two lines with ellipsis.
Apply a shared two-line label utility; keep complete text in the link and
provide its full label as a native title tooltip. No truncation of RDF names.

Launcher density review: text scaling does enlarge rem-based grid/icon
dimensions, but maintainer confirms excessive space also at 100%. Reduce
the grid minimum from 8rem to 7rem and gap to 12px, remove outer tile padding,
and use 4px link/Add padding without the old minimum-height filler. Preserve
text scaling, 64px default icons and two-line complete accessible names.
Check normal/120% scale and phone reflow.

Launcher end-drop review: maintainer cannot drop after the last shortcut.
Treat the Add apps tile as an explicit end destination, show the insertion
marker before it, and append through the existing native reorder/save action.
During menu-based Move-to, its label becomes Move to end and keyboard activation
uses the same destination; ordinary Add apps still opens the catalog.

Toolbar surface review: maintainer now requests transparent fixed toolbars,
explicitly excluding floating ones. Main bars, contextual bars and dialog
header/footer action areas become transparent; floating toolbars/popovers keep
their surfaces and elevation. Consolidate duplicate shared toolbar rules into
the toolbar component and remove the now-redundant quiet variant. Files status
and navigation both expose the same underlying page surface. Slanted button
colors and hover/focus feedback are retained. This supersedes earlier filled
main-bar styling and Files status-background mapping.


Launcher title correction: the maintainer requests the same dark-mode text
shadow as shortcut labels. Reuse the shared header text-shadow property and
map it to the existing Launcher label shadow in explicit and automatic themes.
Light mode remains unshadowed. This is a local CSS-only change within CYC248;
app boundaries, offline recovery, phone controls and download graph are unchanged.


The maintainer requests more prominence for the Launcher workspace title.
Use 1.5rem (24px default), scaling with text preferences, through the shared
header's optional title-size property. Other app and dialog titles retain
1.25rem. This local styling refinement leaves app boundaries, persistence,
offline recovery and interactions unchanged and adds no download dependency.


Add-apps dialog refinement: promote “Choose an app to add to Workbench”
to the dialog title, removing the repeated idle status text and empty status
spacing. Retain the live status region for loading, results and errors and
the existing accessible dialog title association. This local presentation
change leaves app boundaries, offline recovery and actions unchanged.


The maintainer also requests Contacts-style Search apps. Apply the existing
shared inline list-search classes to its label, icon and input: icon inside
the field, text inset to the right, transparent surface, no new CSS or
nested selectors. Search command, accessible label and filtering stay intact.

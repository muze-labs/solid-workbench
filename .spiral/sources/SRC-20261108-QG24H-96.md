# Event subscriptions and implementation authorization

Maintainer discussion on 2026-11-08 extends DES94 to custom/library events:

> What I'd like is if this events system is configurable in such a way that I
> can hook specific events into it, or even custom events that a separate
> library may provide. Is that possible in the current design?

The proposed extension supports a target resolver returning a standard
EventTarget, or a subscription function returning an unsubscribe function.
Both forward original arguments to the current action and own cleanup.
After discussing hooks versus events, the maintainer authorizes proceeding:

> Ok, lets try this design.

Retain the events name and experimental separate-package boundary (SRC95).
This authorizes implementation/evaluation in CYC92 after its design discussion;
it does not establish human acceptance or authorize commits, publication,
external repository changes, integration or push.

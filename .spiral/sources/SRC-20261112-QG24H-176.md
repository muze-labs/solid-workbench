# Confirmed Presenter continuation

The proposed next cycle was a first usable Presenter deck: two layouts, text
creation/editing, Files image selection, native RDF/local recovery and Pod sync,
and local keyboard/phone presentation. The stated gaps were multiple views,
text authoring and bounded content. After closing the icon cycle, the maintainer
instructs “continue with the next cycle”. This commits the proposed scope without
requiring a second scope confirmation. The maintainer subsequently explicitly selects “Store text with the deck
(recommended)”: native RDF text, provider-owned editing, Presenter-owned saving.

Existing code confirms the proposal's gap. EmbeddedView can coexist with other
views but validates only interactive-scroll; Resource Viewer reads text/* and
raster images with no creation/editing. Existing conditional document helpers,
Solid Workspace local Turtle sources and SimplyFlow models can be reused.
SimplyPresent source is locally available at the cited a01a3af commit; its layout
ideas are relevant, its old storage/editor/remote-presenting code is not required.


## Maintainer review and revised design discussion

The maintainer rejects the initial Presenter UI as too narrow an interpretation
of SimplyPresent: insufficient slide styling, names instead of useful thumbnails,
editing disconnected from the slide, and excessive controls occupying the canvas.
They then pause implementation to discuss the design. The revised direction is
one template with a selectable background image (interpretation of the typed
“editable backgrouage”) and a transparent, centered text box with relatively large
text. Styling controls come later. Use list–details with thumbnails on the left,
the slide on the right, and full-screen presenting with previous/next keys.

The maintainer points to muze-labs/margin-notes for Cobalt and linked-data
integration, explicitly authorizes adding a change notification to cobalt-note,
and asks that SimplyFlow's simply.edit floating toolbar inspire a broader Solid
Workbench toolbar design. These are design inputs, not acceptance of the current
Presenter or authorization to publish the Cobalt package. Presenter UI changes
remain paused for design discussion; the narrowly authorized Cobalt change is
implemented independently.

native phone tapping or desktop clicking, focus verification and native input.
The component boundary, persistence and download model are unchanged.

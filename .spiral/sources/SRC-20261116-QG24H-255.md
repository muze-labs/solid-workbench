# Confirmed Launcher grouping direction

The maintainer requests phone-home-screen organization on desktop too, then
clarifies fixed column count and screen width, ordered icons within each screen,
no explicit slots/gaps, no fixed capacity. Four columns, shared vertical scroll,
chevrons, horizontal swipe and focus reveal are confirmed. A shorter screen may
look empty after vertical scrolling; deliberately defer special treatment.
The maintainer accepts scope including simple group create/name/remove and
published parser fix adoption. Current grid is responsive with one rank per
shortcut and has no group controls or membership. Installed parser remains
0.4.4 despite published fixed 0.4.5. These gaps were presented before agreement.
Related roadmap edit was already requested and is preserved on this branch.


Maintainer adds drag affordances: while dragging, each screen has a dashed
border and an empty trailing screen is always available. Only dropping into
that placeholder creates a persistent group. Drag near viewport borders scrolls
horizontally among screens and vertically through the page; stop on drop/cancel
and cleanup. Native gesture and keyboard alternatives require browser evidence.


Maintainer removes the explicit New screen button: use the trailing empty
drop screen to create groups. Expose that same target during keyboard Move to
with a Move here button, preserving a non-drag creation path. Hide visible
screen titles; retain group names in accessible region labels and rename UI.


Refinements during phone review: accessible screen regions are numbered Screen
1, Screen 2, etc. Remove visible screen headings and the standalone creation
button. Recover label space through reduced gaps/padding, retain readable 1rem
labels with whole-word wrapping and two-line truncation. Remove page/scroller/
screen horizontal padding; 390px screen width capped to the viewport on narrower
phones, with only the dashed-border allowance. Other devices use the same
390px width. This supersedes the initial 22rem/360px geometry probe.


Move Add apps out of the icon screens into one bottom-right floating round
button, no visible title, labelled Add apps for accessibility and tooltip. Reuse
shared floating-toolbar surface and light shadow/dark glow. Add to the most
visible screen. Keep Move here endpoints available only during movement, so
keyboard placement and dropping at a group's end remain possible.


Final screen-management correction: no naming, rename or remove controls. Screen
regions use ordinal accessible labels only. After a move or shortcut deletion,
trim empty groups from the right until the last occupied group. Preserve empty
intermediate groups when another screen lies to the right. Keep the implicit
first screen. Group nodes need only type and native integer order; existing
name/unknown RDF remains preserved. This supersedes named-group UI above.


Chevrons are checked independently for left/right overflow, fixed at the
viewport edges, outside layout flow, with 64px hit areas and 48px glyphs.
Showing/hiding them must not shift icons or depend on vertical scrolling.


Latest layout correction: shared screens scroller fills remaining viewport
height, owning both horizontal and shared vertical scrolling, so its native
horizontal scrollbar stays at the viewport bottom. No per-screen vertical
scrolling is introduced. Fixed chevrons remain viewport-bound. Move Add apps
to bottom left and restore normal shared toast positioning; no notification
offset remains. This supersedes the temporary toast offset proposal.


Maintainer reports group membership disappearing on reload while screens persist.
A connected collection regression reproduces it on reconnect: scalar group/order
changes lacked a new dcterms:modified timestamp, so replica arbitration could
choose the older Pod scalar values. Advance every affected shortcut's native
modification timestamp during the move (strictly newer even within one clock
millisecond), preserving scalar merge policy and unknown RDF. Native drop plus
local reload/Pod sync/reconnect must verify membership, not merely screen count.


Insertion-marker refinement: put a screen's first-slot marker inside its
boundary; keep other markers between icons. Use a shared flat inside variant
and fixed 4rem marker height aligned with the icon, independent of label lines.
The height scales with the same text preference as icons.


Label overflow correction: single-token titles use native one-line ellipsis;
multi-word titles use the shared two-line clamp with long-word fallback wrapping.
Full text remains in DOM/accessibility and the existing title tooltip.


Marker stability refinement: use a100ms stable-target delay during native drag,
avoid clearing on nested dragleave/pointerleave transitions, and cancel pending
preview work on drop/cancel/cleanup. Keyboard previews remain immediate. Actual
drops still resolve the current pointer target independently of delayed feedback.
Avoid publishing unchanged group metadata during app moves, reducing redundant
nested-list replacement and focus loss during async UI projection.


Native catalog regression found full-width phone notifications covering the
bottom-left Add action. Keep normal bottom-right toast positioning and expose
a shared available-width token; Launcher reserves horizontal room for its
button. This changes available width only, not the requested toast position.


Remove visible Move here text during native dragging; dashed screens are the
drop affordance. Keyboard Move to exposes the same targets with visible labels
and accessible button names. Late duplicate native dragend must not clear a
subsequent keyboard placement state.


Final maintainer decision, 2026-11-16: “agreed, and cycle accepted”. Keep the
Launcher links' native browser semantics rather than replace them with buttons
for Firefox's browser-level preview. CYC254 is accepted; delivery not requested.

# Confirmed lean-download priority

The maintainer has not observed the Presenter pointer failure and instead
proposes reducing initial JavaScript download size by removing readable code,
leaving future IDE source loading optional and outside normal use.

Investigation finds ?entries-generated authored function/event strings and
explicit JavaScript-as-text module copies embedded in both minified/readable
runtime bundles. Source maps are already separate and not ordinary core requests.
A disposable memory-only build without those source copies reduces normal
complete minified graphs by about 15–32 KB gzip per app; runtime feature code
and HTML/CSS were retained in that probe. Behavior was not yet certified.

After a concrete scope and measurement report, the maintainer says “lets do it”.
This selects the new packaging cycle and authorizes updating the moldability/
build policy to separate optional authoring sources. It does not classify the
Presenter test failure as a product defect or select IDE implementation,
commits, integration or publication. The accepted previous cycle is complete.

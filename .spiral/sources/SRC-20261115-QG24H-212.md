# Published dependency adoption commitment

The maintainer asks to start the next Solid Workbench Spiral cycle, check npm,
adopt published Metro and Solid Tools fixes, remove resolved workarounds and run
required checks. They report Workspace 0.2.2, SimplySolid 0.2.2, Templates 0.1.1
and oldm-shape 0.4.1 and require scope confirmation before implementation.

Preflight presented the current lockfile versus npm latest, the empty-folder
workaround, full-RDF preservation bridge and bounded adoption/evaluation scope.
The maintainer answers “yes”. This confirms the cycle goal, not acceptance of
its implementation or authority to commit or publish.

npm view checked Metro/core 0.9.4, OAuth2 0.9.6, OIDC 0.9.7 and all four reported
Solid Tools versions. Metro Solid remains 0.1.0 and Metro OLDM remains 0.5.1.
Published tarballs inspected in /tmp/solid-release-preflight demonstrate Metro
retaining falsy replayable bodies, Workspace reading direct error.status and
oldm-shape adding its mapped RDF class without replacing other RDF types.
SimplySolid pins the corrected Workspace/shape versions. Templates is not in
this app composition. These are registry/tarball observations, not runtime
verification or claims that unrelated preservation gaps are fixed.

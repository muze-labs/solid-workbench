# Confirmed Presenter collections scope

The maintainer asks for the next cycle after accepted CYC217 delivery. The proposal
is collection-based deck management in Presenter with default/create/open/switch/
make-default, deck links plus one New deck link, reusable collection browsing,
managed versus linked membership and confirmed permanent deletion as in Notebook.
Keep existing direct links, local drafts and dirty-document switching guards;
verify native RDF, offline/conflict/recovery, phone/keyboard, size and full checks.
The maintainer says “agreed”, including the explicitly asked deletion policy.

Inspection: Presenter currently opens one owner-scoped current deck and has no
collection overview/default. Notebook has a full working collection integration;
DocumentCollection, CollectionPreference and ResourceLifecycle already live in
shared data. Its list/details/model projection is still app-owned. These are
concrete reuse and user-workflow gaps, not claims that the current deck editor is
broken. Governing collection design and library review justify the proposed scope.

"Save the current deck before starting another." Inspection and the existing
browser guard test confirm Presenter has one owner-scoped current recovery copy;
its collection overview excludes retained nonmember decks. Thus a hidden draft
can veto New. The maintainer explicitly agrees to extending CYC223 to preserve
separate local drafts and adds that existing local decks should be visible, not
only New deck. This supersedes the single-draft/save-before-switch interpretation
for Presenter, while retaining the requirement to preserve edits, safe provider
teardown, account isolation and conditional Pod writes. No acceptance or delivery
is authorized.

The maintainer subsequently states backward compatibility is unnecessary because
they are the only user, and requests instructions to discard old local decks.
The manual reset names are the solid-presenter and solid-presenter-drafts
IndexedDB databases, with Presenter/embedded Workbench closed. Pod data and
collection links are retained. Remove the migration path; keep the explicitly
confirmed separate-draft behavior for future use. No user browser data is
modified by the agent.

# Separate package before SimplyFlow integration

Maintainer conversation, 2026-11-08, retained verbatim:

> I think adding a new SimplyFlow events section is the correct step, but I
> wouldn't integrate the code for it into SimplyFlow just yet. Lets create it
> as a separate package that we inject into the SimplyFlow set of packages in
> solid workbench itself. If it proves itself, we can always upgrade it to a
> default SimplyFlow component.

This settles the extension/package boundary and supersedes DES94's original
upstream-first proposal. Keep events as component data; implement its support in
a separate experimental package composed here. Core integration is deferred until
evaluation warrants it. The prior design-before-implementation request remains
in force while the revised injection/lifecycle API is discussed. No publication,
external repository work, commit, merge or push is requested.

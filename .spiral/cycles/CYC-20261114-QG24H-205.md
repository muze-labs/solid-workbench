# Notebook collections and document lifecycle

Status: Active, Evaluate / ready for maintainer review. The maintainer confirms Notebook as the first app.
Verified branch: spiral/CYC-20261114-QG24H-205-notebook-collections.
Baseline: c200cb7bdd1209bbb0027e3ca6bfc7e0c60b437c (main/origin-main).

Continue the personal-app foundation and newly incorporated collection design.
Notebook's editor/preferred picker are accepted, but startup selects a device-local
recovery index. No portable document collection/default launch or physical move
exists. Files only writes a conditional parent-description tombstone and retains
bytes. Those effective gaps support the confirmed next-cycle goal.

Deliver portable native RDF collections in Notebook: create/open/switch/default,
independent files, cached summaries/basic grouping, shared conditional physical
move/delete/resolution and retryable interrupted operations. Verify phone,
keyboard, offline/reload and conflicts. Retain current editor/toolbar/recovery.
Prove reuse/format interpretation separately before claiming general compatibility.

The maintainer explicitly confirms managed collection-created documents and
linked additions, whose normal removal leaves content intact. They choose
explicitly confirmed permanent deletion for the first release. No recovery-copy
or trash promise is authorized. Underlying HTTP DELETE must be part of an
explicit, verified PDS-compliant physical operation; the existing Files tombstone
command must not silently become a destructive operation.

Resolve vocabulary/versioning, preference/selection URI fields, operation recovery
and target-server metadata behavior before consequential implementation. Native
RDF remains authoritative; no JSON snapshots. Use existing Metro/document,
SimplySolid/Solid Workspace and OLDM APIs where their public contracts fit.
Document actual gaps before adding narrow integration. No parallel transport,
renderer, broad transaction framework, universal trash, full-text search or sharding.

App boundary: Notebook owns collection navigation/document editing. A narrow
monorepo data module owns portable collection state; lifecycle/resolution are
shared app-independent operations. SimplyFlow owns feature datasets/rendering
and list models; existing Cobalt owns rich content. Keep editable inspection
sources optional at startup. Do not publish a library in this cycle.

Offline/recovery: retain loaded native collections, per-document drafts and minimal
owner-scoped native operation intent through reload/reconnection/account failure.
An unreadable default remains selected, never replaced as if undefined. Uncached
content requires access. Preserve concurrent edits, unknown RDF, identities and
linked-file permissions. Permanent deletion requires explicit confirmation and
strong conditional protection; incomplete outcomes remain visible and retryable.
Phone: collection list and editor core flow, preferred picker, clear action/status
controls and native dialogs. Accessibility: labelled keyboard/AT controls, focus
return, explicit destructive effects and alternatives to gestures. Download:
measure full app/callback and real collection-list task on a slow connection;
list summaries without fetching every document. Budget warnings stay advisory.

Evaluation: actual installed-API/protocol probes first; native graph/concurrency/
operation-boundary tests; independent reader/reuse evidence; phone/keyboard UI;
source/build and required full browser commands. Distinguish simulated servers,
real-server, physical-device/AT and unknown deployment behavior. Record and surface
contradictions before inventing compatibility or irreversible policy.

this cycle. Culture: Muze engineering throughout; library stewardship applies

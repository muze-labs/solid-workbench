# Apply and undo a live Presenter thumbnail template edit

The maintainer selects option 1 from the post-CYC295 roadmap discussion.
[Source](../sources/SRC-20261119-QG24H-301.md)

The verified branch `spiral/CYC-20261119-QG24H-300-presenter-live-template`
starts at `c194fa6` on main. This continues the live-template readiness work
in the Workbench roadmap. Presenter gets one named thumbnail template entry
and a browser proof of applying and removing an in-memory override through
the installed SimplyFlow API. Presenter composes its markup at build time. The fixture uses an in-memory
definition edit in the running app.

## Baseline and approach

A Chrome probe on the accepted build found the row template had no ID or
runtime definition entry. Given the anonymous element directly,
`binding.rerender()` refused to replace a row while its button held focus.
Once focus left the row, it replaced the row and restored the original
markup on undo, with selection, open editor/frame, draft and serialized RDF
unchanged. Use the existing scoped named-template lookup and build-time
include for the authored markup. The test stands in for the future editing
caller, which can coordinate focus by stable slide ID.

## Evidence and guardrails

- Keep changes within Presenter and its browser fixture. Check the edit
  and undo in one production build with existing bindings, commands and
  the same live deck and iframe. Keep the authored component entry intact.
- Check phone-sized layout and native keyboard navigation. Verify the
  focused-row guard and logical focus restoration. Record browser and
  manual accessibility evidence separately.
- Edits to the definition are in-memory only for this proof. Keep the
  existing local drafts, native RDF and reconnection paths. Exercise undo
  with the deck already loaded and verify no Pod writes are caused by the
  override or undo.
- Keep the authored template in View Source and authoring metadata opt-in.
  Measure full minified graphs including the auth callback and cold
  Presenter startup against CYC295. Run `npm run check` and
  `npm run test:browser`, with focused verification of the new proof.

# Inspect a running app from a dockable sidebar

The maintainer selects the read-only inspector, extends it to every top-level
Workbench app, confirms it starts closed, and places Inspect alongside
Preferences in the shared dropdown. Undocking requests a browser popup.
Docking returns the same inspection to a sidebar. Adopt SimplyFlow 0.10.7.
[Source](../sources/SRC-20261119-QG24H-306.md)

The verified branch `spiral/CYC-20261119-QG24H-305-dockable-inspector`
starts at `94a3e9c`. This continues the roadmap's inspect-from-running-view
path. CYC300 proved template edit/undo through the public binding API.
Workbench has no inspector view or dock/window transition. The current
dropdown offers Preferences, and all ten app entrypoints expose runtime
definitions. Account has a separate host.

## Scope and verification

- Open one inspector per top-level app, with a shared sidebar and a separate
  popup presentation. Keep the inspection selection with the inspected app.
  Test both transitions, blocked or closed popups, and two independent apps.
- Verify a pointer and keyboard path from a current Presenter thumbnail to
  its named template and active command. Keep inspection read-only and
  preserve the app's run state, draft, focus recovery and native RDF.
- Start closed and load inspection code and authored source on demand.
  Keep phone layout usable when docked, and test scoped source discovery,
  keyboard operation, and accessibility separately from physical-device
  and assistive-technology review.
- Keep the popup presentation local to the app's origin and exchange
  read-only inspection details. The browser controls how it presents popup
  requests. Keep the inspector docked if the browser blocks opening.
- The inspector can use already-loaded runtime definitions offline.
  Uncached optional sources and popup HTML require the usual browser
  availability. Display runtime information when optional sources fail.
- Verify the published npm workspace graph and measure complete minified
  graphs and ordinary startup requests. Run source and browser checks.

## Review correction

Show the binding graph for a picked element. List the data path, template,
component and active command. Navigate between parents that carry one of
those relationships. Expose authored code on demand and keep it closed
when the selection changes. For generated data, link the runtime path to
the template containing the binding. Use the scoped runtime template
markers and component definitions for ownership.
Show source controls only when a runtime definition or authored source
file exists. Keep other relationships visible as text. A Data entry
shows the bound runtime value as JSON or native RDF as Turtle, alongside source
when available. This stays in the local inspector view.

Show the preview directly below its relationship or parent source control.
The same control toggles its preview open and closed.
Keep long source scrollable within a bounded pane and overlay an X that
closes the preview and returns focus to its trigger. Use the shared app
toolbar with icon-only actions beside the heading and the shared dialog
close button. Align the Account dropdown to its trigger while docked.
Show a crosshair while picking and dim embedded frames with a hint
explaining the boundary. Omit messages that only
announce a successful popup or dock transition.

Remember window or sidebar as a local Workbench preference. Closing
either presentation dismisses the inspector. Reopen in the chosen
presentation on the next Inspect action. Switching presentation is a
specific toolbar action. A blocked popup falls back to the sidebar.

Keep a breadcrumb trail from the picked element through visited parents.
Let the user return to an earlier selection from the trail. Use compact
spacing, right chevrons and an ellipsis for long labels. Give the
docked sidebar a left-edge pointer and keyboard resize handle where the
viewport can accommodate resizing. Keep the resize behavior reusable
within Workbench and the dock full width on phones.
Tint the inspector using Workbench's theme in both presentations, with
a slightly darker surface in light mode and a lighter one in dark mode.

# Shared document save and recovery

Status: Accepted, ready for authorized integration. The maintainer confirms the proposed scope with “yes”.
Verified branch: spiral/CYC-20261115-QG24H-217-document-sessions.
Baseline: 9f2ae843b70bbfd11cb43021056a4d3083eca2b0 (clean main).
Integration target main; require human acceptance and exact integration checks.

Goal: prove and implement a shared save/recovery responsibility for Notebook and
Presenter where it removes duplicated caller coordination. Compare keeping the
current owners with sharing the snapshot/conditional-write/acknowledgement and
local-write ordering algorithm. This continues the high-priority library review
following accepted CYC211 and the updated Spiral core. Broader broker stages,
CSS consolidation, new APIs/packages/publication and sibling work remain outside.

Current gap: both app controllers separately sequence local writes, capture save
revisions, choose existing/new remote records, manage native baselines and apply
acknowledgements without clearing newer edits. Solid Workspace 0.2.2 supplies
local storage and replica ordering but explicitly excludes conditional writes.
The existing loadDocument/saveDocument already own HTTP and safe validators.
A narrow shared owner can compose those contracts, not replace their stacks.

App boundary: preserve Notebook blocks/index/aliases/collections and Presenter's
slides/navigation/current-deck policy. Keep differences in recovery-copy identity,
creation intents, baseline retention and redirect handling explicit. Keep native
StateGraph and collection bridge for unknown/disconnected anonymous RDF.
Offline: retain owner-scoped native recovery copies and edits through failed
local saves, reload, disconnect, HTTP failures, conflicts and missing validators.
Uncached data still requires access. No automatic sync or new retry policy.
Phone/accessibility: existing native Save/Open/Save As, keyboard focus, status and
provider navigation remain; no HTML/CSS change planned. Exercise both core phone
workflows and keyboard paths, distinguishing automation from manual AT/devices.
Download: measure complete graphs/callback and cold core tasks; keep the budget
advisory and optional matching source assets unloaded during ordinary use.

Evaluation: current app tests plus shared cross-app failure/preservation cases;
meaningful use in both apps; exact local schema/backward recovery compatibility;
npm run check and full npm run test:browser; scoped/stock Spiral validation.
Include the new proportional simplification review: algorithm ownership and
removed reasoning burden matter more than line or package counts.
Pause if sharing requires altered switching/data/overwrite policy, extra transport,
unsafe RDF flattening or an unpublished Workspace implementation.
No commit, merge, push, deployment or acceptance is authorized for this new cycle.
Artifacts: SRC218, DES219, IMP220, EVD221.

# Shared embedded views: Files proof

Status: Active. Branch verified spiral/CYC-20261112-QG24H-168-embedded-views,
baseline main 63b0976. The maintainer confirms icons and the proposed following
Files/shared-view cycle: “lets do that and the next cycle you propose as well”.
This independent worktree avoids merging either Active cycle. No commit,
acceptance, merge or push is inferred.

Gap: existing capability dialogs leave a selection call pending and permit only
one embedded task per caller. Files opens ordinary files as downloads and has
no provider-owned persistent details pane. This continues the accepted design
intake's first product proof, not Presenter/widgets/general Weblets completion.

Boundary: Files owns selection/layout; a separate Resource Viewer owns text/image
interpretation and Metro reads. Reuse scoped broker and provider preferences.
Offline: retain loaded content, explicit refresh/retry, no assumed uncached data.
Read-only first provider has no edits to lose; shared transitions must refuse
teardown without a provider prepare acknowledgement or explicit user discard.
Phone: sequential list/details with a Back control, desktop parallel panels.
Accessibility: native controls, labelled iframe, status, keyboard focus and
return; automated evidence is not manual assistive-technology certification.
Download: optional provider loaded only on explicit viewing; measure its full
JS/HTML/CSS/resource graph, no new dependency or font. Budgets stay advisory.

SRC169/DES170 define scope; IMP171/EVD172 record outcome and evidence.


Evaluate: IMP171/EVD172 record the implemented first proof and final checks.
216 source tests / both builds and all nine Chrome suites pass. Phone/desktop
visual review and bounded cold-load measurements are recorded; manual AT,
production OIDC, editors and full recursive Weblets interoperability remain
unclaimed. This cycle is ready for human review and remains Active. No commit,
merge or push. Artifact IDs were reserved in the original worktree before
creating this independent branch/worktree; there is no duplicate allocation.


Maintainer review correction, 2026-11-12: plain text works, but the embedded
viewer repeats the host's “WebID / connection” control. The maintainer requires
embedded viewers to expose only view-specific UI. Inspection confirms the shared
shell enables that task control for every task, including persistent views.
Continue Active CYC168 on its verified branch: opt the viewer into content-only
embedded presentation using SimplyFlow bindings and the existing header component.
Standalone account controls remain useful; resource errors and request-specific
recovery must stay visible. No broker/authentication protocol change or new
cycle approval is needed for this correction within the authorized Files proof.


Further maintainer review: open views on file selection; retain the filename as
an ordinary link to the standalone view; remove View/refresh/close/About/Ready
chrome and the default frame border. Reuse the Preferences loading presentation.
Show recovery only for errors. Limit list filenames with an ellipsis and full-name
title tooltip; the details heading may use all available width, bounded by its
pane/viewport rather than a short fixed cap. Keep full accessible names and
native modified-click/context-menu navigation. These requests supersede this
cycle's earlier explicit View button and always-visible metadata controls.


Maintainer MIME review, 2026-11-12: all `text/*` resources must be viewable as
text, including HTML source. The current exact `text/plain` check leaves this
gap; extend it to the text media family with case-insensitive type matching and
parameter handling. Keep escaped SimplyFlow text rendering, the existing Metro
read path, loaded-content preservation and the same phone/keyboard interaction.
No new app, dependency, network request or offline cache is introduced.

When additional viewers arrive, prefer a matching specific MIME viewer (for
example `text/html`) over the generic `text/*` fallback during default selection.
Preserve deliberate user selection. View-selection tabs are a possible future
UI, not part of this correction; multi-provider discovery/ranking still needs
its own implementation. RFC 9110 sections 8.3.1 and 12.5.1 were checked for
case-insensitive media types, parameters and Accept media ranges:
https://www.rfc-editor.org/rfc/rfc9110.html#section-8.3.1
https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.1
The future app preference is product policy, not a claim that HTTP specifies
capability-provider ranking. UTF-8 decoding remains the existing response.text
behavior; this correction does not introduce charset negotiation.


Review corrections evaluated: 216 source tests and all nine Chrome suites have
passing results, including the targeted continuations documented in EVD172.
Automatic opening, bounded linked filenames, content-only presentation, text/*
fallback and same-provider reopening are ready for review. The exact-MIME
preference and possible view tabs are recorded as future work. Remain Active;
only the maintainer can supply acceptance. No commit/merge/push requested.

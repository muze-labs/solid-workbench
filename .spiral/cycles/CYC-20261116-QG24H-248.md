# Shared UI design and responsive Launcher

Status: Active. Goal confirmed by “agreed, lets do that”.
Baseline main ac51ccff30473ccf817bcbbb02b9c87e121d7ced.
Verified branch: spiral/CYC-20261116-QG24H-248-shared-ui-design.

Scope: supplied form theme and Maya icon pack (including Presenter); consistent
list row normal/hover/focus/selected states in apps/dialogs, retaining Presenter
thumbnails; common form labels/help/errors/disabled/save states and Preferences
review; buttons/text/status only in the top main bar; dark floating-toolbar glow.
Launcher removes icon/card backgrounds, borders and persistent settings link,
uses closer icon/label spacing, right-click/long-press menu with settings/delete,
and drag/drop reordering with keyboard/non-drag equivalents. Maintainer selects
responsive grid reordering, not persistent empty cells.

App boundaries and storage owners remain unchanged. Reordering is local-first,
persisted as native RDF while retaining unknown values and shortcut identity;
reload/offline and synchronization/conflict preservation require evidence.
Phone core: scrolling remains available, long press opens menu, movement is
available without drag; forms remain usable with narrow viewports and keyboard.
Accessibility: native labelled controls, visible focus, menu keyboard access,
focus return and non-pointer movement; separate browser checks from manual AT.
Download: reuse installed the-ds/SimplyFlow, no second vendor stylesheet or font
requests, measure complete graphs and icon payload. Budgets stay advisory.

Roadmap: shared form language, per-app/Preferences review and reusable design
components. No broker/editor feature expansion, naming sweep or generic toolbar
abstraction. No commit, merge, push or publication authorized for this cycle.


The maintainer extends this active UI cycle to browser tab titles: prefer the
current document/file/folder name, remove repeated app branding, and retain
useful text for accessibility (app name last where needed). WCAG 2.2 SC 2.4.2
requires descriptive topic/purpose, not a repeated app name; reviewed
https://www.w3.org/WAI/WCAG22/Understanding/page-titled.html . Existing Notebook
and Presenter views already expose document names; other apps mostly retain a
fixed app-plus-suite title. Use content names for resources/workspaces, person
name plus trailing app context for Contacts/Profile, section then Preferences,
and a descriptive app fallback when no content is selected. Preserve static
nonempty HTML titles before startup and leave visible app headings independent.


Maintainer's header review correction: shared main-bar and dialog title size is
14px at default text scale; content/control rows are 44px. One chrome color owns
the main background. App-specific title sizing and Presenter header geometry
are removed, while Notebook's narrow layout retains reachable action rows.
Status/error rows may grow independently; embedded empty headers remain zero.
Slanted dropdown and close backgrounds retain their original marker color and
white icons, with decoration on pseudo-elements to preserve focus outlines.
Native browser geometry checks cover title/button/toolbar/dialog alignment and
colored slanted markers. This correction is authorized within CYC248 review.

Review correction: the maintainer rejects 14px titles and requires titles larger than body text. App and dialog titles now use 1.125rem (18px at the default 16px body scale), preserving 44px control rows and shared chrome. This supersedes the earlier 14px title choice.

Latest review: the maintainer specifies 20px titles. Use 1.25rem for app
and dialog titles, keeping 44px control rows. This supersedes 18px.

Files width review: maintainer reports subtoolbar/content narrower than the
main bar. Shared content has an 80rem cap. Give that existing shell constraint
a configurable maximum and let Files select none, filling the viewport.
Verify both 390px and 1920px layouts, including navigation and list/details.

Maintainer requests all-app review of the shared width limit. None of the
nine shells needs the 80rem cap. Notebook owns its 58rem document width,
Notebook/Presenter own 80rem collection widths, and the profile editor owns
its 48rem form width. Remove the shell cap and temporary Files override;
retain those local content constraints. Verify all nine shells at 390/1920px.

Presenter review: maintainer requests two toolbar levels, moving deck title
and Deck menu into slide actions. Replace live title input with text and an

Phone actions wrap, keyboard focus returns to Edit, and no new dependency or

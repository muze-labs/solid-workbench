## Proposed boundary and evaluation

including available cached contacts, with broader address-book management and
cross-workspace search retained separately. This scope awaits the maintainer's
answer. Returning an identifier is a selection, not sharing/access authorization
or verification that the contact identifier is an authenticatable WebID.

Reuse the existing scoped managed transport, capability dialog, provider
preferences and Contacts model/profile data APIs. Add the selection contract,
provider declarations, permitted routing and narrow native preference support
needed for this second capability. Keep native RDF authoritative and preserve
unrelated provider bindings/unknown terms. No second renderer, registry or
transport. Show meaningful provider UI and use separately hosted caller/provider
fixtures for protocol evidence instead of adding a demonstration-only product
control. Review the concrete caller flow before expansion into sharing.

Offline: list only locally available book data; show incomplete/unavailable data
honestly. Preserve drafts/filter/selection through cancellation, reload,
authentication failure and reconnection. Prevent late/cross-account results.
Phone: searchable list, explicit selection/cancel, selected person's identity
and source, no forced desktop details layout. Accessibility: native controls,
labels, focus/return and keyboard/assistive-technology review. Downloads: reuse
existing app graph and assess complete Contacts/caller/callback cost; budget
warnings remain advisory. Use the original blue/square/panel visual language.

Evaluate native identifier validation, busy/cancel/provider loss, unknown RDF
and draft preservation, untrusted-origin/stale-result rejection, and offline
selection. Run npm run check and complete npm run test:browser, plus core phone,
keyboard and AT observations with their evidence limits. Prove provider changes

provider tests import ManagedApp and therefore do not alone prove independent
implementation. Record actual complexity and unresolved limits, not Phase 3
completion from same-library fixtures. Pause/replan if book identity or routing

## Human review reopens the result contract, 2026-11-12

The maintainer's actual picker returns an opaque contact UUID alone. External
callers cannot obtain its information. Earlier passing identifier-only tests
and ready-for-review notes do not establish a useful recipient integration.
CYC139 stays Active; return to design within this cycle, with no acceptance.

Inspection confirms swb_returnRecipient returns only @id, while the configured
contacts resource is a whole address-book document and may contain local-only
or unsynchronized subjects. A configured Pod URL is not proof of publication,
caller read authorization or current bytes. Preserve identity separately from
retrieval. Proposed revision: return the selected contact's native RDF
information and, where supported by actual source evidence, its document URL.
Only the explicitly selected contact should be disclosed, with the UI showing
what the caller receives; never silently export the whole book or credentials.
The exact disclosure/result contract is presented for confirmation before code
changes, because the previous design expressly returned no contact fields.


## Concrete caller and useful recipient result authorized

The maintainer requests Files Share → choose someone, with no permission-change
flow, and explains that the caller is another app in the same Workbench/user
context. They explicitly choose “Include selected contact data when needed”
for local/unsynchronized contacts. They also request focused picker UIs distinct
from normal apps, reusing only useful shared controls/data APIs. This confirms
the missing caller and result-usability gap and keeps the correction in CYC139.

The revised result retains @id, an optional containing document locator, and a
bounded native Turtle selected-subject description. The built-in picker works
from a local graph, so it supplies that current description as a fallback rather
than asserting all rows/edits are already published. A document locator alone is
read by the caller's own Metro session; no credentials are passed. The picker
previews the exact returned RDF. It includes the chosen subject and anonymous
values, not other named contacts. Shared/cyclic anonymous values are explicitly
refused by this bridge because the installed object-graph writer would flatten
or recurse; there is no silent data loss or full-book export.

Files gets a per-resource Share action and a selection-only summary showing
name, email/phone/public-profile hints and original identity/location. It writes
no ACL or invitation. Cancellation preserves the previous selection. Native
workspace state retains only resource/entity/document references and a label;
contact RDF is never embedded as a serialized snapshot in Turtle state.
Local-only chosen data works without publishing the book. Files' resource picker
gets a task-focused list instead of the normal management table, with existing
folder navigation and native Select/Cancel. No edit/upload/share controls appear
in picker mode. Phone, keyboard, focus, source/draft preservation and complete
download graphs remain the evaluation conditions; prior passes are historical.

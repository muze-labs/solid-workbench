# Shared account status and recovery design

Status: confirmed for implementation by the maintainer’s “Yes”, 2026-11-09.

Reuse the shared SimplyFlow account/recovery feature datasets, current native
connection dialogs and Metro APIs. Add a compact labelled status button beside
the user name; keep the name's Profile action and existing account/Preferences
menu roles. Preferences remains a dialog iframe with no app identity icon.

Account/authentication state and network connectivity are distinct. Display
explicit states for no selected account, intentional local-only disconnection,
restoring/signing in, a verified usable session or public-only connection,
interaction-required recovery and offline connectivity. Token expiry alone must
not imply that silent refresh is impossible or Pod access denied. Derive state
from the installed public APIs and confirmed operations; do not infer complete
Pod permission from a successful login.

Source inspection already finds generic storage listeners and live token-store
reads. Inspect delivery/receipt/UI handling before adding any signaling. Keep
credential ownership in Metro and scoped session policy here. Recovery must
clear only obsolete auth-owned messages, never unrelated errors or drafts, and
must not replay a write merely because a notification arrives.

The maintainer confirms that Disconnect applies to all apps for the selected
account, and managed account switching is coordinated by Workbench so the old
workspace is preserved before the new account's workspace opens. These supersede
the original per-app-disconnect proposal. Device/browser scope is intended;
this is not a request for identity-provider-wide or other-device sign-out.

Confirmed distinction: Disconnect pauses Pod traffic and
automatic sign-in for the account across participating open apps, retains the
selected WebID, local drafts and stored credentials, and survives reload until
explicit Connect. Logout additionally clears this browser's credentials and
remembered selection, preserving owner-labelled local data. Existing lifecycle
rules stay: Launcher logout closes its managed workspace/apps; a child logout
must not close Launcher or siblings. Those apps can remain local/signed out.

Managed switching belongs to Workbench's ownership/checkpoint boundary. A child
requests the Workbench account flow rather than replacing its own identity under
an old-owner workspace. Preserve locally recoverable state before closing apps;
a cancelled/failed handoff keeps the old context recoverable. Reserve sign-in
windows in actual user gestures. Authentication and workspace activation must
not publish another identity's state before a successful coordinated handoff.

## Understanding and observed gap

Outcome: the shared header reflects actual session/connection state, provides
native accessible account actions, and clears obsolete sign-in prompts after
recovery anywhere in the supported suite session, without a reload or draft
loss. A successful login does not imply access to every Pod resource.

An unchanged-product Chrome probe reproduces the reported Launcher problem with

The Preferences editor also retains a separate auth-related status string in
this fixture. This disproves a universally missing same-origin announcement;
source inspection/action probe identifies missing reconciliation of independent
message owners. EVD127 records exact observations and limitations.

## Proposed shared dialog

Keep the name's Profile action and existing account/Preferences menu. Add a
compact native status button beside the name using the shipped Feather glyphs,
with a meaningful status/action label and no colour-only meaning. It opens the
existing shared connection dialog; consolidate recovery controls there where
that preserves explicit pending-operation and focus behavior. No new app, icon
family adoption or third-party account UI is included.

| State | Presentation and action |
| --- | --- |
| No selected account | Not connected; enter WebID and Connect. |
| Intentional disconnected mode | Disconnected; show retained identity and explicit Connect. |
| Restoring or signing in | Connecting; announce progress, allow cancellation, prevent duplicate submission. |
| Usable authorization | Signed in; show the selected identity, without claiming all-resource permission. |
| Public-only session | Public access; do not mislabel a public profile read as authenticated access. |
| Interaction required | Sign in again; preserve the relevant pending operation and local work. |
| Offline | Identify connectivity separately from authentication and keep cached editing available. |

Expired access alone must not pre-empt Metro's normal refresh path. Update state
on actual lifecycle/storage/HTTP outcomes and visibility; avoid a new token
manager or authentication polling transport. Use public APIs for credential
scope/expiry. A credential-change hint from another origin cannot be treated as
verified usable authorization in this origin's independent stores.

## Message ownership and coordination

Retain typed error cause/owner when forwarding errors into shared or app-owned
status, instead of losing it by forwarding only error.message. Reconcile the
recovery notice, shared message and owning app's status when that owner's
recovery is confirmed. Clear only obsolete auth causes; keep access denial,
connectivity/server errors, write conflicts and unsynchronized-work feedback.
Do not label an earlier failed save as successful just because login succeeded.
Existing explicitly pending conditional operations may resume under their
current cancellation/owner checks; a notification must not start an unrelated
write.

Reuse native same-origin storage notifications and Metro's account-scoped stores.
For account-wide disconnect/switch coordination, inspect and extend the existing
private managed channels only for the concrete missing contract. Domain policy
belongs to account/workspace features; broker transport must not become a token
store or authenticate on behalf of providers. No OAuth credentials travel in
notices, launch URLs or workspace graphs. Limit global controls to authorized
account UI/instances; an arbitrary provider declaration is not an account-control
grant. Unknown standalone external origins are not browser-enumerable; scope
cross-origin support explicitly to participating managed suite apps.

Persist non-credential connection intent in native local data if needed for
reload; do not turn a device's disconnect into a shared Pod preference or write
JSON-in-Turtle. Gate new requests and late callbacks by active owner and mode;
explicitly reconcile in-flight uncertain writes rather than claiming cancellation
undid a server commit. Cached data/drafts remain editable and owner-scoped.

Reuse/size inspection is an early design condition: only 37 readable Workbench
bytes remain. Prefer consolidating duplicated account/recovery responsibilities
where the resulting interaction remains clear. Any retirement of exposed APIs,
UI contracts or larger budget allowance requires explicit design discussion;
no cap expansion or source-obscuring compression is authorized.

Applicable culture is CUL-MUZE-001 for suite engineering and CUL-MUZE-LIB-001
for shared packages/tooling, with the adopted architecture philosophy and
WPF-HUMAN-001 authority/evidence lens. Preserve named editable sources and
component-owned layered styles, native data, local recovery and accessibility.

### Completed Connect is the restoration boundary

The issuer probe establishes a timing distinction: raw OAuth stores change while
an authorization exchange is still active. A trial sessionless restoration from
those intermediate changes produced an authorization-state mismatch. It is not
safe to equate a token-storage hint with a completed explicit Connect.

Use an account-scoped non-credential `solid-apps.connected:<WebID>` nonce on the
existing localStorage notification mechanism, after session.signIn completes and
the initiating attempt is still current. A sessionless recipient restores only
its already-selected WebID, noninteractively, after its startup promise finishes.
Coalesce repeated completions and recheck owner, local interactive work, logout
attempt generation and intentional disconnection before restoration. Existing
live recipients keep the established shared-authorization reconciliation. Raw
OAuth changes alone must not construct another session during sign-in.
This is an app lifecycle notice, not an authentication grant or token transport.

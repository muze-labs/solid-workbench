# Named workspace foundation and Launcher home

Status: Confirmed product goal; technical design for implementation, 2026-11-08.
Current effective code persists one workspace plus one shortcut collection and
shared app settings. The existing broker already checkpoints/restores app state;
SimplySolid manages collection replicas; Solid Workspace supplies native local
sources. Reuse those APIs rather than adding storage or transport infrastructure.

## Native persistence

Extend the current native workspace graph with a linked directory, stable default
identity, active workspace and named entries. Each entry has a title, private
storage endpoint references and explicit app settings. Save inactive instance
sets using the existing native workspace/app-state encoding; keep the active set
at the current root. This uses existing conditional writes, local native Turtle
cache and baseline comparison. Do not encode JSON snapshots in Turtle. Preserve
unknown predicates/subjects and never follow data links for deletion.

Keep shortcuts as SimplySolid collections, with a distinct collection location
per workspace; default reuses the existing configured location, new workspaces
receive separate locations. Scope local replicas to owner/resource. Preserve old
local data and provide explicit recovery/import rather than silently assigning
unknown-owner legacy records. Default setup seeds Files links for profile and
private roots once, retaining user changes on subsequent loads.

## Settings and context

Common preferences remain in the profile-linked preferences file. Workspace app
settings reside in linked native workspace nodes. Existing suite apps receive
only their settings via the existing verified private managed channel, before
restoring app state. Accept settings changes only from an active bound instance
for its own supported app keys. No credentials or broad workspace registry are
sent to apps. Standalone apps retain current shared app defaults. No multi-book
Contacts/search/picker behavior is included.

## User interface and lifecycle

Home shows editable title, Launcher-owned workspace-switch menu, icon shortcuts,
Add shortcut and user recovery feedback. Technical workspace controls remain in
an optional diagnostics disclosure. Preferences owns management and private root/
app-settings fields. Use registered SimplyFlow features, models for transformed
lists, existing menu/dialog components and native focus. Prefer familiar actions,
progressive disclosure and usable targets; read lawsofux.com/llms.txt as required.

Icons use explicit application descriptions plus stored user overrides; plain
links remain supported with a labelled fallback. Fetch metadata only through
Metro/data clients, and retain usable cached shortcut labels/icons offline.
Support the suite's native RDF application manifest convention, documented and
shipped with built-in apps; do not require an app store or infer capabilities
from an icon/manifest. No executable third-party manifest content.

Switch: serialize against mutations, checkpoint current apps, await durable local
state, prepare target collection/state, close/dispose old managed set, activate
and restore target. Abort before closing on checkpoint/storage failure. Retain
native app drafts and old workspace when restore is blocked/partial; expose
Restore apps visibly. Switching does not require a successful remote save and
retains existing explicit Pod checkpoint/conflict actions. Recheck deletion
eligibility at mutation time. Default replacement needs positive missing data,
not network/auth failure. Account changes require an explicit fresh owner context;
never write another owner's state.

## Evidence and constraints

Test data and lifecycle contracts, unknown RDF preservation, storage failure and
cross-origin context authority, then phone/keyboard/home and workspace workflows.
Measure complete graph cost; remove genuinely unused shared code from an app's
load graph if necessary, without hiding required work behind lazy loading or
reducing retained source/readability. Any such build change is budget support
inside this cycle. Preserve previous intermittent workspace timing evidence.

CUL-MUZE-001 shapes bounded coherent workflows; CUL-MUZE-LIB-001 shapes reusable
bridges and affordable readable delivery. Existing native data/rendering/network
requirements constrain every choice. Human acceptance is pending.


The maintainer authorizes temporary budget expansion after the 205233-byte

for that variant and retain the original 200000 elsewhere; measure and revisit
rather than move scope into a separate diagnostic app. A temporary per-feature
chunk split increased the graph cost and was reverted.

## Reviewed home-screen correction

Retain a single heading in the existing account header, bound to the active
workspace title. Add workspace choices to that header's existing dropdown only
when multiple workspaces exist. Remove the separate home toolbar and routine
workspace-save/status controls. Preferences provides an explicit Diagnostics
button opening a Launcher-owned dialog, closing Preferences first so checkpoint
operations can run. Keep the existing diagnostic features in that dialog;
optional preference tabs are deferred because a direct entry meets this review.
An icon tile labeled Add shortcut sits in the shortcut grid. Shortcut options
open native dialogs instead of inline disclosures. Home retains only essential
failure recovery feedback; no home disclosures. SimplyFlow owns all content,
existing design components own native dialogs and keyboard dropdown navigation.
No persistence format/network/offline contract changes are needed. Verify the
single-workspace menu, keyboard switching with multiple workspaces, accessible
icon action, diagnostic entry/focus and unchanged save/recovery workflows.

## Preserve the Launcher tab during workspace switching

After opening the target workspace's saved app set, restore activation to the
existing Launcher browsing context as well as focus to its heading. Use native
window operations, never navigation or content DOM rendering. Limit this to the
workspace-switch path; explicit shortcut launching keeps its existing activation
behavior. Verify actual document focus in Chrome after the app's managed
restoration completes, alongside retained app state and switching safeguards.

The focus-preservation proposal above is superseded by browser evidence and the
maintainer's explicit choice to keep tabs and accept browser-controlled focus.
Chrome requires transient activation for page focus, while opening the restored
tabs consumes it. Self-focus and named-context focus attempts fail the actual
browser assertion. Remove those attempts rather than claiming a focus guarantee.
Retain DOM heading focus within the Launcher, ordinary shortcut activation, and
normal multi-app tab restoration. No popup-policy or persistence change is made.

## Confirmed workspace backgrounds and shared Feather conventions

Use the maintainer's complete Feather symbol sprite as feather-icons.svg in the
shared assets; markup uses the-ds ds-icon/ds-icon-feather SVG/use conventions.
Default app manifests refer to its folder/users/user/grid symbols; custom image
URLs remain supported. Keep old standalone app-icon URLs usable for saved links,
while projecting recognized former defaults onto the shared sprite. Common WebID
and Preferences items precede workspace entries; workspace buttons include a
layers icon so identical labels are distinguishable.

Each workspace owns an optional apps:background resource reference. Stable preset
IRIs identify the six bundled photos; HTTP URLs identify custom/Pod images; a
new local upload uses a UUID resource IRI until explicit Pod save. Main state
remains native RDF, including unknown-fact preservation. Keep image bytes in a
small owner-scoped CacheStorage bridge because installed Solid Workspace 0.2.1
local sources accept only Turtle strings. No new transport/auth/JSON persistence
is added. Uploaded JPEG/PNG/WebP files are decoded/validated and limited to 5 MB;
cache bytes before staging their native reference. Failed storage preserves the
previous choice, and failed upload retains pending bytes/reference for retry.

Save to Pod conditionally creates pending binary images beside the configured
workspace document using the existing Metro client before saving directory state.
A lost upload response is recovered only by comparing the existing image bytes
on a conditional-create conflict; never overwrite a different resource. Keep the
old local bytes and URI if upload, acknowledgement or local staging fails.
Workspace deletion retains images just as it retains other linked datasets.

SimplyFlow binds a decorative background image behind the Launcher and all
preference fields. Resolve image bytes from the cache first; Metro loads uncached
URLs/presets, and a missing offline image falls back to the normal theme while
retaining the choice. Optional image loading must not block usable shortcuts.
Only the chosen background loads; presets are not all requested at startup.
Opaque theme surfaces behind shortcut labels/header preserve contrast. Native
file selection and object URLs are non-rendering operations; revoke replaced
object URLs. Preferences offers native select/URL/file controls with progress
and errors. Verify phone/keyboard, per-workspace choice/reload, cached images,
conditional upload/retry and fresh-browser restoration, and measure sprite/image
cold bytes separately from complete JS graphs. Existing budget exception remains
visible; new readable cost must be measured rather than hidden by lazy loading.

## Theme-aware home text

The home foreground follows the-ds --ds-color rather than fixed white. Default
light mode has no text shadow. Explicit ds-darkmode and ds-darkmode-auto under a
dark prefers-color-scheme retain the established dark outline/shadow. Explicit
light must remain shadow-free even when the OS preference is dark; explicit dark
must retain its shadow when the OS is light. Reuse current DS classes/media
queries, with no second theme state or new persisted setting. The filled dropdown
marker and white-on-accent icon glyphs retain their own contrast colors. Verify
actual Preferences switching plus automatic theme responses and a light-mode
phone preview. No data, image cache, renderer or transport changes are needed.

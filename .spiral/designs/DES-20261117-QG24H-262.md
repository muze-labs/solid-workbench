# PDF annotation integration contracts

Active design for CYC260, based on confirmed SRC261. No accepted implementation
is claimed. Baseline main d96c9b87e84d260da7bf69cee2e4ed93741081ad.

Documents is a new focused app. PDF.js owns its document surface; SimplyFlow
owns application content. HTML annotation display is independent of Cobalt.
Editor invocation uses a versioned edit-note-body contract with HTML input and
output, optional native fragment data, stable draft identity and cancellation.
Default Cobalt editing is loaded only for editing. Replacement providers use
the existing provider preferences and capability presentation mechanism.

Each PDF-and-named-group pair is a native Turtle graph with one collection root,
label and membership links. Annotations have separate stable identifiers within
that graph, HTML bodies, targets and version-bound selectors. Preserve unknown
statements and subjects. Do not flatten unsupported structured edits.
Store these resources in a separate annotations folder chosen independently
of the PDF URI. An index can map (PDF URI, group identity) to resource URI.
Source PDFs may belong to unrelated Pods or websites; never require their
write permission. Stable group identity is distinct from each per-PDF resource.

Use the existing saveDocument helper: strong If-Match for existing resources,
If-None-Match for explicit creation. Its missing-validator refusal and unknown
outcome errors are part of the contract. Local drafts remain after rejection.
Default personal groups stay local until a destination with suitable existing
access policy can be established; no implicit public creation or ACL changes.

PDF inputs use bounded Metro reads or local File bytes. Initial full-read
support can establish coherent representation identity with a digest before
introducing validated range access; any full-read limit is explicit to users.
Sources are immutable for an open reading session. Keep complete bytes only on
explicit offline selection. Paragraph anchors require PDF structural evidence;
page and selected-text anchors remain available on other documents.

Specification review: W3C Web Annotation Data Model, 23 February 2017,
sections 3.2.4 (HTML TextualBody), 4 (SpecificResource), 4.2.1 (FragmentSelector),
4.2.4 (TextQuoteSelector) and 4.2.5 (TextPositionSelector).
https://www.w3.org/TR/annotation-model/
Quote offsets are Unicode code points, not JavaScript UTF-16 indexes. Use
page-scoped selection only with an explicit page refinement and extraction
profile; do not label arbitrary PDF text-layer offsets as interoperable global
TextPositionSelectors. Digest/page geometry extensions are app conventions.
HTTP RFC9110 section 13.1.1: If-Match requires strong comparison. PATCH by itself
does not establish optimistic concurrency control.
https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match

Investigated reuse: StateGraph preserves unrelated native statements;
saveDocument handles conditional updates; existing Cobalt editor API edits and
renders fragments but supplies no general HTML-to-fragment import API. Any
HTML bridge must explicitly bound supported editing and retain unsupported HTML.
Margin-notes supplies an example, not stable PDF anchors or multi-group policy.

Verification will cover native graph preservation, stale-write refusal, local
recovery, HTML sanitization, provider replacement, source changes, scanned PDFs,
phone and keyboard interaction, full dependency cost and the complete suite.

## Integration details established during implementation

The current broker chooses one configured provider per capability, without MIME
negotiation. Files uses a narrow view-pdf capability and preference for .pdf
paths, keeping other resources with the existing view-resource provider.
Documents also advertises view-resource for explicitly configured callers. This
is a concrete departure from the earlier proposal's generic-only routing; it
avoids silently replacing the general viewer for non-PDF files. Opaque PDF URLs
can be opened directly in Documents; MIME-driven Files routing remains a limit.

Use published legacy PDF.js browser artifacts because the modern build requires
Uint8Array.toHex, absent in the suite's Chrome 131. Serve its published minified
worker in production, readable worker in readable mode. Include the required
worker in the advisory JS totals; fonts/cmaps/wasm are additional on-demand
assets. PDF.js raises the documented Node requirement to 22.13.

Native RDF, direct library integration, source inspection and narrow app
boundaries follow the adopted Muze engineering culture. The shared Cobalt
boundary also follows Muze library stewardship; no lower library publication
or external repository changes are made.

Uncached remote PDFs require browser-readable access (including CORS) and a
connection on reopen. Loaded bytes/engine permit same-session use. This cycle
does not introduce a proxy or an offline shell installation. Annotation data
and editor drafts survive reload locally. These limitations are stated in the
UI and evaluation instead of being hidden behind an offline claim.

Final PDF geometry review checked PDF.js 6.5.438's installed public
PDFPageProxy.getViewport API: rotation defaults to the page's intrinsic rotate
value, and PageViewport carries userUnit. Viewer rotation is an offset from that
intrinsic value; text-layer scaling includes the page unit. The synthetic PDF
regression includes a correctly indexed PDF with intrinsic rotation.

## Viewer review correction, 17 November 2026

The maintainer rejected the form-heavy PDF view: opening a PDF in Files must
show the PDF directly, with controls in a toolbar and no default form clutter.
They also reported failure to import assets/pdf/pdf.worker.mjs. The current
template exposes opening, search and group forms inline; the pre-cycle running
dev server does not recognize .mjs MIME. This is corrective work within the
authorized PDF viewer cycle, not human acceptance. Use shared icon toolbar
controls and native dialogs, with an optional annotations panel. Preserve
annotation storage, recovery and capability editor behavior. Publish the worker
as .js for existing dev-server MIME compatibility. Check the actual embedded
Files view, phone layout, keyboard dialogs and worker loading; prior rendering
tests alone did not establish acceptable viewer presentation. No additional
dependency or eager editor download is needed for this correction.

## Shared styling review correction

Maintainer requests that dropdowns, dialogs and other styling follow the other
apps. Inspection finds custom dialog containers and unstyled native inputs in
Documents. Reuse the solid-design dialog component, header/content/close
structure, control/select primitives and shared theme colors. Preserve the
document-first default and storage/editor contracts. This is a correction
within the active CYC260 branch; no acceptance is inferred. Phone dialogs use
the existing full-screen shared treatment; offline and download behavior are
unchanged, with no new dependency. Verify keyboard close/focus, phone and
desktop dialog layout, and the existing PDF workflows.

## Persistent outline review correction

The maintainer wants the outline left of the page, permitting repeated page
navigation without reopening a dialog. Replace the outline dialog with a
toolbar-toggleable persistent navigation panel. Keep it open when selecting
entries; independently scroll the outline and page. At phone width keep both
visible side by side with the outline limited to 40% of the view, and allow
hiding it from the toolbar. Use shared panel/control styling, native buttons
and accessible expanded state. No storage or network contract changes.

## Continuous scrolling preference

The maintainer prefers scrolling between PDF pages with lazy loading; paged
EPUB-style navigation and optional two-page presentation were suggested as
alternatives. Implement the preferred continuous reader first, retaining the
outline and previous/next controls as scroll shortcuts. Separate paged/facing
layouts remain later options, not silently included in this correction.

Keep page placeholders and page controls in SimplyFlow. Each nearby page gets
an independent PDF.js canvas/text subtree; distant canvases are released,
except a page containing keyboard focus or a live text selection. Render only
a viewport-sized buffer, estimate unvisited page dimensions from page one and
learn their own dimensions as they approach. Native scroller supports touch,
wheel and keyboard. Outline stays left and open across page jumps. Update
current-page markers and annotation targeting from the visible page, while
selected-text annotations retain the page their selection belongs to.

PDF bytes still use the existing bounded Metro read; lazy loading here is
page rendering, not incremental HTTP ranges. Loaded-document offline behavior
and local/conditional annotation persistence are unchanged. Download budget
remains advisory and the same PDF.js dependency is reused. Verify repeated
outline navigation, native scroll/End back-and-forth, canvas eviction and
re-render, mixed page geometry, selection identity and existing persistence.

Checked PDF.js 6.5.438 installed APIs and official PDFPageProxy render/getViewport
and examples (https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html,
https://mozilla.github.io/pdf.js/examples/). Each page owns its render task and
canvas; cancellation never shares a canvas between concurrent page tasks.

## Reading continuity and annotation editing refinement

Keep the existing Documents app boundary. Store account-scoped reader settings
and per-URI/revision page plus fractional offset in local native RDF. Merge
changed fields under Web Locks and reject older position writes. This is
device-local convenience, not synchronized Pod preferences. Flush on ordinary
document/account/managed-view transitions; pagehide is best effort. Base scale
on the whole reader layout so sidebars do not rezoom paper. Narrow screens can
scroll the unchanged paper horizontally. Remove inherited list indentation.

Annotations retain HTML for display and a linked native Cobalt fragment when
available. Prefer native content on edit; validate before atomic graph updates.
HTML-only replacement editors detach a stale native association without deleting
unknown native graph data. Local draft RDF retains both representations.
Cobalt owns HTML import through its published 0.2.0 API; unsupported HTML remains
available to another capability editor rather than silently losing content.

Use shared native modal dialog styling, Save and close marker only. Closing
retains the local draft. Formatting uses the shared floating toolbar placement;
Link keeps a snapshot of the selected range while its modal takes focus. Native
buttons/labels, keyboard selection and Escape remain core interactions; verify
phone sizing and focus alongside automated persistence contracts. Cobalt remains
lazy-loaded on editing; reader state adds no dependencies. Existing offline
loaded-document/edit recovery and conditional group save contracts remain.

## Inline anchors, visible notes, external sources and thumbnails

Maintainer review explicitly requests paragraph + controls at the paragraph,
visible-anchor-only annotation cards without page labels, explicit authors and
additional external files rendered distinctly, plus optional thumbnails if
performance is adequate. Current implementation exposes a paragraph dialog,
lists every note in the writing group, omits stored creator projection and
replaces the writing group when opening a remote file. These are the evidenced
gaps within the existing active reader cycle.

Keep Documents as the app boundary. SimplyFlow renders paragraph controls and
cards; native PDF geometry only supplies placement and visibility. Keyboard Tab
reaches each + button; hover/click reveals it and touch uses visible buttons.
Cards use the actually visible anchor bounds, not the renderer prefetch buffer.
External annotation files are cached alongside the writing group, labeled by
source/creator, and read-only in this presentation. Preserve unknown RDF and
existing creators, including multiple creator values; never assign legacy notes
to the current reader. New signed-in notes use the WebID; anonymous notes retain
a local pseudonymous author identifier. No permission management is introduced.

Optional thumbnails render only near the thumbnail pane viewport with one task
at a time, bounded canvas retention and page-number overlays. Native buttons
scroll the main reader, keeping sidebar scale independent. No extra dependency;
PDF engine remains the known advisory-size excess. Loaded/cached source data
works offline; fetching a new external file still needs access and connectivity.
Verify phone and keyboard paragraph insertion, visibility filtering, source and
author preservation/reload, and thumbnail canvas counts/navigation/performance.

Specification: W3C Web Annotation Data Model Recommendation 23 February 2017,
section 3.3.2 Agents (https://www.w3.org/TR/annotation-model/#agents): creator is
optional, may have multiple agents, and is recorded metadata, not authenticated
proof. Retain native Turtle and existing application PDF-anchor extensions.

## Destination and responsive-pane refinements

The maintainer confirms external annotation files are view-only by default,
with an explicit Enable writing action. New notes offer enabled writing groups
and resources in the note dialog. With a replacement editor, choose the
destination before handing control to that capability. Existing notes retain
their source; this is not a general annotation-move UI. A newly created empty
marker is retained locally for recovery and can change destination on Save:
preserve the completed destination first, then detach only the original empty
marker membership. Unknown RDF stays intact; failed persistence retains drafts
rather than publishing either resource. Pod saves remain explicit/conditional.

Small screens start with all sidebars hidden, even when desktop preferences
remember an open pane. Toolbar handles open one overlay at a time. Outline and
thumbnail navigation dismisses the overlay and returns keyboard focus to the
reader; paper scale is unchanged. Phone thumbnails fill the reader width and
wrap into rows. Desktop retains side-by-side panels. Saving a note does not
automatically reopen a phone sidebar. Thumbnail rendering is bounded to the
pane's viewport plus a short buffer, sequential and cancelled/released on close.

The maintainer also asks to discuss standalone Documents collections like
Notebook/Presenter. Proposed as a following cycle, referencing PDFs and separate
annotation resources without copying source bytes. It is not implemented or
accepted as part of this correction.

## Further review: responsive continuity and compact annotation cards

The maintainer requests desktop panes to return after a narrow-window interval,
and paper to retain its reference fit width: shrink when needed and restore up
to that width without further enlargement. Explicit zoom remains unchanged.
Each resource receives a persisted local hue, reused for dark card backgrounds
and lighter PDF highlights; source/author metadata remains available as well.

New-note close must not leave an empty annotation. Closing a new draft now
removes its provisional marker and draft; saving empty text removes an existing
annotation. Existing-note close still preserves its unsaved draft. This supersedes
the earlier close-keeps-new-marker behavior. Removal drops the annotation and its
owned body/target/native-fragment statements, preserving shared subgraphs and
unrelated RDF. Group resource publication still requires its conditional save.

Hover/touch on a highlight emphasizes the matching visible card(s), scrolling
the open sidebar without moving the PDF. Closed phone panes stay closed until
their handle is used. Keyboard text selection supplies an equivalent activation
path; keyboard note editing remains available through native controls.

The maintainer requests nicknames/first names, never visibly printed WebIDs.
Use embedded names or the existing Solid profile reader through Metro, caching
native profile RDF per account. Unavailable profiles do not block notes: a stable
generated symbol pair identifies the author, with WebIDs in hover titles only.
Compact cards replace the text edit button with a pencil visible on hover/focus
and touch. Source names remain compact with resource addresses in titles.

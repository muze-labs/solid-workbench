# Static optional authoring assets

Keep installed SimplyFlow's app/component datasets and normal imports intact.
The existing Rollup source-extraction plugin emits authored entry metadata as
separate hashed assets. Runtime ?entries imports retain component-keyed URL
slots, allowing existing re-export and component composition to remain direct.
Each optional module exports inert source metadata as data, not executable app
behavior. Rollup emits and resolves the same-build asset URLs; no runtime
manifest fetch or authoring request is part of startup.

Explicit ?source imports identify full API-module source used only for
inspection. Their optional hashed modules export the original source string;
runtime definition.modules retains sourceUrl, origin and dependencies. Ordinary
UTF-8 text imports keep their existing bytes/HTML/CSS behavior. This avoids
silently changing text-import semantics to strip arbitrary executable content.

There is no IDE or production source loader in this cycle. A test tool may
explicitly import authoring modules to verify retained source reconstruction,
file origins and separate-host feature reuse. Normal feature checks use the
actual runtime datasets without loading authoring assets. Network regressions
must prove normal tasks remain usable when optional source routes are absent.

Keep both executable variants lean, and keep source maps separate. Report
optional artifact costs independently of the complete normal graphs, without
hiding required runtime imports or callbacks. An old open app may find its
hashed source asset missing after deployment cleanup; that affects future
inspection only, not normal behavior. Atomic deployment remains hosting policy.

Muze engineering and library stewardship shape thin build-time reuse of Rollup,
readable code and clear distribution boundaries. No runtime evaluation,
parallel renderer, library publication or new transport is introduced.

Build API verification: installed Rollup 4.67.5; official plugin-development
sections this.emitFile and File URLs, and output.assetFileNames configuration
were checked. Asset emission in load and import.meta.ROLLUP_FILE_URL references
are the supported API; local tests verify both executable output variants.
References: https://rollupjs.org/plugin-development/#this-emitfile,
https://rollupjs.org/plugin-development/#file-urls,
https://rollupjs.org/configuration-options/#output-assetfilenames.

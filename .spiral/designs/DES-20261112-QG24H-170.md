# Finite opening and persistent scoped views

Extend existing embedded tickets with presentation kind view. Keep modal tasks
unchanged and independent. Initial view-resource request returns only when actual
content is usable; the port then carries finite view update, refresh and prepare
operations. Host validates ready/version and scoped lifecycle replies. No pending
request represents the lifetime. Provider data reads use its own Metro session;
no credentials or unrelated folder data cross the boundary.

Shared host retains old frame until prepare explicitly permits teardown and
freezes provider edits. Timeout/disconnection is not permission. Replacement
serializes teardown and rejects stale responses; repeated selections coalesce
through a generation. Explicit discard is a distinct user command. Scoped
source/origin/port validation and existing ticket owner checks remain governing.
Embedded providers may host using their own local broker and explicitly selected
children; upstream child delegation remains refused, not root discovery bypass.

Read-only viewer accepts direct HTTP(S) resource references and interactive,
scrolling text/plain or decoded raster image content. No arbitrary HTML/SVG
execution. Standalone URL/form works without Launcher. Initial and later complete
appearance sets have generation-local revisions, typed colours/font/size defaults,
and reported limitations. Resize/visibility update allocation without remount.
Full Weblets/recursive interoperability, editors, Presenter, widgets and semantic
provider discovery remain later gates. Provider choice uses existing preference
bindings and offers explicit local/default selection; failures do not switch apps.

Files retains download and standalone opening, focused picker behavior and native
RDF state. It does not parse viewer content. Editing infrastructure/lifecycle is
verified with an independent guarded fixture rather than claimed as an editor.


Implemented experimental contract, version 1:

- Capability URI: `https://vocab.muze.nl/capabilities/view-resource`.
  Initial input carries version, generation, resource URL, `access: direct`,
  complete appearance hints, and interactive/scroll presentation allocation.
- Initial result confirms version/generation, ready content and
  `presentation: interactive-scroll`, plus appearance support, limitations and
  optional minWidth/minHeight/overflow constraints. It finishes the open call.
- Existing private port handles `view` operations: update (complete appearance
  and presentation plus monotonically increasing revision), refresh, and prepare.
  Prepare must return both allowed and frozen before ordinary teardown.
  A refused/failed close leaves the frame, content, label and selection intact.
- Readiness observes SimplyFlow output and decoded images. A loading shell is
  insufficient. Startup has the existing bounded connection style (20 seconds);
  no inactivity timeout expires a ready view. Failed opens retain their frame
  for explicit retry/guarded close/discard. Native process crashes are outside
  this graceful closure guarantee.
- Appearance values allow fixed generic font families, hex RGB colours, font
  size 12–40 CSS pixels and line-height 1–2.5. Values are hints, never arbitrary
  CSS. The initial provider applies typography with accessible minimums and
  reports that colours follow its own accessibility preferences; images retain
  their pixels. Omitted values restore defaults without remounting.
- The initial interaction profile is scrolling/interactive, not bounded/passive.
  No custom font fetching, rich content editor, live subscription or universal
  selection/query descriptor is introduced.

Files offers an explicit View action showing the chosen provider before loading.
Default apps gains Resource views using the existing native preference binding,
manifest declaration lookup and custom URL entry. Failed choices never silently
fall back to a different app. Provider data access is its own Metro client;
read-only presentation does not revoke the user's Pod permissions.

Parent removal, workspace switch/conflict replacement and account transitions
coordinate current views before changing their context. Ordinary app checkpoint
semantics remain intact. A native tab close/crash bypasses graceful coordination;
the built-in provider has no edits, and general editor crash recovery remains
future work. The independent editable test peer demonstrates refusal, freezing
and preserved draft data but is not a delivered editor.

This is project-owned experimental protocol, not implementation of a published
Weblets standard. Existing MessagePort and window/origin checks are reused.
No new HTTP/authentication/RDF transport or externally standardized wire format
is claimed. Recursive third-level interoperability remains a later proof;
embedded peers cannot bypass their immediate host to discover root siblings.


Maintainer review correction, 2026-11-12: plain text works, but the embedded
viewer repeats the host's “WebID / connection” control. The maintainer requires
embedded viewers to expose only view-specific UI. Inspection confirms the shared
shell enables that task control for every task, including persistent views.
Continue Active CYC168 on its verified branch: opt the viewer into content-only
embedded presentation using SimplyFlow bindings and the existing header component.
Standalone account controls remain useful; resource errors and request-specific
recovery must stay visible. No broker/authentication protocol change or new
cycle approval is needed for this correction within the authorized Files proof.


Further maintainer review: open views on file selection; retain the filename as
an ordinary link to the standalone view; remove View/refresh/close/About/Ready
chrome and the default frame border. Reuse the Preferences loading presentation.
Show recovery only for errors. Limit list filenames with an ellipsis and full-name
title tooltip; the details heading may use all available width, bounded by its
pane/viewport rather than a short fixed cap. Keep full accessible names and
native modified-click/context-menu navigation. These requests supersede this
cycle's earlier explicit View button and always-visible metadata controls.


Maintainer MIME review, 2026-11-12: all `text/*` resources must be viewable as
text, including HTML source. The current exact `text/plain` check leaves this
gap; extend it to the text media family with case-insensitive type matching and
parameter handling. Keep escaped SimplyFlow text rendering, the existing Metro
read path, loaded-content preservation and the same phone/keyboard interaction.
No new app, dependency, network request or offline cache is introduced.

When additional viewers arrive, prefer a matching specific MIME viewer (for
example `text/html`) over the generic `text/*` fallback during default selection.
Preserve deliberate user selection. View-selection tabs are a possible future
UI, not part of this correction; multi-provider discovery/ranking still needs
its own implementation. RFC 9110 sections 8.3.1 and 12.5.1 were checked for
case-insensitive media types, parameters and Accept media ranges:
https://www.rfc-editor.org/rfc/rfc9110.html#section-8.3.1
https://www.rfc-editor.org/rfc/rfc9110.html#section-12.5.1
The future app preference is product policy, not a claim that HTTP specifies
capability-provider ranking. UTF-8 decoding remains the existing response.text
behavior; this correction does not introduce charset negotiation.

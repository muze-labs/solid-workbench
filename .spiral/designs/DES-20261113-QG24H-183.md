# Demo experience design

Apply shared muzeSolidDesignToolbar controls and Feather icons to existing
app workflows, keeping native forms, SimplyFlow commands and current data APIs.
Files receives compact folder navigation/create/upload and resource actions;
Contacts receives a discoverable search/add/sync toolbar and contextual actions.
Review Preferences action hierarchy and spacing without changing setting policy.

Catalog is an editable Workbench component, using a static folder: index.ttl
links schema:hasPart entries, each with schema:name, schema:image and
schema:subjectOf manifest URI. Existing schema:SoftwareApplication manifests
remain authoritative for launch URL. Names/images are presentation, no authority.
Use oldm-turtle/document helpers through configured Metro clients. Resolve
relative IRIs against document URL through existing loader.
Multiple source URLs and last successful native index graphs persist locally
in an app-owned Solid Workspace Turtle source. Never serialize JSON-in-Turtle.
Read on explicit opening/refresh; source failures retain cached entries and
other sources. Added shortcuts use the existing collection and user action.
External entries use ordinary anonymous links, without fabricated capabilities.
Use SimplyFlow model effects for catalog search/sorting; preserve source RDF.
Duplicate listings may coexist by source, while adding an existing launch URL
is idempotent. Source removal never removes added shortcuts.

Muze engineering shapes readable app-owned slices and library reuse; library
stewardship applies only to shared toolbar changes. Adopted warning profiles and
native RDF/storage contracts remain active. No new auth/rendering stack.

## Evaluation-driven corrections within scope

The shared control's display default uses `:where()` so structural components
retain display ownership. Otherwise its later-loaded `display: inline-flex`
made Preferences' phone-only Back control visible and tabbable on desktop.
The adapter also applies to standalone tool controls, so they retain hover
feedback outside a toolbar group. Existing profile action-footer structure stays
intact; its controls receive the new style.

A native keyboard folder-create probe exposed an installed Metro composition
gap: the default empty-string request body loses its replayable data, causing a
locked ReadableStream before PUT. The same public `createContainer` call with a
Turtle comment body succeeds. Files supplies that empty native graph and
`Content-Type: text/turtle`; Metro still owns HTTP, auth, conditional headers,
container typing and discovery. No library patch or replacement transport.

Specification check before changing this path: Solid Protocol 0.11.0,
2024-05-12, sections 5.1/5.3/5.5 (URI allocation, writes, representations),
https://solidproject.org/TR/2024/protocol-20240512 . PUT assigns the client-chosen
URI; slash semantics identify a container. `If-None-Match: *` is encouraged for
creation; the installed API already supplies it, along with the BasicContainer
Link type. LDP 1.0 section 5.2.4 makes PUT support optional at the LDP level;
Solid's required write support is not generalized to every LDP deployment.
No containment/resource-metadata triples are supplied by this empty graph.
The fixture checks the actual request headers and native create result.

Catalog vocabulary checked against Schema.org v30.1 (2026-09-16),
https://schema.org/hasPart and https://schema.org/subjectOf. This is an app-owned
index shape, not a newly claimed Solid or broker protocol requirement.

## Root, hierarchy and Turtle negotiation correction

Root location has no ancestors; only nested locations prepend the root. The
location menu exposes each ancestor/current folder once, with depth-derived
logical padding capped at 96px to preserve room on narrow screens. Existing
native buttons, URL controls and disclosure behavior remain. Labels retain the
root folder name consistently. No additional renderer or persisted data.

Viewer requests text/turtle explicitly for .ttl URL paths (case insensitive;
query/fragment do not affect the suffix); other resources retain existing text/
raster-image negotiation. The returned Content-Type continues to select the
actual supported rendering. Existing Metro session/anonymous clients are reused;
no HTML sniffing, replacement transport or data writes. RFC 9110 (June 2022)
sections 12.5.1 (Accept media ranges) and 8.3 (Content-Type) were checked at
https://www.rfc-editor.org/rfc/rfc9110.html. Accept is a client preference; this
does not claim every server must honor it.

## Catalog categories and Contacts reach refinement

Use the shared native-dialog header/close class; omit Done/footer. Workbench's
existing shared list/details component owns category navigation (All apps,
native catalog categories, inline manual-link form, catalog sources) and phone
Back. Categories filter through the existing SimplyFlow model and jaqt query;
manual entry reuses existing shortcut-add action and controls. A successful app
selection/add closes and returns to Workbench; errors keep the form and dialog.
More info is a real link selecting an inline app detail view, with Back, safe
plain text, optional image and Add. Catalog browsing grants no new capabilities.

The static app-owned profile reads optional schema:applicationCategory as a
plain string (fallback Other apps), schema:text as a plain string (fallback
description) and schema:screenshot as an HTTP(S) image URL. There is no runtime
catalog authoring service. Existing RDF cache preserves all terms; missing and
unsupported structured options do not get flattened or rewritten. Schema.org
v30.1 property definitions were inspected during implementation: Text/URL
category, ImageObject/URL screenshot, CreativeWork text. This limited profile
chooses Text and URL forms; no global RDF/protocol requirement is inferred.
See https://schema.org/applicationCategory, https://schema.org/screenshot and
https://schema.org/text. Presenter includes one 29 KB screenshot with example
slide data, loaded only when its More info is requested.

Contacts' list/recovery content scrolls above a fixed bottom flex item containing
search, New and Sync. Search uses the same toolbar field/input primitives rather
than an overlaid-icon input. DOM order follows visual order and native focus
continues to use the existing list model, commands and dialogs. No data/storage
or provider changes. Guardrails and review limitations remain as recorded.

# Presenter input readiness and editor recovery

Diagnosis: the provider exposes cobaltEditor/support before its contenteditable
has completed first layout. A fast native phone probe measured the target center
as (8, 233.390625), exactly the iframe origin; after failure the inner field was
(29.90625, 90.984375, 314.1875, 28.03125). The native tap missed the field because
its earlier bounds were zero. A cold unmodified scenario passed, consistent with
a readiness race, not evidence of a product pointer-events defect.

Wait for a visible field with positive width and height before computing native
input coordinates. Preserve native touch/mouse dispatch and the explicit click
receipt and focus assertions. Do not add retry-click loops, arbitrary sleeps,
programmatic focus or synthetic content editing to bypass regressions.

The initial correction belongs in the test harness. At that checkpoint no
product gap had been demonstrated. Subsequent editor-restart probes established
the separately confirmed correction below. Existing tests also cover persistence
failure, guarded closure, offline edits and conflicts.

## Confirmed editor-restart correction

The separately evidenced product gap is now confirmed by the maintainer. A failed
view update retains geometry with visibility:hidden. On Retry the new provider
confirms usable content, but the ready projection inherits that old failure style.
Clear the failure style when the new provider confirms readiness, through the
existing SimplyFlow frame attributes. Do not clear it globally on every status
change: failed bounded/overflow presentations must remain hidden. No new renderer,
transport, retry stack or dependency is needed.

Regression: reload only the text provider, trigger a real viewport size change
while disconnected, use the existing Discard/Retry controls, verify restored saved
text, then click/tap and type through native browser input. Cover both phone and
desktop. Existing overflow refusal, offline preservation, storage failure,
conditional conflict, IME guards and keyboard focus assertions must still pass.


## Confirmed failed-startup/clone correction

ManagedApp.requestEmbedded currently sends raw nested reactive input over a
MessagePort. Standalone WorkspaceBroker serializes the same wire values first.
Use the existing serializable helper at the managed call boundary as well;
do not invent a renderer/proxy walker or change native RDF persistence.

Track the broker's actual content-delivery boundary separately from its pending
request flag. Preparing a view that has not received content must freeze future
delivery and return a safe frozen acknowledgement, including when startup failed
before readiness. A pending readiness wait must check this freeze before it can
send content. Once delivery starts, preserve normal provider prepare/refusal;
missing readiness/support alone is never evidence that edits may be discarded.
Use the existing prepare wire operation; no new protocol or discard default.

Verify real MessageChannel transport of nested reactive inputs and the race
where readiness completes after safe unstarted preparation. Retain existing
post-invocation unsaved-work veto checks. Browser checks must include managed
Disconnect -> slide switch and failed-startup leave/retry after restored access.

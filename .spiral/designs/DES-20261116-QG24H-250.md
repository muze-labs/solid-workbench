# Shared theme ownership and Launcher interactions

Current evidence: shared shell foundation owns basic swb-control rules;
solid-design owns dialogs/list-details/toolbar. Contacts and Files override row
appearance independently; section choices inherit button presentation. Launcher
shortcuts use padded image backgrounds and a persistent settings button; no
ordering interaction exists. Floating toolbar has a fixed dark drop shadow.
The theme explicitly defines separate main bar, contextual toolbar and panel
patterns, and uses a host-token adapter. Integrate into existing editable style
components, retaining SimplyFlow rendering and native lifecycle/focus actions.

Use one shared list-row visual contract with app-owned content and selection.
Presenter retains thumbnail content and geometry. Existing public libraries own
interaction bindings and RDF storage. Menu gestures must not prevent scrolling
or accidentally launch after long press. Reordering retains resource identity;
keyboard movement and pointer movement share one persistence action.
Muze engineering/library stewardship support readable shared ownership without
a new renderer. WPF-HUMAN-001 meaningful exclusion informs keyboard/non-drag
paths; composition risk informs integrated theme and recovery checks.

Installed library inspection: SimplyFlow 0.10.4 model/effects and the existing
simplyflow-events extension provide list projection and native event lifecycles.
No additional event framework is needed. Solid Workspace's WorkspaceWrites.save
snapshots the whole resource graph before queuing its existing local write; thus
setting validated integer ranks in the shared collection graph and saving one
subject persists the order in one local resource write. Register shortcutOrder
as a scalar predicate for existing synchronization/conflict policy. Unsupported
ranks remain visible with feedback and block structured reordering rather than
being flattened. Native pointer drag is supplemented with menu-based movement
for touch/keyboard; long press never disables ordinary vertical scrolling.

The supplied theme's mainbar/contextual-toolbar/panel distinction is retained.
The existing shared dialog owns scrolling and lifecycle rather than adopting the
prototype's JavaScript. Its decorative angled background becomes a pseudo-element
so the focus outline remains rectangular. Shared list panes own their divider;
app-specific category/detail/thumbnail content remains outside that rule.

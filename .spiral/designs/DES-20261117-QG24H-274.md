# Reading mode design

CYC272 Active on verified spiral/CYC-20261117-QG24H-272-paged-reading,
from accepted main 6e61f15. The maintainer confirms “lets do that” to continuous,
single-page and two-page reading, position preservation, remembered preference,
keyboard navigation and lazy rendering with all existing navigation/annotations.
Current implementation offers only continuous vertical flow. Single/spread
layouts will hide unrelated page rows through SimplyFlow, preserving page identity.
Spreads pair 1–2, 3–4, etc.; narrow screens display a single page while retaining
the spread preference. Next/previous advance a spread when two pages fit.

Documents remains the reading app; native PDF.js surfaces retain their existing
approved exception, SimplyFlow renders controls and page visibility. Reuse local
locked ReaderState native RDF for mode, with backward-compatible continuous default.
Mode changes preserve page/fraction. Already loaded bytes work offline subject
to existing engine/assets availability; uncached documents require network.
No new dependency or startup request. Compact native toolbar select and buttons,
keyboard PageUp/PageDown and Home/End, accessible labels, and phone-first layout
are required. Verify search/bookmarks/outline/thumbnails and annotations in each
mode, odd final spreads, mixed page sizes, resize and reload. Retain advisory
budget measurements and distinguish automated from manual AT/device evidence.

No commit, acceptance, merge or publication requested. Preserve unrelated vision
Markdown. Pod bookmark sync, collections and EPUB format support are later work.


Reader review correction: spreads now fit the current paper area rather than
cache their first width; compensate for per-page padding so the pair occupies
the same default reading width. A paper ResizeObserver recomputes spread fit
when sidebars change, preserving zoom/page/fraction; single/scrolling fit is
unchanged. Deferred resizes settle after ongoing navigation rather than racing it.

The reading-mode text select becomes an icon-only native popover trigger with
a 12px down-chevron below the icon within the existing 44px button height.
Reuse shared dropdown rows, current-choice styling and required shortcut scope;
Arrow Up/Down, Enter, Escape and native focus return remain available. No added
npm dependency or mandatory request; SimplyFlow renders choices and current state.

Size spread canvases and slots from the same fit calculation. The previous PDF
scale ceiling of 2 leaves unused width when the available page width exceeds
twice its natural width. Preserve explicit zoom. Keep the edge controls in a
stationary frame around the paper scroller so sidebars and scrolling move
neither control away from its reading edge.

Use the first wide layout as the spread reference box, independent of open
sidebars. For a page or pair, fit the width and tallest aspect ratio into that
reference. Below 100% shrink only if the chosen target no longer fits the
actual paper area. At 100% fit both axes. Above 100% magnify the default fit
and allow scrolling. The phone fallback must not initialize the wide reference.

Only reference width persists. The current available height is always a fitting
constraint, so opening initially in a short window cannot permanently limit
page height after the reader grows taller.

Use the actual paper frame for single-page fallback, so open sidebars count
against the available width. Above 100%, compare the zoomed spread to that
frame and switch to one page if necessary. Use the inner scroller width to
account for the vertical scrollbar without making mode selection depend on
whether the previous render had a scrollbar.

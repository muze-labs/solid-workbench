# Shared invocation recovery and obsolete route removal

The accepted assessment reproduces Contacts reload leaving the old invocation
pending while the new page has no request; Close -> Discard currently recovers.
Use that shared presenter gap as the implementation boundary. Explicit port
closure should signal peers before local shutdown; iframe navigation and renewed
provider readiness provide host-observable recovery without a heartbeat or user
inactivity deadline. No invocation replay. Keep ordinary dirty/save close guards
for still-connected providers and reject stale replies after settlement.

Remove chooseFiles, broker live routing/allow APIs, ManagedApp.request and the
instance grant UI. Keep managed-app state/checkpoint/reconnect behavior and
owner-scoped transient capabilities. Stop interpreting/writing allowBrowse;
existing RDF statements become unowned and must survive ordinary writes.

Review inherited 65536-byte serializable/app-state and 60000-byte recipient
limits together. Separate JSON value shape/depth and native RDF/domain validation
from byte policy. No universal transport cap is justified solely by old code.
Record measurements and the resulting choice in EVD155 before completion.

Specification review: WHATWG HTML Living Standard, 12 November 2026,
https://html.spec.whatwg.org/multipage/web-messaging.html#message-ports
and https://html.spec.whatwg.org/multipage/nav-history-apis.html#event-pagehide.
Check exact origins/sources and private-port authority; structured-clone support
is not a JSON-only or 64 KiB platform restriction. Lifecycle event coverage is
bounded; no claim of arbitrary crashed-process detection is made.


## Size policy and lifecycle refinement

Remove the serializable/app-state 65536-byte checks and recipient 60000-byte
cutoff. These duplicate arbitrary application restrictions, not a browser port
budget. Preserve JSON value/depth, native RDF and selected-subject validation.
Node probes round-trip 1011, 80011 and 1000011 UTF-8 byte values and descriptions
with 1164, 80164 and 1000164 bytes. This demonstrates crossing the old cutoff,
not an unlimited-memory guarantee or a measured mobile maximum. No new cap is
justified by available evidence. Count/depth guards remain unchanged.

The independent 60000-byte attemptExit safeguard remains: Fetch §4.6,
HTTP-network-or-cache fetch step 8.10 rejects keepalive request bodies when their
sum with in-flight keepalive bodies exceeds 64 KiB. This is a specific HTTP
background-delivery constraint, not a state/message constraint. The existing
headroom is heuristic and does not guarantee availability of the shared quota.
Explicit foreground saves and local recovery remain available.
Reference: https://fetch.spec.whatwg.org/#http-network-or-cache-fetch (reviewed
2026-11-12, Living Standard updated 2026-10-19).

The existing browser regression exposes a necessary distinction: a private-port
disconnect can leave an editor and its unsaved draft alive. Keep that view and
its discard guard. Only observed navigation/reload permits the straightforward
interruption close path. Ending a ticket does not prove a page has navigated.

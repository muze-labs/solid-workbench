# Separate resource execution from collection reconciliation

Keep ResourceLifecycle as the physical conditional operation engine. Retain its
existing known operation fields and native .graph across records. Additional
context is a native StateGraph merged into the prepared journal atomically;
unknown context survives stage writes. Remove interpretation of collection/entry
from this engine, retaining the existing vocabulary and journal shape. Clear the
journal only after acknowledged completion or supported cancellation. No HTTP,
retry or authorization mechanism changes; use existing Metro/session clients.

Add CollectionFileOperation in existing private solid-app-data, combining native
collection association (the same root/predicates, so old journals still open)
and shared finish ordering: require complete, obtain correct collection when
associated, repair/remove membership, sync, invoke app-local reconciliation,
then acknowledge. Failures retain complete intent and retry that reconciliation
without replaying acknowledged remote effects. Standalone operations skip only
the membership step. App callbacks remain editable dataset actions and own
collection activation, dirty guards, draft retention/purge, dialogs and focus.

This is a meaningful bridge because it owns native association and acknowledgement
ordering, not a renamed call. Use one source for physical state and context;
a separate association journal would add a two-write ambiguity. No new package
or dependency. Preserve raw engine API exposure and add explicit bridge API and
optional version-matched source metadata in each real consumer. Keep the new
module in the existing document-only chunk and preserve all unrelated graphs.

Specifications rechecked: Solid Protocol 0.11.0 (12 May 2024), sections 4.3 and
5.4, https://solidproject.org/TR/2024/protocol-20240512 . Auxiliary links use
advertised describedby; server containment/auxiliary cleanup is a server duty,
not an app graph rewrite. PDS Interop Living Document (24 January 2022), sections
3, 4.1, 4.3, https://pdsinterop.org/solid-link-metadata/solid-storage-specification/ .
Use advertised parent description for forwarding/deletion metadata. This remains
an extension-specific workflow, not a universal server capability. Physical
conditional removal in document apps and Files' retained-byte tombstones remain
distinct. Source/validator/digest preconditions, lost replies, metadata conflict
and native relative IRI meaning retain existing tests and are extended for
context and finalization/reload boundaries. No specification behavior is relaxed.

Muze engineering and library stewardship shape the thin explicit boundary with
two consumers, readable inputs/effects and native data ownership. Main's pinned
culture versions apply; existing maturity policy keeps this private/experimental.

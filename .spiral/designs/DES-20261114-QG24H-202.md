# Notebook document and editor integration

Use published NotebookController 0.1.0 directly with Cobalt rich-text editor
adapters. The app owns document/block membership, title, selected editor and
structural commands; Cobalt owns local text/formatting and the controller joins
and navigates between adapters. SimplyFlow owns HTML lists, attributes, status,
controls and editable feature datasets; its model owns block ordering and the
local-document list projection. Native focus and editor lifecycle stay direct.

One open document has native RDF Notebook and named block subjects. Owned
membership/position/kind terms link existing native Cobalt fragments and typed
annotation lists. Preserve unknown triples and detached content; validate only
interpreted fields and refuse unsupported block types. No serialized main state
or persistence baseline is stored as JSON in Turtle.

Use Solid Workspace local sources: separate account-scoped Turtle document
copies, a native registry/selection index, and native per-URL comparison baselines.
Preserve the old local copy before New/Open/select. Roll back the active in-memory
document if saving the newly activated cache fails. New remote reads validate
before replacement and detect concurrent local revisions. Save uses existing
loadDocument/saveDocument and Metro session.perform. Save As requires a missing
destination; it never overwrites an unrelated document. A failed/conditional
write retains local edits. Local drafts are also available through a native
Document disclosure and ordered list; no folders or multi-tab coordination.

Phone-first layout shows editing controls and blocks; Document and Link native
disclosures contain occasional controls. Visible Add/Split/Join controls accompany
keyboard operations. Native composition prevents destructive switches. Structural
operations retain the active block/caret and restore focus only after the bound
inert state is removed. Busy operations protect document/account transitions.

No new renderer or HTTP/auth mechanism. Controller-only dependency is isolated
from shared app chunks. Reuse the supplied Notebook icon. Workbench navigation
and the existing static catalog expose the app. The published editor 0.1.1 dist
is byte-identical to the accepted temporary build, so all consuming apps use
that npm version; the unused archive remains provenance, not a new exception.

The confirmed outcome supersedes a single-persistent-document interpretation.
No arbitrary multi-notebook feature library, code/image blocks, collaboration,
new editor framework or automatic sync is implied. Check native phone/keyboard,
IME/reload/local failures/conditional conflicts and full app download cost before
human review. Manual AT and physical devices remain separate evidence.

## Firefox visual Bold correction

faces use font matching. This is an application presentation choice, not a claim
that HTML mandates a particular visual weight. The existing Chrome fixture now
supplies a lower reset-layer relative strong weight to expose the Firefox
baseline; the app's component layer owns the explicit emphasis. Native Firefox
button/Ctrl+B and reload probes provide actual engine evidence.

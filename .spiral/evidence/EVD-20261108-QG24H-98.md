## Guardrails and limits

The app/task boundaries, native RDF authority, storage and authentication policy
remain unchanged. Existing available local content, in-memory drafts, conditional
saves and recovery checks pass. Full offline startup and reload-persistent draft
support are not added or implied. The Preferences fixture covers phone layout,
keyboard/focus and accessibility-tree expectations; existing menu/dialog/task
flows pass. There is no new UI to manually review, and no claim of a screen-reader
user study, new non-professional-author usability study or broad provider coverage.

Declarations/conditions are snapshots at activation. Live action replacement is
supported; live descriptor rebinding requires explicit stop/start. Subscription
setup and cleanup are synchronous contracts. An adapter that throws before it
returns an unsubscribe must undo its own partial setup. If unsubscribe itself
throws, the package attempts remaining cleanups and makes retained callbacks inert;
it cannot force an external library to release a failed subscription.

Existing SimplyFlow recursive composition is reused, including nested descriptor
merges; the extension does not install a personal-layer manager or change that
composition's aliasing rules. Authored event source remains retained independently.
Element behaviors and transport/message listeners keep their own lifecycle owners.
Promotion into SimplyFlow is a future decision after real-use/API evaluation.

# Design extension verification

The focused Chrome example test passed with two native popovers, placement near
their own triggers, Escape dismissal and focus restoration, dark mode and
enlarged text at 390px. The SimplyFlow example filtered local records and used
the shared arrow-key behavior. The plain example loaded no JavaScript. Chrome
confirmed normal Contacts startup did not fetch the example or the compiled
extension stylesheet. Each shared sheet appeared once in Contacts. The
workspace package resolver resolves styles.css.

Chrome initially accepted the implicit CSS anchor syntax but positioned the
example popover at the viewport corner. Named anchors resolved the geometry
on the tested browser. The app search fields retain their names through
native labels. The initial full suite caught an authoring assertion that
looked for the old redundant aria-label. Its replacement still verifies the
accessible name after swapping the template in a separate Contacts host.

A cold Chrome probe used a 390px viewport, 200000 bytes/s download, 150ms
latency and an empty cache. Plain HTML was available in about 1.0 s, with
3.2 KB HTML, 77.1 KB CSS and a 52.7 KB SVG sprite, no JS and no fonts. The
minified SimplyFlow example showed filterable results in 2.8 s, with 2.7 KB
HTML, 45.9 KB CSS and 438.6 KB JavaScript in three requests before the icon
request completed. Contacts reached its search field in 3.2 s, with 29.1 KB
HTML, 45.9 KB CSS and 483.9 KB JavaScript in four requests. Sizes are
uncompressed transfer bodies from the local server and exclude headers.

The build reports 129872 minified gzipped JS bytes for the complete Contacts
graph including auth, 155539 for Launcher, 163131 for Presenter and 726874 for
Documents. The existing readable and Documents advisory budget warnings
remain. All app graphs are isolated from the optional example entry.


The restarted full browser command passed the Contacts authoring probe and
stopped in the provider suite at line 417 waiting for preference synchronization
after a fixture fetch failure. The provider suite then passed independently.
The catalog, Contacts styling, shared ten-app layout and Presenter suites
also passed independently. Documents initially reported a 788px scroll height
in a 748px page-fit viewport. An isolated build of main reproduced the same
assertion and dimensions. The unmodified Documents suite later passed on this
cycle, and its cold PDF profile passed as well. The passing run exercises the
migrated reading-mode menu with keyboard selection and focus return.

The 390px previews were visually checked. These runs use headless Chrome and
do not constitute physical-device or manual screen-reader verification.

## Prefix and semantic examples

The prefix migration updates all Workbench consumers and leaves the package
specifier in place. No renamed JavaScript identifier or CSS token collided
with an existing name in the baseline scan. The compiled app and example
assets contained none of the former prefix. The renamed build reports
129596 minified gzipped JavaScript bytes for Contacts, 155067 for Launcher,
162820 for Presenter and 726550 for Documents.

The example markup now uses native search regions, one GET search form,
labeled search inputs, link-list popovers and an output element for filter
feedback. The shared decorative SVG retains aria-hidden. Chrome's
accessibility tree reported a search landmark, named searchboxes and an
implicit status. Filtering to no results updates the native output.
The coverage includes the existing menu keyboard and dismissal checks.

The post-rename full browser run passed through Notebook. It stopped at a
Presenter collection test that still required the old shared anchor name.
The revised assertion retains the viewport and styling checks and verifies
that each popover uses its own trigger's anchor. Presenter Collections,
Preference sections, shared UI layout, Launcher groups and shortcut metadata
then passed independently. The Documents normal-profile page-fit assertion
recurred with the same baseline dimensions. The cold PDF profile passed.

The acceptance rerun passed `npm run check` and the focused Chrome design
extension test on the committed implementation.

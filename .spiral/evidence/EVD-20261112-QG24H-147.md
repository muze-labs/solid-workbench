- Preferred picker tasks: per-operation private preference -> exact provider URL

## Setup and user decisions

Developer baseline: installed npm dependencies, npm run dev, Chrome for fixture
checks. No relay/server registration or central service is required. A separately
implemented provider needs the existing private-port handshake and runtime
capability declaration, exact task URL/context handling and its own Solid access.
An explicit manifest is useful for the saved-app chooser, not required for a
manually entered compatible URL. An application URI is not an executable URL.

Normal recipient task: open Files through Workbench with a usable folder, choose
Share beside a listed resource, choose a person in the current cached Contacts
book, review/confirm Use, then see the summary. This is recipient selection;
permissions are unchanged. Provider choice is a separate configuration task:
Preferences -> Default apps -> selection task -> saved compatible app/custom URL
or built-in reset. Changes persist locally and sync conditionally; an unavailable
manifest does not delete the choice. Account sign-in and data availability remain
owned by each app/session, not supplied by the broker.

User-facing decisions include the configured selection task/provider; a custom
URL where metadata is absent; which resource/person to choose and confirm;
cancel; tab fallback if embedding fails; and keep/discard if a provider has edits.
The retained chooseFiles API uses the instance Allow resource selection grant
and rejects multiple eligible live instances. The current Choose in Files button
calls resourceSelection.handlePickResource -> muzeSolidUiInvoke, not chooseFiles. Keep this
compatibility path distinct from preferred transient picker configuration.

## Reproduced raw transport gaps

Disposable /tmp/cyc145-probes.mjs exercises the unchanged PortConnection and
WorkspaceBroker. /tmp/cyc145-port-browser.mjs serves the unchanged transport module
and repeats the boundary in HeadlessChrome 131. Both observe:

1. serializable rejects a 70000-character object, but PortConnection.call sends
   it and the echo peer returns it successfully. The Node probe also round-trips
   a Map, outside the documented JSON-value profile. PortConnection neither
   bounds/checks the complete raw frame before sending nor validates it on
   receive. App-specific input/state/recipient checks do not establish a global
   frame guarantee. This observation is not a demonstrated data-disclosure or
   code-execution exploit. Receiver checks also cannot undo structured-clone
   allocation; any future claim of denial-of-service protection must be scoped.
2. The remote peer closes its port after receiving an interactive call with
   timeout:null. The local pending call remains pending after 120 ms in Node and
   160 ms in Chrome; explicit local close then rejects disconnected. Inspection
   finds no remote-close/liveness handler in PortConnection. This establishes a
   missing raw-port settlement path, not that every full app-close path hangs:
   ManagedApp detects a closed opener during its 400 ms announcement loop, and
   the presenter monitors tab closure and permits explicit abort/discard. Browser
   crash/navigation/broker disposal while a caller stays open needs composed
   reproduction before selecting the repair mechanism. Do not impose a short
   inactivity timeout on someone who is still deciding in a healthy picker.

The bounded probe observations are:

```json
{
  "browser": "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) HeadlessChrome/131.0.0.0 Safari/537.36",
  "helperRejectsOversize": true,
  "wireEchoLength": 70000,
  "remoteCloseAfter160ms": "pending",
```

Minimal raw-port reproduction, runnable from repository root with
node --input-type=module (remove the second channel block to test only bounds):

```js
import { PortConnection, serializable } from
  './packages/solid-app-data/src/capabilities.mjs';
const channel = new MessageChannel();
const caller = new PortConnection(channel.port1, () => {});
const peer = new PortConnection(channel.port2, (_method, input) => input);
const value = { data: 'x'.repeat(70000) };
try { serializable(value); } catch (error) { console.log(error.message); }
console.log((await caller.call('echo', value)).data.length); // 70000
caller.close();
peer.close();
const lost = new MessageChannel();
const waiting = new PortConnection(lost.port1, () => {});
let outcome = 'pending';
const received = new Promise(resolve => {
  lost.port2.onmessage = () => { lost.port2.close(); resolve(); };
  lost.port2.start();
});
const pending = waiting.call('interactive', {}, { timeout: null }).catch(error => {
  outcome = error.code;
});
await received;
await new Promise(resolve => setTimeout(resolve, 160));
console.log(outcome); // pending
waiting.close();
await pending;
console.log(outcome); // disconnected
```

The 64 KiB claim also needs scope. serializable enforces 65536 UTF-8 bytes where

fixture with the actual shipped Workbench presenter and actual Contacts app,

ManagedApp's task announce path does not perform ordinary managed reconnection.
This gives a concrete recovery case for the proposed next cycle. It does not
prove automatic recovery is absent for tab closure, opener closure, every crash

## Origin and status of the 64 KiB value

Git search for 65536 in capabilities.mjs locates introduction in commit
101a053f5e91a6d3ef9c8e6bc844eb4b6cbbecc7 (2026-11-01), in serializable with the
message “State exceeds 64 KB.” No documented benchmark, maintainer requirement
or cited protocol constraint justifying that exact value was found in the
inspected history and records. Keeping state small is an inference about its
purpose, not recovered author intent. Later document/viewer/recipient designs
refer to it as an existing limit; repetition is not independent justification.
The semantic-open-with proposal's separate 64 KiB bounded-fetch budget concerns
another workflow and does not establish a transport requirement. The maintainer
now agrees that need, purpose and scope must be evaluated before choosing a
size limit. Raw oversize acceptance demonstrates behavior, not by itself a
violation of an agreed universal byte budget.

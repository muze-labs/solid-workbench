# Assistant fixture evaluation

The implementation was evaluated on
`spiral/CYC-20261120-QG24H-310-assistant-fixture`, from `d9f0827`.
The tests cover implementation `0a0535e3e5fd26404bd71dcdd98109c0c1183ee4`.
The verification companion binds this evidence to that exact version.

## Inline permission proof

The focused Chrome test embeds Bookmarks at `localhost` and the assistant
at `127.0.0.1` in a single browser tab. At 390 by 844 pixels, keyboard users
can reach the model approval inside the assistant frame. The assistant
displays the selected title and URL before invoking the mock. An independent
selection read waits for its own approval before returning data.

The waiting call opens and focuses the “Social Bookmarks permissions” modal
outside the dock. The test verifies that the dock stays visible behind the
separate Bookmarks dialog. Deny settles the call without data. Enter on
Allow completes the waiting call with the selected title and URL. A new
call asks afresh, and Escape denies it. Disconnecting the assistant while
waiting closes the prompt. Suggestions are returned and reviewed separately.
The test counts one browser tab throughout the permission flow.

The same test verifies apply and undo, cancelling with a mock response
pending, closing the dock, keyboard focus restoration and desktop resizing.
Manual tagging works while offline in the loaded fixture and the stored
result survives reload. The preview uses a mock model and no external
requests. Both permission prompts were visually reviewed at phone width.
Physical devices and screen readers remain untested.

## Transfer and browser policy

The fixture's opening assets total about 35.6 kB gzip across the carrier
page, Bookmarks page, stylesheet and script. The assistant is requested
only on open. Its script is about 20.2 kB gzip and the complete proof uses
about 57.4 kB gzip of distinct assets across the two origins. These are
estimates for emitted assets. The preview sends them uncompressed.
A cold Chrome phone probe before separating the dialog, at 50 KiB/s down,
25 KiB/s up and 150 ms latency,
reached selectable bookmark controls in 2.55 s over five requests with
115,470 uncompressed response-body bytes.

HTML's window and channel messaging rules specify exact target-origin
delivery, document readiness, sender origin and source, and transferred
ports. The preview validates source and origin before accepting its port.
The assistant iframe retains its separate origin for this validation and
its sandbox enables scripts. CSP Level 3 section 6.4.2 governs the
response-header framing policy, including checks across both ancestors.
[HTML messaging](https://html.spec.whatwg.org/multipage/web-messaging.html#crossDocumentMessages)
· [HTML iframe sandbox](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)
· [CSP Level 3](https://www.w3.org/TR/CSP3/#directive-frame-ancestors)

The Bookmarks dialog uses native modal focus and inertness.
[HTML modal dialogs](https://html.spec.whatwg.org/multipage/interaction.html#modal-dialogs-and-inert-subtrees)

The mock does not exercise provider credentials, persistent grants, or the
planned channel from each assistant frame to the trusted settings tab.

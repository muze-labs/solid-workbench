# Dockable inspector verification

The working branch is
`spiral/CYC-20261119-QG24H-305-dockable-inspector` from `94a3e9c`.
The Turtle verification reference binds this review to the committed
inspector implementation.

## Build and transfer

The published npm lock resolves SimplyFlow 0.10.7, app 0.10.6 and bind
0.10.4. Workbench's bundle test verifies that the shared UI reaches the
inspector host through a dynamic import. The Presenter fixture verifies
that normal startup has no inspector requests. The direct link from a
rendered thumbnail to its source uses the published marker.

The production Presenter graph including the auth callback measured
169927 gzip bytes, up 2032 from CYC300. Contacts measured 136895 bytes.
Documents measured 733737 bytes. That graph continues to exceed the
advisory target. The 81 optional authoring files total 186992 gzip bytes.
Before the final lazy-frame and stacking adjustments, the throttled
390-by-844 Presenter fixture reached the first editable
slide in 27250 ms, transferring 1383222 bytes over 23 requests at 50 KiB/s
down, 25 KiB/s up and 150 ms latency. CYC300 measured 27238 ms and 1376783
bytes over 23 requests.

The HTML Standard defines the popup feature as a request for minimal
browser chrome. Desktop Chrome window IDs provide evidence of an
actual second window in the browser fixture. Window presentation on
other browsers and devices remains subject to their popup policies.
[HTML Standard](https://html.spec.whatwg.org/multipage/nav-history-apis.html#opening-and-closing-windows)

## Focused Chrome and accessibility

The Presenter fixture selected a thumbnail by keyboard, read its named
template and original command source, and retained the selected slide.
A blocked popup left the sidebar available. Chrome reported a different
window ID for the opened inspector. Docking and closing the popup directly
both restored the sidebar with the same template. A second Presenter
instance started with its own closed inspector and empty selection.
The embedded Viewer only exposed its normal editor controls. No Pod writes
occurred during the Inspector workflow.

The app-layout fixture opened Inspect on all ten standalone routes
and verified that wide docked layouts reserve room beside the app.
The existing phone and desktop viewport checks passed. Browser automation
exercised keyboard selection and focus, with physical-device and manual
assistive-technology checks still outstanding.

One focused Presenter attempt timed out before the inspector at the
existing thumbnail image readiness check. The exact test passed on retry.
The first combined browser run also found a test that expected the Account
menu's former wrap point and a second test that treated Preferences as
the bottom row. The revised checks cover keyboard wrapping, the hover
highlight, and the geometry of every visible menu row.

The independent combined-app fixture passed with the revised menu checks.
The other independent browser fixtures passed except the Documents page-fit
assertion already reproduced on main. The initial closed dock also created
a blank iframe, changing the frame tree used by the Preferences accessibility
check. The final dock renders its frame on opening through the public
SimplyFlow bind API. Preferences, Presenter and the ten-app layout fixture
passed against the final build. A pointer probe and visual review checked
the dock at 390 and 1440 pixels. At 390 pixels the dock is above the existing
app toolbar. The final source check passed all 368 tests and both builds.

## Relationship view review

The revised Presenter fixture confirms that the inspector shows the bound
slide path, named template, component and command before showing any
source. Opening Data renders the authored thumbnail binding. The Command
and Component links open their corresponding authored code. Each
meaningful parent has an inspection control and a separate source link.
Selecting the thumbnail row changes the data path from the slide
attributes to the slide list and closes the previous source. The popup
and sidebar preserve the resulting selection. The viewport fixture
continues to cover all ten top-level routes.

The bundle check confirms that authored component declarations carry their
file origin. The new declarations share the existing on-demand authoring
modules, so none are requested during ordinary startup or by picking
an element.

The final relationship view passed all 368 source tests, both builds,
and the focused Presenter Chrome fixture. The combined Chrome run
passed the inspector, its dock/window transitions, and all ten app
layouts before reaching the known Launcher phone-paging timeout. The
independent shortcut fixture passed. Documents reproduced the known
default-zoom page-fit assertion. A final pointer probe and screenshot
review checked the relationship list on phone and desktop with source
closed.

The final Presenter minified graph with auth callback measured 170748
gzip bytes. The 81 optional authoring files total 233223 gzip bytes.

## Inline previews and presentation review

The Presenter Chrome fixture checks each inline preview against its
activating row, verifies that long source scrolls, and closes the
preview with focus returned to its trigger. Navigating to a parent and
returning by breadcrumb restores the initial path and command. The
fixture checks that closing via the browser or the inspector X
preserves the chosen window presentation, that a fresh app reuses the
preference without inheriting the selection, and that only the toolbar
switches back to the sidebar.

A real Chrome pointer drag widened the right-hand dock from 448 to 544
CSS pixels. The arrow-key check shrank it by 24 pixels and confirmed
the exposed width. Workbench content reserved the updated width. The
Account dropdown opened eight pixels below and inside its trigger’s right
edge after the app toolbar wrapped. It stayed clear of the resized dock.
At 390 pixels the inspector fills
the viewport and has no active resize handle. Screenshots at 390 and
1440 pixels checked the icon toolbar, dialog X, background and source
placement. The tint checks cover explicit light and dark modes.

The final Presenter fixture confirms that the pick hint explains the
frame boundary. The embedded Viewer dims while picking and restores its
original appearance once the selection is made. The app pointer is a
crosshair during picking. The inspected document remains the app’s own.

The final `npm run check`, complete standalone Presenter Chrome fixture
and ten-app layout fixture passed. The Presenter minified app graph
including auth callback is 171966 gzip bytes. The inspector route’s reused
design stylesheet is about 5.7 kB gzip and loads when the inspector opens.
The cold app check finds no inspector route or iframe request before
activation.

The combined Chrome run passed Presenter, the ten-app layout fixture,
Launcher paging, and shortcut metadata. Its last fixture stopped on
the existing Documents default-zoom page-fit assertion. The measured
scroll height was 788 pixels for a 748-pixel viewport.

These checks exercise Chrome’s keyboard and pointer behavior.
They do not include physical-device or screen reader testing.

## Breadcrumb and data preview review

At 390 pixels, the Presenter thumbnail name ellipsizes after a compact
right chevron. The breadcrumb keeps its full label in the title and
returns to the preceding selection when activated.

The Presenter Chrome fixture opens a Data preview with both its bound
JSON and authored thumbnail source. A fixture-only value shows JSON
without a source pane, and an unresolved command remains plain text.
An OLDM named node previews as Turtle containing only the selected
subject, with its language tag and custom datatype preserved.
A direct serializer probe also round-tripped an OLDM graph, blank node,
collection, standalone tagged literal, bare named-node reference and
multivalued RDF terms. It verified that the original graph was unchanged.

A pointer check opened, closed and reopened one preview with its
trigger. The expanded state matches visibility. The preview X returns
focus to the trigger. At phone width the content starts alongside
the overlaid X, and the scroll area stays bounded independently.

The final `npm run check` and standalone Presenter fixture passed.
The ten-app layout fixture also passed during this review. The final
combined run timed out waiting for Presenter's image provider before
the inspector scenario. The standalone retry of the remaining fixtures
reached the intermittent Launcher shortcut popover timeout.

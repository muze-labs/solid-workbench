## Boundary and effective behavior

PortConnection was already framework-free and remains the existing transport.
The real gap was browser launch policy required by ManagedApp's constructor:
URL conventions, window/opener listeners and resume session storage were tied
to registration, restoration, request completion and readiness. No new transport,
renderer, storage engine, package or dependency was justified.

CapabilityParticipant in the same dependency-free capabilities module owns the
explicit port connection, restoration identity, register/state/ready/error
sequence, capability completion/cancellation, checkpoints and app close/view
callbacks. ManagedApp inherits it and keeps browser offers, resume tickets,
presentation/focus, preferences authority and broker-embedding conventions.
Existing suite composition keeps the same ManagedApp API; all apps therefore
consume the shared implementation. No product feature dataset or app policy
moves out of its editable boundary.

The independent cross-origin picker now constructs CapabilityParticipant,
validates its expected host source/origin/ticket, passes the transferred port,
and owns its native close/disconnect gestures. It imports no shell/framework,
Metro or RDF implementation. It uses the same registration/restoration/request
mechanism as the suite. The former ManagedApp constructor assumptions no longer
apply to this consumer. It still owns meaningful host/UI policy; those decisions
are not hidden inside a new generic workflow abstraction. Separate raw-wire
recipient/view fixtures remain unchanged to catch same-client assumptions.

This is a private integration proof, not npm distribution or a new production
third-party app. The module remains directly importable and requires standard
MessagePort, AbortController and crypto APIs. There is no automatic window or
storage access when constructing the participant. Domain/HTTP/account policy and
Solid authority stay outside it. A caller must authenticate window offers before
passing a port; importing the class does not grant broker or Pod authority.

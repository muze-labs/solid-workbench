## Contract comparison and ownership

Current published Solid Workspace 0.2.2 supplies native local sources, graph
replicas and their ordering. Its README explicitly excludes conditional remote
writes/cross-tab ordering. Its source snapshot/write APIs operate on object
projections and do not replace Workbench's complete raw-RDF preservation bridge.
Existing loadDocument/saveDocument already implement Metro reads, conditional
create/update, validator reacquisition and ambiguous PUT failure reporting.
Reuse those mechanisms directly.

Notebook and Presenter both previously owned a local persistence promise queue,
revision capture, remote destination/existence checks, baseline read/write and
save acknowledgement. The new owner shares that coordination in both meaningful
app consumers. It leaves Notebook's native index/aliases/collection lifecycle,
per-copy creation journal/always-retained baseline and redirect:error intact;
Presenter retains its current deck/open guard, owner/URL baseline and conditional
creation refusal after a lost receipt. No new retry, simultaneous-save, cross-tab,
automatic sync or complete uncached-offline guarantee is introduced.

App classes specialize one shared class and keep their live fields authoritative;
there is no forwarding object with a second revision/address/dirty state. Native
recovery schemas/keys remain readable, with current Open/New/selection and model
validation in the app. Both APIs and optional source descriptors expose the
shared dependency for inspection. Neither startup nor use needs authored sources.

## Proportionate simplification review

No-change would retain two copies of the snapshot/conditional-save/baseline/
acknowledgement and local-write ordering algorithm. A separate coordinator object
would need callbacks/forwarders or duplicated state to access the same live
revision/address/dirty fields. The small shared base owns those existing fields
and algorithm directly; both app APIs retain their meaning and native storage.

The concrete reduction is that preservation/error fixes to the shared save
algorithm and local queue have one owner and one cross-app contract matrix.
App-specific policy remains visible: baseline/intent factories, Notebook Save As
alias hook and its acknowledgement override; app-owned Open/New/load behavior.
The implementation has 101 lines, and the two original document modules together
shrink by 90 lines; raw line count is not the success criterion. Optional source
metadata and explicit isolated bundling add a modest cost measured above.

Keep app-specific loading/activation and file-reference repair instead of moving
them behind more hooks merely to reduce duplication. No new published package,
generic lifecycle engine or state-model tool is needed to establish this bounded
contract. Broader extraction remains governed by the existing library review;
this evaluation does not automatically select another refactor.

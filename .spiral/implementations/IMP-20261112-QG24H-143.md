# Current-book Contacts recipient picker

CYC139/SRC140/DES141 authorize the confirmed current-book slice. The actual
branch is spiral/CYC-20261112-QG24H-139-contacts-picker. This is uncommitted
implementation under evaluation, not human acceptance.

The new swbRecipientPicker component exposes its template, styles, commands and
actions through Contacts' editable dataset. It uses the existing Contacts model
and native collection, displaying source book, requesting origin, names and
original identifiers. Search, choose, explicit confirmation and cancellation
are read-only with respect to contact RDF. No profile/collection write or Pod
permission is inferred. Ordinary Contacts editing is hidden in transient picker
mode, and the normal filter is restored when an invocation finishes.

Contacts declares select-recipient in its managed registration and manifest.
Requests are bounded to the existing empty-node/@context contract; overlapping
requests fail busy and cancellation is request-scoped. Confirming rechecks the
account, book and membership. Return the contact's exact HTTP(S) or urn:uuid
identity; reject blank/unsupported/credential-bearing identities rather than
inventing a WebID. The selected native RDF description is returned with its identity and optional
document locator, following the maintainer's review correction. No credentials
or unrelated contact records are returned.

Launcher adds Contacts after the existing embedded providers, retaining their
order and the normal browse route policy. The existing provider resolution
callback additionally handles recipientProvider. No broad authorization rule,
transport, registry, renderer or standalone invitation/sharing app is added.

IMP121's existing preference integration is extended to the second capability:
one operation parameter in the native registry reader/writer, separate native
cache nodes per field, independent whole-choice comparisons/drafts and generic
conditional-write preservation. The old browse cache node remains compatible.
Default apps selects Files/folders or Recipients using the same controls/model;
changing task clears stale candidate rows and reloads supported manifest/live
choices. Recipient defaults to built-in Contacts. Anonymous invocations use the
built-in provider. Published dependencies are unchanged.

Verification lives in EVD142: source contracts, shipped presenter and actual
Contacts keyboard/phone/offline behavior, plus independently written wire peers
on another origin, changed provider choice and a second browse provider through
the actual separately hosted Workbench. Fixture peers are test code only and do
not import ManagedApp/PortConnection or replace production UI. The browser
command includes the new recipient suite in addition to existing regressions.

Known boundary: only locally available rows of the current configured book;
uncached data is not claimed available. Book discovery/switching, cross-workspace
search, invitation delivery/permission editing, and the iframe Escape roadmap
repair stay outside this implementation. Browser fixtures do not establish
manual assistive-technology usability or third-party deployment certification.


The picker has its own input field for a transient query while using the
existing Contacts list model. It does not replace the ordinary filter in the
captured app state. Large-text confirmation uses a component-scoped wrapping
class on the native DS buttons. The cold-loaded browser proof explicitly waits
for the pending request before interacting, with a measured deadline.


## Human-review correction: usable data and a real caller

Files now provides Share… on ordinary resource rows. swbFileSharing invokes the
preferred recipient provider through the existing scoped presenter and consumes
native selected data, or reads a document-only result through Files' own Metro
session. It displays contact hints and a clear Permissions unchanged state.
No permission/invitation implementation is added. Previous selections survive
cancel, stale results are rejected, and native workspace state retains only
references/a label. The current local contact graph remains authoritative.
Files declares its existing internal solid-profile data dependency explicitly.

recipient.mjs uses the installed OLDM-Turtle writer over a read-only selected
subject interface; the public writer lacks a partial-subject option and its
anonymous-value limitations are checked rather than hidden. Native typed values,
multiple values, anonymous metadata and named email/telephone value records
remain RDF. Whole-book output and unrelated named entities are rejected.
Contacts previews the returned RDF and rechecks it before completion. New
preparation/return guards prevent cancelled or superseded tasks returning data
into a later invocation.

Files' picker uses its own model-bound list, while the ordinary management table
and edit/share controls are hidden during selection. Shared folder navigation
and the existing native Select/Cancel controls are reused. This meets the
maintainer's explicit distinct-picker-UI direction. The existing browse handler
also refuses busy while a Files recipient selection is active.

# Layered, feature-owned CSS implementation

Status: implemented and evaluated within Active CYC112; EVD116 records passing
checks and bounded evidence. Ready for human review.
No human acceptance, commit, merge, push or publication is inferred.

## Changes and reasons

All 21 authored stylesheets now use explicit cascade layers. The generated head
establishes DS order before loading styles; component-root `theme` adapters map
DS values to small component-owned property interfaces. Implementations no longer
read DS variables directly. Shared component implementations have useful native
color/spacing fallbacks. Existing named styles, origins and originals remain.

Explicit `swb-` part classes replace generic/ancestor-dependent styling across
markup, selectors and affected JS/test queries. DS primitive classes remain
intentional integration. Existing component IDs, commands, fields, capability
identifiers, app handles and persistence formats remain unchanged. No new
framework, dependency or runtime style updater was introduced.

The account header exposes an inherited page variant interface; Launcher supplies
its transparent surface, foreground/shadow and focus treatment without styling
header descendants. Account title rules are consolidated, preserving the effective
compact width. Dropdown padding is a property variant instead of a duplicate
account link implementation. Launcher owns shortcut focus. Explicit keyboard
focus outlines on DS buttons and native suite controls preserve visible focus
through themes; upload focus uses the host foreground for contrast.

List/details owns panes, toolbar and section choices; the host explicitly supplies
available height through a shared fill-content utility. The profile app owns its
outer flex layout and embedded controls policy. Dialog content padding has an
explicit variant used by the capability host, independent of stylesheet order.
Structural exceptions are documented in the shared design README: local menu
hover/current arbitration, component-local presentation/recovery conditions,
page presentation/density state and shared native composition.

Files picker actions are a named template in the existing picker feature. They
follow the browser content in DOM order, occupy their actual flow height and
stick to the scrolling pane edge. Labels can wrap; the fixed 8rem reservation is
gone. Profile line textareas use intrinsic rows with a minimum initial size and
native scrolling/resizing. No selection, persistence, authentication or HTTP
policy changes accompany these layout changes.

Retired workspace-management, background-preview and form-grid selectors have no
remaining authored/dynamic consumers. They were removed after tracing source
composition; the existing workspace-home style identity now owns its recovery
button's stacking. Compact density targets explicit list actions, avoiding an
accidental reach into dialogs nested in a list. No arbitrary line-count target
or broad JS-handle rename was pursued.

The installed DS 0.2.7 distribution has an unterminated Google Fonts import that
consumes its layer-order statement. Chrome CSSOM confirms an import with a
`not all` media condition; baseline diagnostics fetched remote CSS but no font
files. The build now calls the installed public `dsBuildSheet` API with its named
local sheets, excluding optional remote imports. It preserves DS rules, native
font-family fallbacks and explicit layer order without editing node_modules or
shipping DS catalogue JS. No second authored-CSS copy is delivered.

## Narrow and independent surface contracts

The observed 320px title/account collision is corrected within the same cycle.
Visible account controls have their own row below 360px; short-height list panes
scroll their toolbar rather than letting it cover the task. Title paint variants
are consumed only by the intended label/status parts, so menu/dialog surfaces do
not inherit home shadows. Embedded headers without account controls keep their
existing compact presentation. Tests and screenshots retain those boundaries.

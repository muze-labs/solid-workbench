# Shared styles and behavior for compact search and popovers

The solid-design workspace package exposes styles.css for plain HTML styling
after The DS. The Workbench build uses The DS's named-sheet composer to produce
a single optional workbench-design.css asset. App views keep using the named
SimplyFlow style entries built from the same files. The bundled examples are
separate entries and stay out of app startup graphs.

Contacts, Launcher and Documents use one decorative search icon partial and
native label text. The optional icon reserves inset space. PDF's submitted
search retains its form and separate search button. Existing models, commands,
storage and data flows continue to belong to the apps.

Documents and Presenter use the shared anchored popover sheet. Each invoker
pair supplies its own named CSS anchor to support the current browser floor.
The reused SimplyFlow dropdown opens via the native trigger so the browser owns
dismissal and focus return. Arrow keys move through visible actions. Presenter
settings retain native form navigation.

The extension documents exact imports, its markup contracts and runnable native
and SimplyFlow examples. Open UI's popover research and the platform specs are
linked in the design. No proposal-specific JavaScript dependency was added.

Component exports, dataset keys and commands use the `solid` prefix.
The extension's shared selectors, variables, named styles and HTML bindings
use `solid-`. The migration updates the existing consumers and examples.

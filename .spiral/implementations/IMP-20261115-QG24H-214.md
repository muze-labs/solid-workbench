# Published stack adoption

All existing Workspace manifests now require ^0.2.2; shared data requires
SimplySolid ^0.2.2, Metro core ^0.9.4, OAuth2 ^0.9.6 and OIDC ^0.9.7.
The lockfile resolves Metro umbrella/core 0.9.4, Workspace/SimplySolid 0.2.2
and transitive oldm-shape 0.4.1 from npm with registry integrity metadata.
Metro Solid 0.1.0 and Metro OLDM 0.5.1 remain current. The jsfs-owned nested
legacy Metro 0.6.21 remains under its separate required range; it is not the
configured Solid-client replay implementation. Templates 0.1.1 is verified
published but has no existing consumer and is not added.

Files makeFolder no longer sends a dummy Turtle comment. It uses the library's
normal empty-string body while retaining its explicit Turtle Content-Type.
Chrome demonstrated text/plain without that header, so its removal is not
justified. The browser fixture checks real zero-byte PUTs, If-None-Match:*,
BasicContainer Link and text/turtle for success and failure requests.

New public-API tests verify repeated shape mapping preserves extra RDF types,
unknown repeated predicates and other subjects, plus direct/nested/typed HTTP
failure states and direct-status precedence while local graphs stay available.
Transport failures without status remain offline. Both regressions fail when
only the previous published shape/status modules are substituted by a disposable
Node loader; no installed runtime files are patched.

StateGraph and native collection overlays remain: the published object writer
still omits disconnected anonymous cycles. Existing app-specific data validation,
source callbacks, conditional saves and local recovery policy remain necessary.

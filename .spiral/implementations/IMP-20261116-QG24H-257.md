# Grouped Launcher screens and published parser adoption

CYC254 is Active on spiral/CYC-20261116-QG24H-254-launcher-groups.
No commit/integration/acceptance is inferred.

Launcher now projects the existing shortcut resource into ordered screen lists
through SimplyFlow models and jaqt. Native apps:LauncherGroup subjects store
integer rank; each app has an optional named apps:shortcutGroup link. Existing
ungrouped apps use an implicit first screen. Unknown RDF/types/identities remain
in the existing resource. Grouping stays owner/workspace scoped and uses current
SimplySolid collection and Solid Workspace replica storage/sync APIs.

Authored nested list HTML renders screens and the existing icon/menu/settings
markup. Screen width is390px, capped to narrow viewports, with four tracks and
minimal side padding. Regions have ordinal accessible labels and no title/name/
management UI. A trailing empty drop region is authored and toggled during drag
or keyboard Move to; dropping there creates a group. Empty intermediate groups
stay; empty groups at the right are tombstoned after their last app leaves. The
first screen always remains. There are no explicit cells, gaps or row limits.

One scroller fills the remaining viewport and owns both horizontal and shared
vertical scrolling. Screens fill its minimum height and grow with content;
horizontal scrollbar remains at the viewport bottom. Native swipe works there.
64px fixed chevrons with48px glyphs show independently by actual left/right
overflow, never consuming layout space. Focus reveals icons; disappearing
chevrons transfer focus without overriding a later user focus change.

Native drag uses current SimplyFlow event registration, scoped document dragover
for viewport-edge detection and a cleaned-up animation frame for shared vertical
and horizontal edge scrolling. Dashed borders inherit a drag-state property.
The temporary trailing screen does not rebuild the dragged icon's DOM. Shared
insertion markers have icon-area height and an inside variant at a first slot.

Add apps is one round bottom-left floating action, no visible label, with
accessible name/tooltip and shared surface, light shadow/dark glow. Normal toast
placement is retained. App labels remain1rem; restoring swb-list-item on dynamic
classes removes the inherited list indent, recovering the actual column width.

Connected-drop regression found that scalar screen/order edits lacked a new
modification revision. applyShortcutOrder now validates interpreted metadata and
advances dcterms:modified strictly beyond previous time, including same-millisecond
edits. Existing library scalar arbitration remains unchanged. Native drop/local
reload/Pod sync/reconnect are tested together. This also repairs the earlier
single-grid order helper's missing revision update.

Installed published @muze-labs/oldm-turtle0.4.5 using npm dependency/lockfile,
with no sibling link or app parser patch. The anonymous live Pod directory read
that failed on integer-dot Turtle now succeeds through configured Metro.

App boundaries remain Launcher organization and existing Files parsing. No new
runtime dependency or renderer. Normal operational feature datasets stay in the
runtime; optional authored inspection sources remain off startup paths. The
initial named-screen controls and per-screen Add tiles were removed following
maintainer refinements. Add apps card redesign remains future roadmap work.


Group metadata and shortcut projections are published with SimplyFlow's public
batch API, avoiding intermediate nested-list states during a combined update.
Unchanged group descriptors are retained. Native tests wait for the rendered
state after multi-move fixtures before beginning their next keyboard gesture.

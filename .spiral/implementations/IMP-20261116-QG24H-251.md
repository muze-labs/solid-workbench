# Shared UI implementation

Implementation complete; chronological refinements below are preserved. Final verification and explicit human acceptance are recorded separately.


Imported supplied theme as a named solid-design component with library-prefixed
classes/tokens, integrated through suiteAppearance; no vendor CSS/font/script
copy. Authored templates opt into control/choice/label/button primitives. Existing
shared dialog retains lifecycle and scrolling, adopts two-tone surfaces and
unclipped decorative close background. Existing toolbar uses appearance-selected
elevation. List-row state is shared, content/layout stays app-owned; Presenter
thumbnails remain. Six existing apps receive supplied artwork/favicons, including
Present -> Presenter; custom/external icon RDF is preserved.

Launcher menu uses existing SimplyFlow events and native popover/focus. Context
menu, Shift+F10, hold, pointer drag and menu-based movement share actions. Native
integer apps:shortcutOrder scalars stay in shortcut subjects; validate all before
mutation and save once through the collection's whole-resource snapshot. Unknown
RDF/identity are retained; ordered projection stays in SimplyFlow model + jaqt.

Visual review added field spacing for the suite's existing wrapping-label
composition and removed Files-only list padding. List pane dividers now have one
shared owner. Native select wrappers retain browser picker/keyboard behavior and
restore the native arrow in forced colors. Primary and quiet variants preserve
save emphasis and transparent account-menu rows. No input moved into the main
application bar. Account/Preferences embed recovery and dialog guards remain
owned by their existing lifecycle components.

Maintainer-requested tab-title extension: build output retains a descriptive
app-only startup title without the repeated suite suffix. The shell captures its
visible app heading before later content updates. Existing actions now update
native document.title for workspace, file/folder, person and Preferences section;
Viewer strips query/fragment and decodes the final path segment. Notebook's
existing document/collection title handling is preserved. Presenter renaming
updates its title immediately and empty decks retain an explicit untitled label.
Document names alone suffice where they identify the content; person/settings
views retain trailing app context. No icon-only or empty title is introduced.

Header review: generic, compact and Presenter title sizing is consolidated.
App and dialog titles use 1.25rem (20px default) above 16px body text;
control rows are 44px. Main bars use the shared chrome surface and retain the
public header-background override. Dialog close and account dropdown buttons
own their original colored slanted pseudo-elements and white icons, excluding
the generic form-button variants. Focus outlines remain outside the decoration.
Empty embedded headers retain zero spacing; narrow action layouts can add rows.

Maintainer requests all-app review of the shared width limit. None of the
nine shells needs the 80rem cap. Notebook owns its 58rem document width,
Notebook/Presenter own 80rem collection widths, and the profile editor owns
its 48rem form width. Remove the shell cap and temporary Files override;
retain those local content constraints. Verify all nine shells at 390/1920px.

Files supplies --swb-status-background using the same DS background as its
subtoolbar. Shared status rendering retains its marker and accessibility role.
Account has no suite wrapper; the other eight wrappers are now uncapped.

Maintainer requests reusable search styling for future list-details search.
Move the compact field/icon/input styles to solid-design list-details, use
prefixed shared classes in Contacts, and document the composition. No new
search behavior is added to other apps. Model filtering stays app-owned.

Contacts action review: move Edit profile and Delete contact into one toolbar
at the top of the selected profile pane. Contacts uses the existing shared
edit command and opts out of the embedded profile edit button through
showEditButton:false. Hide this toolbar while editing; existing Save/Cancel
remain. Profile standalone keeps its default action. Persistence is unchanged.

Presenter has one deck/slide action toolbar. Its title is display text; a
shared dialog applies title changes through existing native RDF persistence.
Empty decks retain title/Deck actions; slide-only actions follow selection.
Scoped CSS anchors position Deck/View options sheets with inline/block flip
fallbacks and bounded scrolling. Their dark elevation uses the shared glow.

Presenter dropdowns now use native auto popovers with button invokers; CSS
anchors remain responsible for positioning and the browser owns Escape and
outside-click dismissal. Other existing auto popovers remain unchanged.

Popup surface review: maintainer requests no white border and medium shadow
or glow according to light/dark mode. Apply one shared popup appearance class
to native popover surfaces across apps, with medium DS shadow in light mode
and medium DS glow in dark mode. App features retain positioning and content;
remove local shadow overrides. Focus outlines on controls remain unchanged.

Iframe dismissal: maintainer identifies native light-dismiss not crossing
iframe documents and requests a shared small fix. A shell event component

If it is an iframe within this shell, hide open auto popovers outside that

native focus/hidePopover and existing event cleanup; no frame DOM access,
message protocol, content renderer or persistence change is introduced.

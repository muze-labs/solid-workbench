Status: Active. CYC106 / DES108; implementation explicitly authorized.
Evaluation and human acceptance remain pending.


## Implementation boundary

The maintainer authorizes implementation with “lets start” after DES108 and the
immediate-change/inactive-workspace choices. Work remains on the mechanically
verified CYC106 branch from main 0912f86; no integration is authorized.

A fifth app, apps/preferences, owns the editor and named sections. The shared
account command invokes edit-preferences through the existing capability dialog.
Managed callers use their existing broker; a standalone caller composes the same
WorkspaceBroker with only a transient Preferences provider. This reuses the
existing offer/port/cancel/close machinery instead of inventing another transport.
No transient editor enters the persisted workspace app set.

App-owned settings-sections.mjs descriptors and settings.html templates are
registered by Preferences; common entries stay first. Existing build-time
composition is retained. Known suite contributions are supported; there is no
arbitrary remote module loader, provider registry or new app store. The old
per-host dialog factory/form/templates and Workbench's direct editor runtime
coupling are removed. The shared preference document APIs remain available.

The existing list-details component supplies phone snapping panes and desktop
columns. Its existing Back command now prefers the selected navigation item;
small shared rules support full-width native DS section buttons and a constrained
preview. Existing DS navbar/button/selected classes and native form controls are
reused. No new Preferences CSS component is introduced. Broader CSS cleanup is
still a separate roadmap item.

## State, authority and library reuse

PreferenceState stores interpreted confirmed fields, pending choices, native
per-field baselines and incomplete text as RDF terms in Solid Workspace 0.2.1's
local.indexedDB sources. The installed API supports native Turtle load/save but
does not supply this app-specific per-setting immediate/draft/conflict policy.
Use its local sources directly and keep only that policy in solid-preferences.
Native Web Locks serialize source access and synchronization across same-origin
contexts. Metro plus the existing loadDocument/saveDocument helpers owns HTTP,
authentication, strong validators, conditional writes and lost-response errors.

A valid choice is persisted before appearance is applied or a notification is
sent. Incomplete text is a distinct native draft; change/blur/Enter commits valid
text, while selects apply immediately. A source write failure retains the last
effective setting. A newer pending edit survives an older write acknowledgement;
remote edited-field conflicts require explicit local/Pod choice, and unrelated
remote RDF is retained. An already-equal remote field acknowledges a lost write
without blindly repeating it. Shared notifications contain only owner and a nonce;
startup/online/visibility and existing sign-in recovery refresh owner-scoped
cached choices. Background synchronization never opens authorization per keystroke;
explicit Retry uses the existing interactive recovery flow.

Workbench remains the sole live workspace writer. A narrow preferences-workspace
RPC verifies provider origin/path, selected owner, target ID and revision before
create/rename/delete/settings/background mutations. Existing native stage/save,
protected deletion, unknown RDF and image/cache/conditional upload rules remain.
A selected inactive workspace does not mutate directory.active or close apps.
Incomplete workspace text is cached separately with owner and target identity.
Local write completion gates closing; synchronization can continue/recover from
its durable pending state. Workbench sends settings synchronization status over
the existing private port; failed sync retains edits and offers existing recovery.
Standalone workspace editing offers opening Workbench, rather than adding another
workspace writer. App-specific settings from managed Files/Contacts target the
caller's workspace; standalone app sections edit existing global defaults.

Background byte helpers are shared only by Workbench and Preferences, in a
separate ordinary Rollup chunk, so other apps do not download workspace images'
storage implementation. All required chunks and the auth callback remain counted
in each app budget. No external version/dependency upgrade or publication is
performed; new app metadata and direct use of the already installed workspace
library are recorded in package-lock.

## Evaluation boundary

workspace service contracts cover owner/provider/revision/target checks,

## Keyboard review correction, 2026-11-08

The maintainer requests Up/Down behavior like the dropdown, Enter to switch
sections and Tab into section controls. Inspection finds ordinary buttons with
no arrow navigation; activation currently moves focus to the heading. Extend
the existing list-details component with an opt-in section shortcut scope.
Arrows move focus and wrap without selecting; native Enter selects while
keeping keyboard focus in the list, and Tab moves to the displayed section's
first enabled visible control. Shift-Tab returns to the selected section.
Pointer activation retains heading focus and phone detail navigation. Native
arrows within input/select controls are unaffected. SimplyFlow binds a single
roving Tab stop, and stable row objects retain focused DOM nodes on activation.
No new CSS component or persistence change. This is an authorized correction
inside Active CYC106; human acceptance and commit/integration remain pending.


## Presentation focus correction, 2026-11-08

The maintainer explicitly adds workspace-menu icon alignment to this cycle and
reports arrows unavailable, suspecting stale server assets. Installed the-ds
sets ds-icon vertical-align to bottom; CSS center is invalid. Apply middle to
the suite's shared svg.ds-icon default in its existing foundation style, without
editing node_modules or the external design-system repository.

Live HTTP checks on port 4174 confirm the actual process serves this checkout's
current bytes with Cache-Control: no-store. A fresh Chrome probe against that
server reproduces outer Close-button focus and child BODY focus; Down works only
after manually focusing the section. The cause is presentation focus, not stale
served bytes. Preferences now receives an initial focus request after SimplyFlow
has removed iframe inert/hidden/busy attributes. A native MutationObserver waits
for that concrete browser state; it does not render content. An immediate check
also handles an already-interactive frame. The callback targets current actions
and respects an interaction already started by the user.

Only Preferences requests this focus policy. ManagedApp validates the parent
window, origin, live task/peer and exact ticket ID/key before invoking its optional
onFocus callback. Other capability providers retain their own focus behavior.
Observer cleanup and existing private capability lifecycle remain intact. A live
server probe verifies initial focus in the iframe's selected button and the
first Down reaching Language without setup focus. Human acceptance, commits and
integration remain pending.

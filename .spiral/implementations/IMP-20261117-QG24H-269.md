# Reading navigation implementation

CYC266 is Active on verified branch
spiral/CYC-20261117-QG24H-266-find-resume-reading, from main 3a63f96.
The maintainer confirms “ok” to Find and resume reading: document search sidebar
with multiple contextual results and exact-position navigation/highlighting,
per-document and global bookmarks, and investigation of reading-position reload.
Existing search is a modal returning one page; reader state stores only the last
position. No deliberate bookmark list or cross-document resume interface exists.

Documents owns reading navigation. Reuse SimplyFlow for content, native RDF for
account-scoped local bookmark records and the existing locked local storage.
Bookmarks reference source URIs and revision digests, leaving annotation folders
independent. Loaded bookmark lists work offline; reopening uncached PDFs requires
network. Keep failed opens and bookmarks recoverable; never discard changed-source
anchors. Pod synchronization and bookmark sharing require later storage policy.
Phone uses existing sidebar overlays, native search/forms/buttons and keyboard
navigation, with focus returned to the paper on result activation. Search is lazy,
sequential and cancellable by generation; no new dependency or startup request.
Measure download impact and verify phone/desktop geometry, keyboard interaction,
unknown RDF preservation, multi-instance bookmark updates and reload restoration.

Paged/spread reading and collections remain subsequent work. Existing roadmap
edits and unrelated company vision document are preserved. No commit, merge or
publication is requested for this Active cycle. Evidence will distinguish actual
passes from inherited/intermittent browser failures and manual review limits.


Implementation uses a separate editable Documents navigation component with
commands for sidebar mode, search/results and bookmark add/open/remove. Its
bookmark projection uses a SimplyFlow model for current-document filtering.
Search walks PDF pages sequentially and discards outdated generations; results
retain page, quote and source offsets for exact range highlights after lazy
rendering. Source and reader bytes continue through existing Metro APIs.

ReaderState now reads/writes native bookmark membership and scalar fields under
the existing account lock. Add/remove reread current RDF and preserve unrelated
statements; removal detaches only membership. Global bookmarks reopen source
URIs and refuse stale-revision anchors with a message, retaining the bookmark.
Local-file bookmarks require reopening the local PDF. Lists are device-local;
no Pod write or permissions integration is added.

Page restoration waits for SimplyFlow-bound geometry, refreshing sizes learned
by background PDF rendering. This replaces the one-frame assumption. Existing
continuous lazy scrolling and annotation storage remain in the same workflow.
Phone handles are narrow edge controls; navigation is an overlay on phones and
a left panel on desktop. Native inputs/buttons expose keyboard equivalents.


Review correction: bookmarks, document search, outline and thumbnails are
mutually exclusive. The maintainer reports saved outline visibility being
restored alongside bookmarks during cross-document navigation. A shared
normalization action runs after applying reader settings and restoring desktop
panes: an open navigation pane takes precedence, then thumbnails, then outline.
The existing toggle commands already close their alternatives. Annotations
remain separate from this four-panel rule. The regression follows a bookmark
with saved outline enabled and checks actual visible panels after every switch.


Further review: bookmark rows remove inherited list-item indentation and use the
shared menu hover/current colors, plus a focus background. Remove is a positioned
overlay revealed by hover, focus-within or current selection, remaining tabbable
so keyboard focus can reveal it. Source URI moves to the row title. Empty labels
remain empty native RDF strings and empty label spans do not reserve a gap.

Bookmarks use SimplyFlow's built-in sort effect, grouping global results by
source document then numeric page; annotations use the same effect by page before
viewport filtering. This keeps page changes responsive and native RDF untouched.
Equal-page ordering follows the existing source sequence. Tests must observe the
model's asynchronous sorted projection rather than require synchronous DOM/list
updates after a save or attachment.

# Paged reading implementation

CYC272 Active on verified spiral/CYC-20261117-QG24H-272-paged-reading,
from accepted main 6e61f15. The maintainer confirms “lets do that” to continuous,
single-page and two-page reading, position preservation, remembered preference,
keyboard navigation and lazy rendering with all existing navigation/annotations.
Current implementation offers only continuous vertical flow. Single/spread
layouts will hide unrelated page rows through SimplyFlow, preserving page identity.
Spreads pair 1–2, 3–4, etc.; narrow screens display a single page while retaining
the spread preference. Next/previous advance a spread when two pages fit.

Documents remains the reading app; native PDF.js surfaces retain their existing
approved exception, SimplyFlow renders controls and page visibility. Reuse local
locked ReaderState native RDF for mode, with backward-compatible continuous default.
Mode changes preserve page/fraction. Already loaded bytes work offline subject
to existing engine/assets availability; uncached documents require network.
No new dependency or startup request. Compact native toolbar select and buttons,
keyboard PageUp/PageDown and Home/End, accessible labels, and phone-first layout
are required. Verify search/bookmarks/outline/thumbnails and annotations in each
mode, odd final spreads, mixed page sizes, resize and reload. Retain advisory
budget measurements and distinguish automated from manual AT/device evidence.

No commit, acceptance, merge or publication requested. Preserve unrelated vision
Markdown. Pod bookmark sync, collections and EPUB format support are later work.


Implementation adds a native compact toolbar mode select and local native-RDF
readingMode preference. Existing Show/Page/viewport actions now retain page
identity while projecting hidden rows for single/spread reading, fitting spread
width to the paper area and rendering at most two page surfaces. A paged target
fraction is retained when the available scroll range clamps it, until the user
scrolls elsewhere; mode switching can then recover the requested position.
Spread preference falls back to single below 720px without rewriting the saved
preference. Existing search, bookmark and outline/thumbnails call the same Show
action. PageUp/PageDown/Left/Right and Home/End apply when the PDF region has focus;
continuous mode retains native scrolling. Mode settings reuse the account lock
and preserve unknown RDF. Final navigation rechecks generation after layout
settles and evicts unrelated paged renderers before completing.


Reader review correction: spreads now fit the current paper area rather than
cache their first width; compensate for per-page padding so the pair occupies
the same default reading width. A paper ResizeObserver recomputes spread fit
when sidebars change, preserving zoom/page/fraction; single/scrolling fit is
unchanged. Deferred resizes settle after ongoing navigation rather than racing it.

The reading-mode text select becomes an icon-only native popover trigger with
a 12px down-chevron below the icon within the existing 44px button height.
Reuse shared dropdown rows, current-choice styling and required shortcut scope;
Arrow Up/Down, Enter, Escape and native focus return remain available. No added
npm dependency or mandatory request; SimplyFlow renders choices and current state.

The spread now uses the paper viewport width less a 4px center gap, divided
between its pages. The PDF session supplies one scale for the slot, canvas and
text layer, with uncapped width fitting in spread mode. Documents removes the
suite's inline shell padding and spread mode removes inline paper padding.
Actual content, page proportions, scrollbars and explicit zoom remain intact.

Two native launcher-style chevrons sit in a stationary frame around the paper
scroller. They invoke the existing page-turn command for single pages, phone
fallback or spreads. SimplyFlow hides unavailable directions and both controls
in continuous mode. Position recovery accounts for the browser clamping the
scroll offset when hiding the loading status increases viewport height.

The final fit combines a stable preferred width with the available frame width
and height. The first wide spread records the full reader width using an
account/device-local Turtle integer. Competing readers use the existing store
lock so the first reference wins. Initial window height is a temporary
constraint. A taller window can recover the originally requested spread width.
Rendering measures the visible page or pair before fitting and accounts for
rotation and the taller page. Frame resizes also include height-only changes.
At 100% or below every page fits. Above 100% explicit zoom magnifies the fitted
page and permits scrolling. Removing the inline canvas baseline and the suite's
outer shell padding gives the complete PDF page the available reading area.

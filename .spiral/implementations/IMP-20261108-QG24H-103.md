# Workspace and Launcher foundation

Implements DES102 on spiral/CYC-20261108-QG24H-100-workspace-launcher.
Human acceptance, commits and integration remain pending. No external libraries
or repositories were changed; no dependency was added.

The native workspace directory records the selected workspace, titles, private
storage additions, app-specific settings and inactive managed app sets. Existing
native workspace encoders, conditional writes and local Turtle recovery remain
authoritative. Deleting an inactive non-default entry unlinks its membership;
linked datasets and unknown RDF remain. A positively confirmed missing previously
saved default creates initial setup and retains a native recovery copy. Failed
reads do not establish deletion.

The home screen presents labeled icon shortcuts and workspace switching, with
management in Workbench Preferences. Diagnostics retain the prototype resource
and broker controls in a closed disclosure. Built-in applications ship native RDF
manifests and SVG icons; Metro/OLDM reads optional custom manifests, and users may
override names/icons independently. No executable manifest code is loaded.

Each workspace has a distinct SimplySolid shortcut collection and local keys
include owner/resource. Initial Files shortcuts cover profile storage plus
private additions. Save to Pod synchronizes directory shortcut datasets before
conditionally saving workspace state. Explicit device recovery can import the
legacy origin-wide collection without deleting the source.

Switching checkpoints current apps and awaits durable local writes before
closing them and restoring the selected app set. Checkpoint/storage failure
leaves the current set open. Managed Preferences must be closed before a switch;
domain edit drafts are restored through the existing native app-state contract.
Trusted same-origin suite apps receive only their allowed workspace setting keys
over the existing private managed channel. Selected identity scopes local data;
it is not authentication and grants no Pod rights. Standalone defaults and common
profile-linked preferences retain their existing behavior.

Contacts and its inline Profile view use owner/resource-specific local data;
Files honors the explicitly launched root before the workspace default. New
workspaces reuse the configured/default Contacts resource reference. Creating a
missing remote book still uses Contacts' explicit synchronization; multiple book
discovery/search and selection capability are deferred to the next design cycle.

Library inspection found no reason to replace existing SimplyFlow, SimplySolid,
Solid Workspace, Metro or OLDM contracts. App-specific missing directory/context
policy stays in narrow monorepo bridges. SimplyFlow owns content rendering and
registered feature datasets; native calls handle focus/dialog/popover lifecycle.
A real shared/profile chunk removes unused profile editing code from Workbench
and Files. A finer chunk experiment increased cost and was reverted. Workbench's
readable graph uses the maintainer-authorized temporary 215000-byte ceiling;
production/other app graphs retain 200000, with reduction work left visible.

Known limits: static assets must be available to start offline; uncached Pod data
is unavailable. There is no new ACL editor, widget runtime, app store, global
cross-tab lock, multi-WebID aggregate view or external app settings registry.
Custom remote image availability follows browser image loading. No live Pod
provider/access-control or screen-reader usability claim is made.

## Maintainer review correction

The home presentation described above is superseded by the review in SRC101 and
DES102. The existing account header now supplies the sole title. Launcher-specific
menu entries are compiled into its existing dropdown and bound through an exposed
workspaceMenu feature; the workspace list is hidden when only one exists. Shared
shell composition accepts account feature entries just as it accepts preference
entries. Other applications retain their app heading, without the document's
suite-name suffix.

The separate home switch/save/status toolbar is removed. Add shortcut is a
labeled plus icon tile in the same grid as application shortcuts. Per-shortcut
options use native dialogs. Preferences offers Open diagnostics, which closes
Preferences before opening the Launcher-owned diagnostic dialog. The existing
resource, workspace/save/conflict and synchronization tools remain there, with
no disclosures on the home screen. Tabs were optional in the review; a direct
Preferences entry satisfies access without adding tab state or keyboard handling.
All markup remains build-time composed and SimplyFlow-bound; existing native
menu/dialog components handle focus and lifecycle. Persistence is unchanged.

## Tab focus investigation and maintainer disposition

The reported last-restored-tab activation reproduces in Chrome. An attempted
self-focus call and then a named-Launcher-context activation both fail a browser
assertion after two app tabs restore. Neither workaround remains in product code.
The maintainer explicitly selects retaining tabs with browser-controlled focus;
the existing window/tab preference is unchanged. The strengthened workspace
scenario restores two participating app instances, retains the unsaved native
draft and checks that an explicit shortcut still activates its app. There is no
claim that DOM heading focus selects the Launcher browser tab.

## Feather defaults, stable menu order and workspace backgrounds

The shared full Feather sprite is copied from the maintainer's reference checkout
as feather-icons.svg, with its MIT notice distributed alongside it. All suite SVG
controls use it with the-ds classes. The retired partial sprite is removed.
Default manifest icons refer to folder/users/user/grid symbols; shortcut rendering
uses SVG/use for this sprite while retaining custom image URLs. Recognized prior
default-icon references project to Feather, and standalone app icon URLs remain
usable. The plus tile also uses the shared sprite. Common WebID / connection and
Preferences entries precede workspace entries. Workspaces have a layers glyph
and distinct accessible labels, including a workspace literally named Preferences.

An optional apps:background RDF resource reference on each workspace identifies
a stable preset, a custom/acknowledged Pod URL, or a pending local upload UUID.
Existing native cache/conditional graph writers preserve it and unknown facts.
The six original JPEGs are copied as optional shared assets; None remains the
initial choice. The editable launcherBackground and backgroundPreferences
features own decorative image binding, controls, object URL lifecycle and feedback.
Opaque shortcut/header surfaces preserve text contrast. A missing image retains
its choice and uses the normal theme. Image loading does not block shortcuts.

The app-specific backgrounds.mjs bridge uses owner-scoped CacheStorage for raw
binary bytes because Solid Workspace 0.2.1 local sources accept Turtle strings
only. It adds no HTTP/auth machinery. Metro reads uncached images and conditionally
creates uploads beside the configured workspace resource on explicit Save to Pod.
JPEG/PNG/WebP uploads up to 5 MB are decoded and cached before native staging.
A failed local stage restores the previous choice; failed/ambiguous uploads retain
pending bytes. A 412 retry only acknowledges the upload after exact byte and MIME
comparison. Original cached bytes survive, including known anonymous adoption.
Deleted workspaces never delete linked images. Images follow the configured
folder's Pod permissions; the app does not infer ACLs from a workspace file.

The source modules/feature entries remain exposed for moldability. No dependency
or shared external library is changed. The temporary readable Workbench ceiling
is raised from 215000 to 220000 under the existing maintainer allowance; measured
cost and cold asset/image impact are retained in EVD104. Human acceptance remains
pending.

## Transparent Launcher presentation

The maintainer's latest correction supersedes opaque home surfaces. Shortcut tiles,
Add shortcut and shortcut-settings buttons are transparent. Launcher-only CSS
removes the header/account backing fills; the existing photo layer already fills
the viewport, including the title area. White title/labels have a dark text
outline/shadow; Feather/image silhouettes have a dark drop shadow. Empty-home
feedback uses the same readable treatment. Keyboard focus has a two-color outline
without a persistent panel. Shared dialogs/popovers and other applications retain
their theme surfaces. These are declarative styles in the existing editable
background/shortcut features; no runtime renderer or data/network changes are
added.

## Icon-only backing and dropdown marker correction

Restore the account/dropdown marker's original shared filled, angled button.
Remove the Launcher overrides which had made that button transparent/unclipped;
keep its keyboard outline inside the clipped shape. Preserve Feather stroke
icons and give SVG/custom image icon boxes a small padded square using the DS
accent/contrast colors. Add shortcut gets the same backing. The containing link,
shortcut tile, labels and original title remain transparent with contrasting
shadows. No markup, renderer, persistence, image bytes or network behavior changes.

## Light-mode foreground correction

The home foreground now follows the public DS --ds-color token, with no text
shadow by default. Explicit dark mode and automatic mode under a dark OS
preference select the established dark shadow. This uses the existing DS classes
and media query, without new theme state or a persistence change. The marker is
removed from the home text-color override so its original filled button keeps
its own white glyph color. Padded accent icons likewise keep white glyphs while
their separate labels become dark/shadow-free in light mode.

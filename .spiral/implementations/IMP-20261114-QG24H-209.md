# Notebook portable collections and file lifecycle

Implements the confirmed CYC205 goal and DES207 on the matching isolated branch.
SRC206 retains the explicit managed/linked and confirmed permanent-delete choices.
Implementation and affected verification are complete for review; no human acceptance or commit,
merge, push or deployment authority is inferred.

Native RDF collection records, independent document URLs, groups, cached summaries,
app-owned default preferences and per-account local recovery use installed Muze
APIs. Solid Workspace owns replica merging and admitted write ordering. StateGraph
preserves full raw RDF while its known-field projection avoids the installed
writer's cyclic-structure failure. Empty group relations use the public graph
remove API because the installed array writer emits invalid Turtle for [].
The complete format is documented in design/portable-collections-format.md.

Notebook exposes collection create/open/default, a searchable/grouped listing,
preferred file-picker operations, reserved creation targets, summary updates,
linked addition, membership-only removal and explicit confirmed file operations.
Existing Cobalt H1/rich editing, formatting and on-device drafts remain in place.
Physical operations record native intent, use strong conditional writes and reject
destructive redirects. Copy verification, content removal and parent metadata
publication are separate recoverable steps. Cached addresses are repaired after
move; deletion retains drafts with no active Pod URL, preventing ordinary Save
from reviving the old address. Existing Files tombstone-only deletion is unchanged.

The new rapid Escape/reopen browser probe exposes shared dialog cancellation bound
by both shell and nested app. Shared native lifecycle now honors an already handled
cancel and shares pending close state by element through its prefixed public API;
opening waits for any pending close. No duplicate renderer or transport is added.
A fast-start probe also verifies that body editor focus waits for its model/DOM,
and is restored after the collection dialog closes.

physical-phone usability and assistive-technology human review remain distinct
from automated fixtures. Cross-resource file operations are not atomic.

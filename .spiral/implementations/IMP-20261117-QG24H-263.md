# Documents and portable annotation bodies

Implementation for human review in CYC260, implementing DES262 and SRC261 on the verified
cycle branch. No commit, human acceptance, integration or publication. Causal
Git references will be pinned when commits are authorized, not invented here.

Documents uses published PDF.js 6.5.438 (legacy browser build), with Metro byte
and engine-asset reads. Full PDFs are bounded at 32 MiB. Canvas/text rendering
occupies the approved specialist surface; SimplyFlow renders app controls and
sanitized HTML notes. Page, selected-text and tagged-paragraph anchors carry
source URI and revision digest. A changed digest retains the original anchor.
Original bytes are available for download without changing the source PDF.

Each PDF/group has its own native Turtle graph. Personal notes start in
account-scoped local storage. A separately chosen annotations folder receives
an explicit conditional create; no write is sent to the PDF origin. Resource
names hash the PDF URI and stable group root, avoiding name collisions. The
local native index maps PDF URIs and group IDs to resource URLs. Remote ETags
and separate native baseline files survive reload. Existing permissions apply;
there is no permission editor or implicit ACL modification. No remote index is
required for this first implementation; resource URLs and Turtle export/import
support opening groups elsewhere.

Local writes use browser locks and baseline comparison. Competing drafts are
preserved in separate local recovery entries, retaining both native versions.
Recovered conflicts cannot be published as if resolved. Remote writes reuse
saveDocument's If-Match / If-None-Match protection and missing-validator refusal.

Default editing loads Cobalt lazily. Display loads no Cobalt. The shared
cobalt-html module writes a linked HTML TextualBody along with native Cobalt
fragments for Notebook, Presenter and Resource Viewer, as well as returning
HTML from the editor capability. PDF annotations can use another edit-note-body
provider. The default importer refuses unsupported HTML rather than flattening
it. DOMPurify sanitizes displayed notes.

EVD264 records passing feature checks, the reproduced baseline launcher-test
failure and other explicit limits. Human acceptance remains pending.

Save operations retain the originally selected group and account. Later edits
do not change an in-flight snapshot; account changes and editor transitions
are guarded while saving. Every save rechecks the independent folder boundary,
including restored destination metadata. Default-provider recovery recognizes
its already-applied output without discarding an unacknowledged draft.

## Viewer review correction

Opening/search/outline/group forms now live in native toolbar-triggered dialogs;
no details/summary controls remain. The embedded provider hides the source
opening action and renders the PDF immediately. The notes panel is hidden by
default, opened from the toolbar or after saving a note. Shared square icon
controls have accessible names, native dialog Escape/focus restoration, and a
scrolling toolbar on phones. The PDF surface owns scrolling within the available
view height. Annotation storage and editor contracts remain unchanged.

Publish the PDF.js worker as pdf.worker.js. The old running server knew .js but
not .mjs MIME; the regression server deliberately omits .mjs support to verify
loading under that condition. Existing .mjs/.wasm MIME additions are retained
for new server processes. No claim of reproducing the maintainer's exact browser
session is made.

The PDF scroller reserves scrollbar space; ResizeObserver waits for the initial
render/extraction before initiating replacement renders. Closing the notes
panel explicitly restores toolbar focus after the visibility update.

## Shared design alignment

Documents composes the existing muzeSolidDesignDialog component, including its
open/close animation, cancellation and focus lifecycle. Dialog templates use
the suite header/title/marker-close/content primitives and full-screen phone
layout. All form inputs use shared controls and labels; the annotation-group
select uses the shared select wrapper and chevron. The notes panel and reader
background use shared theme surface/chrome/text/divider colors. The white PDF
page remains document content. Custom dialog dimensions/header styling and the
parallel close command were removed. No shared styling was changed.

## Continuous reader and persistent outline

The outline is a persistent, independently scrolling left navigation panel,
toggled from the toolbar. Shared list-row controls mark the current page and
remain available across repeated navigation. Phone layout keeps outline and
pages side by side, with the outline limited to 40% of the reading area.

SimplyFlow owns a list of page-sized placeholders. A PDF session now owns
independent page renderers. Scrolling renders the visible page first and a
viewport-sized buffer on either side, releasing distant canvases and text
layers while preserving focused/selected pages. Page dimensions are learned
lazily, using page-one dimensions for unvisited placeholders. Native scrolling
and Home/End update the current page; previous/next, search, notes and outline
entries scroll to the requested page. Selected-text anchors use their own
page renderer; highlights are projected across all rendered pages. Zoom,
rotation and width changes invalidate affected renderers.

The PDF remains one bounded Metro read. There is no new range transport or
service, and unvisited pages can still require uncached PDF engine font/CMap
assets. This change does not claim an installed offline application. Separate
paged/facing-page layouts are not implemented. Existing HTML annotation,
separate-folder, conditional-write and recovery contracts are preserved.

## Reader continuity and annotation dialog correction

Added reader-state.mjs for account-local native RDF preferences/bookmarks,
field-level locked merging and revision-aware reading restoration. The layout
width now sets the PDF scale independently of sidebar visibility. Outline list
items reset inherited indentation.

Annotation bodies link native Cobalt RDF through dct:hasFormat, preserve unknown
graphs and prefer validated fragments over HTML conversion. Drafts keep native
fragments too. The editor uses a shared Save/Close dialog, floating formatting
controls and a separate link dialog with a frozen selected range. Closing keeps
the draft. Published Cobalt 0.2.0 supplies HTML import; the app-owned converter
is removed and all existing Cobalt consumers use the same npm version.

## Destination and responsive-pane refinements

The maintainer confirms external annotation files are view-only by default,
with an explicit Enable writing action. New notes offer enabled writing groups
and resources in the note dialog. With a replacement editor, choose the
destination before handing control to that capability. Existing notes retain
their source; this is not a general annotation-move UI. A newly created empty
marker is retained locally for recovery and can change destination on Save:
preserve the completed destination first, then detach only the original empty
marker membership. Unknown RDF stays intact; failed persistence retains drafts
rather than publishing either resource. Pod saves remain explicit/conditional.

Small screens start with all sidebars hidden, even when desktop preferences
remember an open pane. Toolbar handles open one overlay at a time. Outline and
thumbnail navigation dismisses the overlay and returns keyboard focus to the
reader; paper scale is unchanged. Phone thumbnails fill the reader width and
wrap into rows. Desktop retains side-by-side panels. Saving a note does not
automatically reopen a phone sidebar. Thumbnail rendering is bounded to the
pane's viewport plus a short buffer, sequential and cancelled/released on close.

The maintainer also asks to discuss standalone Documents collections like
Notebook/Presenter. Proposed as a following cycle, referencing PDFs and separate
annotation resources without copying source bytes. It is not implemented or
accepted as part of this correction.

## Further review: responsive continuity and compact annotation cards

The maintainer requests desktop panes to return after a narrow-window interval,
and paper to retain its reference fit width: shrink when needed and restore up
to that width without further enlargement. Explicit zoom remains unchanged.
Each resource receives a persisted local hue, reused for dark card backgrounds
and lighter PDF highlights; source/author metadata remains available as well.

New-note close must not leave an empty annotation. Closing a new draft now
removes its provisional marker and draft; saving empty text removes an existing
annotation. Existing-note close still preserves its unsaved draft. This supersedes
the earlier close-keeps-new-marker behavior. Removal drops the annotation and its
owned body/target/native-fragment statements, preserving shared subgraphs and
unrelated RDF. Group resource publication still requires its conditional save.

Hover/touch on a highlight emphasizes the matching visible card(s), scrolling
the open sidebar without moving the PDF. Closed phone panes stay closed until
their handle is used. Keyboard text selection supplies an equivalent activation
path; keyboard note editing remains available through native controls.

The maintainer requests nicknames/first names, never visibly printed WebIDs.
Use embedded names or the existing Solid profile reader through Metro, caching
native profile RDF per account. Unavailable profiles do not block notes: a stable
generated symbol pair identifies the author, with WebIDs in hover titles only.
Compact cards replace the text edit button with a pencil visible on hover/focus
and touch. Source names remain compact with resource addresses in titles.

The maintainer additionally requests Ctrl+Enter to save without leaving the
editor. The default editor now invokes the ordinary Save command on Ctrl+Enter
or Cmd+Enter; ignore held-key repeats and text composition, and leave the
hyperlink dialog's form behavior intact. The native Save control advertises the
shortcut. Source/build and targeted interaction results are recorded in EVD264.


### Search and hover review refinements

The maintainer asks for all annotations independent of visible pages and search
similar to Contacts, then specifies an icon-only toolbar toggle with a title and
pressed background. The existing SimplyFlow notes model now owns scope and
search options. All mode includes all loaded groups for the current document;
search matches decoded note text, displayed authors and group names. Results
have native page-navigation buttons. The Contacts search primitive and shared
pressed toolbar styling are reused, with no dependency or persistence change.
Loaded annotations can be searched offline; missing remote resources are not
implicitly fetched. Search and scope remain transient view state.

The maintainer also reports lingering hover emphasis and requests a background
change instead of an outline. Empty hit sets and pointerleave now clear emphasis;
active cards use a lighter shade of their resource color, retaining native focus
indicators. These changes remain review corrections inside Active CYC260.


Card metadata is now one compact nickname/group header row. All-mode page links
use numeric bottom-right overlays, with accessible names and titles. Long labels
truncate within the pane, retaining their metadata titles; controls keep native
keyboard focus and existing toolbar design tokens.


Whole-card non-interactive clicks/taps use the existing page navigation command;
Edit and annotation links remain independent, and native page buttons preserve
keyboard equivalence. A subsequent visibility bug report exposes the old selected-
writing-group filter. Both list modes now include all loaded groups for the PDF:
visible mode additionally requires a visible valid anchor, while All mode does
not. Writing-group selection is a storage choice only. The earlier descriptions
of restricting visible mode to the selected group are superseded.


Final review removes reserved page-number footer spacing and the sidebar X.
Chat, thumbnails and contents use the selected toolbar background while expanded;
chat state derives from actual panel visibility. Hover reveal observes the
SimplyFlow-bound card key/active attributes before measuring scroll geometry,
fixing the reproduced one-frame binding race without taking over rendering.

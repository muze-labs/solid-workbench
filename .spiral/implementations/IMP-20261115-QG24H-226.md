CYC223/SRC224/DES225 govern this implementation on verified
spiral/CYC-20261115-QG24H-223-presenter-collections. Exact final design:
DES225@650bbae2b22edd531ceed4b1db323ad35d67e902. The maintainer authorizes
commit/integration; ACC228 separately pins implementation and evidence versions.

Presenter now opens its native default deck collection, offers one New deck link,
and supports explicit create/open/make-default, category management, linked
membership and confirmed managed file operations. Existing DocumentCollection,
CollectionPreference, ResourceLifecycle, resolveResource and DocumentSession
supply native persistence, conditional writes and operation recovery. The
profile-linked preferences subject is urn:muze:solid-app:presenter. Merely
switching collections does not change it. Defined inaccessible defaults retain
the URI/cache. The current deck stays in the existing owner-scoped store;
uncached deck bodies require access and dirty documents veto replacement.

The shared muzeSolidCollectionBrowser dataset owns category/entry HTML, CSS,
SimplyFlow models and entry/category dispatch. Notebook and Presenter configure
labels, route builders and app commands. Management dialogs, editing and
lifecycle policy remain app-owned. Native category links retain focus while selection attributes update; dialogs and controls retain labels and native keyboard interaction.
Category assignment adds to existing categories; clearing is explicit.

Presenter's native local-target reserves managed deck creation without creating
placeholder Pod content. It is excluded from remote content and cleared only
with save acknowledgement. A completed deletion detaches the current binding
while retaining native draft content. Move acknowledgement adopts the target
validator only when the local graph corresponds to the moved source, preventing
an old cache from overwriting a newer deck. Presenter injects a separate
solid-presenter-file-operation owner-scoped local source into ResourceLifecycle,
so Notebook's operation journal cannot be adopted or overwritten.

Routing supports collection/member/category/create links and browser history.
Direct deck resources remain independent. Account mismatch/access errors retain
the requested URL; collection navigation does not authorize another account.
Current deck resumes retained work; overview does not destroy provider drafts.

Build composition exposes version-matched optional sources and isolates shared
collection data/browser chunks to the two consumers. No dependency, parser,
HTTP/auth, renderer or collection format changes are needed. Tests cover native
target persistence, account checks, deletion preservation, stale move validators,
reactive browser models, existing editor behavior and collection workflows.

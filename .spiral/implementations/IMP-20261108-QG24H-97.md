# Experimental SimplyFlow event bindings

Implementation in CYC92 after the design discussion and SRC96 authorization,
on spiral/CYC-20261108-QG24H-92-lifecycle-bindings. The goal and evidence gap
were presented before product changes; no past implementation approval is inferred.

A private @muze-labs/simplyflow-events workspace package consumes app.events,
which the installed SimplyFlow constructor composes through its existing object
section rules. installEvents(view) adds an eventBindings controller without
replacing the SimplyFlow factory, touching dependencies' source, changing global
SimplyFlow or introducing content rendering/HTTP paths. External dependency
versions remain unchanged. Its README describes the experimental API and limits.

Descriptors name an action and either a window/EventTarget source or a custom
subscribe(notify) source returning an unsubscribe function. target/subscribe/when
run with app context; notifications resolve current SimplyFlow actions, retain
arguments/results and reuse action error handling. Conditions and descriptor
snapshots are evaluated at explicit start; no live rebinding observer is added.
Each activation has separate guarded callbacks so unsubscribe/restart cannot
revive stale delivery. Stop invalidates all callbacks before attempting every
cleanup. Startup/rollback handles synchronous notifications, reentrant lifecycle
calls, setup failures and app destruction before initialization completes.
Sources that fail before returning cleanup must undo their own partial setup.

The package wraps destruction outside the existing definition adapter, stopping
bindings before app cleanup. The adapter now guarantees underlying SimplyFlow
destruction through finally even when app cleanup throws. This is a narrow
lifecycle integration change, not a general plugin registry.

Workbench beforeunload/pagehide and shared account storage/conditional hashchange
are named component entries. Their original activation points and action policy
remain. Their handwritten listener registration/removal is replaced by controller
activation; transport/message/dialog/element behavior owners are unchanged.

Definition metadata now includes events. Build-time source extraction preserves
whole descriptor expressions, including activation predicates, with authored
origins. Existing function-source reconstruction recognizes descriptor metadata;
the browser fixture reconstructs and invokes an actual account predicate.

Node contracts and real-app browser fixtures cover custom EventTargets,
subscription sources, composition, current action replacement/restoration,
conditional registration, disposal, late activation and retained data. EVD98
records final results, earlier failures and evaluation limits separately.

No IDE, persistent override layer, live template/descriptor observer, account
ownership rewrite, new storage/sync policy or library publication is implemented.
This is the requested local experiment before considering future promotion.

# Demo experience implementation

Confirmed CYC181/SRC182 and DES183 govern these uncommitted changes.
Verified branch: spiral/CYC-20261113-QG24H-181-demo-experience.

- Reuse `muzeSolidDesignToolbar` in Files, Contacts, Preferences and the shared
  Profile view's existing action structure. Shared control display has lower
  specificity than structural visibility rules; controls initialize their own
  adapter tokens even outside a toolbar group. No second design system.
- Files: parent/open location toolbar, New folder disclosure/form and upload,
  contextual resource tools. Folder creation supplies an empty native Turtle
  graph through Metro's supported options to avoid the observed empty-body gap.
  Keep success-only reset/closure and existing failure handling.
- Contacts: search/add/sync above the list, neutral profile and delete tools;
  inline editing, native RDF, draft and picker ownership stay in existing APIs.
- Preferences: matching action controls and a restrained section divider;
  native settings, section keyboard behavior and synchronization stay intact.
- Workbench: editable `muzeSolidLauncherCatalog` dataset and app-owned
  `AppCatalog` module. SimplyFlow model owns search/sort and the bound list.
  Metro/document helpers and oldm/oldm-turtle handle reads and native caches;
  Solid Workspace IndexedDB stores account-scoped sources and native graphs.
  Reuse the existing manifest decoder and shortcut collection for addition.
  Adding an existing launch URL does not overwrite its icon/launch settings.
- `catalog/`: independently hostable static Turtle index, six suite manifests,
  Penny/Umai ordinary-link manifests and neutral external artwork. The build
  copies it to `www/catalog/`; this is local preparation, not publication.
  Multiple sources, cached refresh failure and source removal preserve existing
  shortcuts. Manifests are cached after successful use; uncached additions need
  a connection. External apps receive no fabricated capability declarations.
- No new external library version. Launcher declares its existing Solid Workspace
  dependency directly. The authorized local Cobalt tarball remains untouched.

Tests: catalog data/failure contracts, native catalog browser workflow and
native phone app-controls workflow. Existing browser appearance expectations
now assert the agreed neutral control/target instead of a filled button;
contact action visibility uses the changed toolbar class. Behavioral assertions
for editing, storage, preservation, cancellation and launch remain intact.

New artifacts remain uncommitted; exact new-artifact version references must be
pinned only when commits are authorized. No human acceptance, integration or
publication is inferred. Existing roadmap additions and app-priorities document
are preserved.

## Files design correction

The maintainer's review reopens the Files portion of this implementation.
The supplied study was read and its wide/phone previews inspected directly.
Files now uses an opt-in compact shell header (New, Upload, Refresh/More and
existing account controls), ancestor/current-folder breadcrumbs with a native
address disclosure, and a simple icon/name list. Existing Share/Delete remain
in per-entry native menus. Selected-file actions and linked filename complete
the desktop context row; phones use a separate Back/filename/action row.
Provider-specific formatting remains owned by the provider; no example-only
formatting or unsupported file operation is fabricated.

File list/view content owns scrolling below fixed context chrome. The old
phone-only location hiding rule and ancestor scrollIntoView calls are removed.
The browser root's mode binding is now inside the app's binding scope; panel
focus waits for that mode to apply. URL editing remains available alongside a
view. New-folder creation uses the existing dialog component, and native file
selection is activated from the app toolbar. Account and shared appearance
remain in the existing shell. Native graph/storage/provider lifecycle code is
retained, including guarded closure and cancellation.

## Additional Files review corrections

Location projection emits an empty ancestor list at root and a single root
entry for nested folders. Folder-choice UI projections carry depth via a
namespaced CSS custom property bound by SimplyFlow; logical padding caps deep
paths on phones. The Viewer limits .ttl requests to text/turtle via its existing
Metro client rather than text/* (which allowed negotiated HTML). Response MIME
handling and escaped source rendering remain intact. No dependency/storage
changes; automated browser coverage exercises root/nested location and real
server-observed Accept for embedded and standalone viewers.

## Catalog categories and Contacts bottom search

Catalog uses the shared dialog header/corner close, without a footer/Done.
Shared list/details supports native categories plus All apps, inline manual
shortcut entry and catalog sources. Existing SimplyFlow list model options own
category/search filtering via jaqt. Selecting a category updates button attributes
in place (preserving native keyboard focus); shared arrows/Tab/Back handle
navigation. App selection adds through existing shortcut code, reports feedback
and closes. More info opens an in-dialog text/image view, Back restores its link
focus, and Add remains available there. Screenshot URLs only bind on request.

Static native RDF fields provide categories/long text/optional screenshot, with
unknown data preserved by the existing cache. One authored Presenter preview
with example slide data demonstrates the optional screenshot (28956 B PNG).
The existing manual form is moved inline, not duplicated; validation errors keep
the form/dialog and native values, successful adds reset/close. The old add-dialog
command opens the manual category for compatibility. No new HTTP, authentication,
renderer, persistence format, library or publishing service.

Contacts list/recovery content scrolls independently above a bottom toolbar.
Search uses shared toolbar field/input controls. Existing model, native dialogs,
inline profiles, account handling and RDF operations remain. Focused browser
verification includes real filtering and long-list wheel scrolling with stable
bottom controls, plus category/More info/native manual recovery interactions.

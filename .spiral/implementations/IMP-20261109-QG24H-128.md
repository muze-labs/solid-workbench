# Shared account status and sign-in recovery

Active implementation of confirmed DES126 in CYC124. Branch verified as
spiral/CYC-20261109-QG24H-124-account-status before product changes.

Begin with typed recovery-message ownership and the smallest shared status
control, using SimplyFlow and existing native dialogs/storage notifications.
Inspect graph cost at this early checkpoint before broadening account controls.
No new dependency, renderer, HTTP client, token store or transport.

App boundary, offline/recovery, phone and accessibility commitments are retained
in CYC124/DES126. All account changes preserve local owner-scoped edits, distinguish
network state from authorization, and do not replay writes on login notices.

Planned global Disconnect/Logout and Workbench switch coordination follow the
checkpoint only if a readable implementation fits the unchanged graph limits.
This record does not claim evaluation, completion or acceptance. No commit or
publication is authorized. Causal Git references will follow when source/design
versions exist; uncommitted history is not invented.

## Final implementation, 2026-11-09

Continued on the mechanically verified CYC124 branch following the maintainer's
instruction to finish CYC124 and then CYC129. Earlier checkpoint-only wording
above is superseded. The explicit CYC129 instruction makes size thresholds
advisory; no size reduction or human acceptance is inferred.

The shared account feature owns its status button and native connection dialog.
It distinguishes usable authorization, stored authorization awaiting verification,
public access, intentional disconnection, recovery, connecting and connectivity.
Phone account-name sizing leaves space for the additional native control.
SimplyFlow owns all content and attributes; no renderer or dependency is added.

Errors retain their typed cause in shared/app-owned feedback. Existing Metro
storage events reconcile authentication-owned shared, Launcher and Preferences
messages, preserving unrelated errors and drafts and never reporting a failed
save as successful. Credential availability does not initiate an unrelated write.

Session transport checks the account's local disconnect intent before operations,
authorization and request dispatch. Disconnect cancels pending sign-in while
retaining WebID, credentials and local state, including through reload. Explicit
Connect releases the intent. A scalar, account-scoped localStorage flag records
browser connection policy; it is not app data, Pod state or a workspace snapshot.
The remembered issuer is non-secret discovery metadata so Logout can use Metro's
public credential stores after a disconnected reload without network discovery.
Logout clears credentials/remembered selection and leaves other open apps/local
owner-labelled data intact. Launcher-initiated logout first checkpoints its
workspace and closes its own managed apps. No HTTP DELETE or RDF format changes.

A managed child switching WebID asks Workbench through its existing private port.
The default broker denies account-control requests; Workbench grants its shipped
suite URLs explicitly, independent of advertised capabilities. Workbench focuses
its own dialog, checkpoints the old workspace before a switch, validates the new
session before closing old apps, and reloads into the new owner only afterward.
Failure/cancellation retains the old context. Logout invalidates late startup
results; connection attempts are invalidated by Cancel/Escape/Disconnect/Logout.

Same-origin suite apps share Metro stores and connection intent. External
standalone origins cannot be enumerated or signed out by this browser origin;
an arbitrary external provider is not granted account-control authority. This
implementation adds no cross-origin credential replication or token message.

Workbench checkpoints again after the candidate's sign-in completes and before
closing the old managed apps: sibling windows can receive edits while the
sign-in popup is open. A failed final checkpoint therefore leaves the old
workspace open instead of switching with an earlier snapshot.

Final offline review found that Contacts selected a fresh fallback collection
when account restore was deliberately paused. Its feature now retains a scalar
local dataset address scoped by WebID and workspace, reopening that same native
collection while disconnected. Explicit configuration/session discovery still
selects the resource when available; synchronization migrates a never-connected
fallback through the existing recoverCollection API. No RDF is copied into a
projection or JSON cache. The browser regression disconnects, reloads Contacts,
requires the same collection key and visible saved contact with zero Pod reads,
and explicitly reconnects afterward. A focused test checks owner/workspace
isolation of these remembered addresses. This necessary CYC124 correction was
made after switching back from CYC129 and verifying the CYC124 branch again;
no account code was changed on the budget branch.

Logout propagation is account-scoped. It removes the remembered WebID only when
it matches the account being logged out, and publishes an existing-style scalar
storage notice for that WebID. Other accounts' open sessions and remembered
selection are retained. The session transport captures that account's logout
generation and checks it before operations/dispatch, so retained clients stop
even before a sibling has handled the storage event. New connections capture
the current generation. Public Metro stores still own every credential.

Logout retains the same account's persistent local-only connection intent until
explicit Connect, in addition to clearing credentials and its remembered WebID.
The current signed-out view reports Not connected while preserving owner-labelled
local data. Reloading an old managed/account context therefore cannot silently
resume Pod reads. Focused logout contracts verify the retained intent and clear
status. The policy correction was made after another mechanically verified
return to CYC124; final CYC129 evaluation follows without product changes there.

The new shared Disconnect command is exposed as muzeSolidUiDisconnect, matching
the required reusable-component namespace. Its native control and regression
callers use the same public name. Existing accepted command names are retained.

The held-token cancellation regression exposed an additional session ownership
gap: signIn resolved the queued request's popup and also started a separate
forced authorized GET, allowing two OAuth flows to compete for the same window.
A pending sign-in now joins that request's completion and checks the public
usable-token state; a recovery with no queued request still uses the existing
forced probe. Request failure/cancellation owns the completion rejection. No
token, retry or authentication implementation is duplicated. The Metro client
fixture verifies one original conditional PUT and one popup with no parallel
probe, while the actual issuer/Pod browser regression verifies cancellation,
retry and exactly one conditional save.

Native focus diagnostics distinguished two boundaries. The provider fixture now
uses real account-menu clicks and keeps its isolated headless page active only
while testing Preferences; it restores normal activation before picker/tab work.
Product presentation focus now waits for the provider's existing explicit
presentation-ready message rather than equating the five-second visual fallback
with readiness. If readiness arrives after fallback, focus is requested then;
if focus is already inside the provider it is preserved. No new protocol or
renderer is introduced. Explicit successful sign-in also reconciles typed auth
feedback even when the pending resource response is a permission failure rather
than a successful HTTP callback; unrelated resource errors remain untouched.

## Account app revision, 2026-11-11

Within this same Active cycle, apps/account now owns the WebID form, account
feedback, button readiness and editable SimplyFlow templates/styles/commands.
The build emits /account/ and six complete graph reports. There is no Launcher
entry or separate icon and no new dependency version. The app is dialog-only;
opening its URL independently explains how to open it from a caller.

The shared account-presenter dataset owns a dedicated native modal/iframe and
uses the existing PortConnection transport. Explicit source-window/origin and
current-port/owner checks limit controls to the shipped Account frame and its
active caller. This is an app-specific privileged bridge, not a generic
capability grant; the generic presenter/broker remains unchanged. A synchronous
same-origin host hook reserves the popup inside Account's actual user gesture;
WindowProxy cannot be cloned over MessagePort. Session/Metro executes sign-in,
Disconnect and Logout in the caller. Workbench still checkpoints before and
after managed-switch candidate sign-in. No credentials are sent over ports.

Account uses plain display snapshots rather than cloning SimplyFlow proxies.
Draft WebID input stays with the caller across dialog close/retry; signed-out
state clears it. The app never owns a second session or workspace writer.
Closing invalidates connection attempts and releases its port/popup/frame,
leaving an active Preferences/Profile capability task intact. Loading failure
has Retry/Close and does not assume uncached assets exist offline. Escape from
inside the child document is forwarded through its scoped port because native
keyboard events do not cross iframe documents. Native host dialog closure owns
focus restoration. Final evaluation follows in EVD127; no acceptance is inferred.

Final focus/lifecycle refinement: observe the iframe's bound hidden attribute
before the one initial focus request. Retain its document through native modal
closure so native focus returns to the caller, then unload it. A Workbench-
coordinated reopening waits for any previous close completion and uses the
presentation generation to reject late unload/navigation. This uses the existing
shared dialog lifecycle, not a separate animation or focus-trap implementation.

## Maintainer review corrections: first Connect and Launcher, 2026-11-11

Only the shared account component changes in production for these corrections.
Fresh explicit Connect now awaits the existing session.signIn(popup) operation
before publishing its candidate; it uses the same path as a repeated Connect
and the existing generation check rejects cancelled/obsolete completion. Failed
sign-in leaves the prior session and local editor/drafts intact. Public-only
profiles remain public access; actual authentication uses the advertised issuer.

Completed fresh/repeated Connect sends an account-scoped UUID notice through
existing localStorage events. A recipient with no session restores its current
selected WebID through restoreAccount's existing noninteractive path. It waits
for startup, coalesces repeated notices and rechecks owner/connection intent and
attempt generation. An interactive local Connect takes precedence. Existing
live sessions reconcile their status through the established auth action. Other
owners' disconnect/completion notices do not switch this host's owner or cancel
its account operation. No workspace, RDF, renderer, CSS, token store or HTTP
implementation changes are added; app definitions retain editable actions.

The final implementation intentionally does not construct sessions from raw
OAuth store updates or the initial removal of Disconnect: those can precede
completion of another app's authorization. An early trial of that approach was
removed after the issuer fixture exposed an authorization-state mismatch. No
unused credential-hint API remains; the installed session APIs own sign-in.

The source/tests are uncommitted on local Metro branch fix/oauth2-redirect-iss.

there is no app runtime wrapper, filter, URL rewrite or extra auth mechanism.

## Compact connection feedback, 2026-11-11

Remove the persistent shared recovery section and its now-unused layout check.
Keep the recovery state for toolbar labels, existing sign-in commands and native
request dialogs. A transition to required authorization announces once via the
existing polite toast; repeated pending/background notifications do not repeat
it. Shared feedback ignores typed authorization-required and account-disconnected
errors, preserving unrelated conflict/task errors (including a disconnected
capability when the account itself is connected). Logout clears its persistent
status text; the toolbar retains account state.

Preferences no longer renders passive Connect-to-synchronize guidance and does
not attempt synchronization through an explicitly disconnected session. Local
choices/drafts remain preserved. Required-connection failures do not produce
retained status paragraphs; other save/conflict errors keep their feedback. The
existing swb-empty utility collapses an empty Preferences status paragraph.
No new network/storage/rendering path, dependency or component is introduced.

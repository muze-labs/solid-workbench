# Presenter: inline slides and reusable toolbars

The maintainer accepts the reviewed result and authorizes commit, merge and push.
SRC176/DES177 retain the rejected first UI and the confirmed revision; ACC180
will bind final acceptance to the committed implementation and evidence. The
historical notes below are superseded where later corrections explicitly say so.
The final implementation uses the authorized local Cobalt 0.1.1 tarball, its
composition guards and corrected presentation-only pointer suppression.

Presenter owns decks, slide order, backgrounds and local presentation. New slides
use one 16:9 background/centered-transparent-text composition, with numbered
thumbnails rather than names. The phone list becomes a horizontal strip; desktop
uses left thumbnails and the larger slide at right. Compact app actions sit beside
the title/account area. Deck storage and provider controls use disclosures.
Native fullscreen is requested from the initiating gesture, with viewport fallback;
arrow/Page keys and Previous/Next navigate, Escape exits and returns focus.

Shared solid-design features supply namespaced Feather icon/label controls and
viewport-clamped placement. The shell's optional action list dispatches to its
own app. Presenter is the first consumer; Files has no new toolbar UI. Contextual
text controls remain provider-owned inside its iframe, float near selection or
dock at the top. Ctrl+Space/Text tools opens them, native Tab reaches buttons,
Escape restores selection. Bold, Italic and safe Link controls are included.
Existing light/dark preferences remain authoritative.

The published @muze-labs/cobalt-rich-text-note 0.1.0 supplies the editor/render API.
Its editable surface owns editing DOM, as explicitly selected by the maintainer;
surrounding UI and read-only rendering remain SimplyFlow features and transformers.
A detached reactive fragment is observed after a completed Cobalt operation, so
intermediate text/range mutations never reach RDF writes or the preview. The
separate unpublished cobalt:change work is not linked or required. Cobalt's chunk
is imported by Presenter/Viewer only, avoiding its cost in unrelated app graphs.

The native fragment bridge follows Margin Notes' precedent: rdf:value, ordered
rdf:first/rest annotation lists, typed start/end/order and tag values. It preserves
unknown RDF, stable list/member identities and detached facts; unsupported stored
formatting refuses editing instead of flattening. Link and clipboard validation
covers the attributes Cobalt 0.1.0 can render. No fragment JSON is stored in Turtle.

Each completed editor change first saves a native local recovery draft. A scoped
notification contains no content; Presenter checks frame, origin and generation,
then reads over the existing private broker port. It writes the deck locally
before acknowledging that revision. Failed writes retain the frame/recovery draft;
retry must durably save even if the in-memory fragment already matches. A current
acknowledgement retires the provider copy so stale drafts cannot replace later
Pod content. Read/acknowledge use the existing owner-scoped EmbeddedView route.

Existing conditional Pod writes, native baselines, account separation, explicit
signed-out import, replacement guards, unknown data preservation and provider
close vetoes remain. Background selection reuses Files; image and thumbnail reads
use configured Metro clients. Object URLs are transient and cleared on account
change. Bounded text can scroll while editing; passive presentation refuses text
that does not fit and returns to the editable surface on exit.

Limits: one local deck per account, no multi-tab coordination or provider/image
installation cache. Cobalt 0.1.0 lacks undo/redo; physical-phone IME, manual AT and
broader editor styling remain follow-up. No remote presenting/export or general
layout editor is delivered. Historical text-only layouts remain native data;
new UI creates only the confirmed composition. EVD179 distinguishes fresh tests
from historical proof and human usability review.

Working provenance only: causal references must be pinned before any authorized
semantic commits. No historical acceptance or hashes are invented.

Evaluation correction: the separate composition probe in EVD179 establishes an
actual Cobalt 0.1.0 preservation gap, beyond the previously listed IME-review
limit. Its visible composition edits do not update native fragment state. This
implementation cannot yet be characterized as safe for phone/IME editing;
ordinary-input workflow success does not waive that condition. Scope of the
upstream correction is awaiting the maintainer's answer.

# Shared document-session implementation

DocumentSession in existing solid-app-data now owns owner checks, edit revisions,
serial recovery-write admission/retry and the shared conditional save state
transition. NotebookDocuments and DeckDocument inherit that owner rather than
carrying separate versions of its algorithm/state. Existing loadDocument,
saveDocument, session.perform and native storage APIs retain their responsibilities.
No renderer, HTTP mechanism, persistence format or npm dependency is introduced.

The shared save preserves the local copy before the remote operation, captures
native graph/revision, chooses existing/creation protection, checks any per-copy
creation intent, delegates the conditional PUT, writes the required baseline,
clears acknowledged intent and persists the binding/dirty acknowledgement.
Newer edits remain dirty. Failed recovery writes reject to their callers; later
explicit persistence can retry instead of inheriting a rejected promise forever.

Notebook owns its schema/index/blocks, per-recovery-copy baseline and native
creation-intent keys, redirect:error, Save As alias handling and target cleanup.
Its acknowledgement specialization preserves its void-return save API. Presenter
keeps its current deck, slide model/navigation/dirty-open guard, URL/owner-scoped
baseline factory and no creation reconciliation policy; it returns the saved
record. Open/New/selection/activation and file-operation repair remain app-owned.
Existing local storage names/keys and native recovery metadata are unchanged.

Both app APIs expose DocumentSession, and each definition identifies its matching
optional source module. Build composition emits one shared/document-session chunk
for these two consumers, keeping the runtime and optional source descriptor out
of unrelated app graphs. The optional asset stays unloaded during normal use.
Bundle tests enforce both the module inventory and per-app import ownership.

Fourteen cross-app observable cases characterize local ordering/retry, complete
native RDF, HTTP/account failures, edits during write, failed local acknowledgement,
no/weak validators and reload after a lost creation response. They pass both
against the pre-refactor app source (disposable loader) and the shared owner.
Existing app tests remain as independent richer model/policy evidence.

## Compatibility audit supersedes release readiness, 2026-11-11

The maintainer asks whether iss is required in all Metro OAuth2 workflows.
Audit confirms it is not: existing validateIssuer and reference.md accept
missing response iss unless authorization_response_iss_parameter_supported is
true, and callback-returned authorization results already exercise that policy.
Client-credentials and refresh grants have no browser authorization response.

The prepared b5d3b96 URL guard incorrectly requires iss before calling existing
validation. A disposable real two-page redirect probe reproduces the regression:
with a valid authorization code/state and absent iss, both advertised-support
false and true return isRedirected=false, start authorization a second time and
end authorization_not_completed. With matching iss, both yield HTTP 200 after
one authorization and one URL consumption. The strict-support case also skips
the required missing-issuer error. Probe: /tmp/metro-issuer-compatibility-probe.mjs
and /tmp/metro-issuer-compatibility-probe.log.

The 536-check pass did not cover missing-issuer page redirects; its missing-iss
test returns an object from authorize_callback, bypassing getTokensFromLocation.
Therefore passing tests/dry-run and archive inspection do not establish backward
compatibility. Prepared archives and source branch MUST NOT be treated as ready
for publication. Nothing has been published. The maintainer explicitly chose
Prepare the release only; lack of login is no longer the publication boundary.

Primary standards: RFC 6749 section 4.1.2 defines code/state without requiring
response iss; RFC 9207 introduces response iss and metadata defaults support
to false (section 3). RFC 9700 requires mix-up defenses for multiple servers but
does not universally require this transport parameter. Preserve issuer checking
when present/advertised and distinguish callback detection from validation.
https://www.rfc-editor.org/rfc/rfc6749.html#section-4.1.2
https://www.rfc-editor.org/rfc/rfc9207.html#section-3
https://www.rfc-editor.org/rfc/rfc9700.html#section-4.4.2

Recommendation pending confirmation: recognize callback code/error rather than
all fragments, preserving non-OAuth #webid anchors, and keep existing conditional
issuer/state validation. Add page-redirect tests for optional/required/mismatched
issuers and errors before regenerating corrected release archives. No product
change, new commit, push or publication is made during this audit.

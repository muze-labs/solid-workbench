# Notebook document workflow

Adds apps/notebook with editable SimplyFlow component entries for document
commands, native Cobalt editor lifecycles, model projections and core interaction.
NotebookDocuments uses the existing RDF fragment, local-source and conditional
HTTP document APIs. New/Open/Save/Save As and a native local-recovery list support
different documents. Ordered blocks support native editing, Bold/Italic/Link,
Add/Split/Join, keyboard split/join and boundary movement. Scope and ownership
are DES202; actual branch is spiral/CYC-20261114-QG24H-199-notebook.

Build/runtime integration includes a private app workspace, isolated published
notebook-controller chunk, optional authored source metadata, supplied SVG icon,
Workbench launch link and static catalog entry. Presenter and Viewer now use
published editor 0.1.1 after a byte-identical dist comparison. No external checkout
was edited and no new local dependency exception is introduced.

Unit tests cover distinct document identity/recovery, unknown-RDF retention,
unsupported content refusal, conditional creation and Save As, account mismatch,
conflict retention, invalid remote input and failed local activation. The native
Chrome scenario covers phone touch edits, formatting, split/join, composition
guards, independent documents, remote open/save, conflicts, offline text recovery,
keyboard structure, labels, themes and optional-source isolation. Build graph
checks include the ninth app and its private controller. No acceptance inferred.


Document chrome now follows the maintainer's explicit review direction: visible
shared-style document toolbar with Feather icons; shared document-name heading
and edit-title action; native shared rename dialog and synchronized tab title;
unnumbered borderless block surfaces with subtle focused highlighting. Native
Notebook regression covers dialog cancel/rename, escaped text, title transitions
and reload, action visibility and phone reflow. Evaluation is recorded in EVD201;
no acceptance is inferred.

The final requested refinement supersedes the intermediate document toolbar:
all tools use the shared header action list. Native Open/Save As/rename/link
dialogs replace disclosures; split/join/add/selection controls and their obsolete
commands are removed. Ctrl/Cmd+K opens the link dialog, supports selected text or
linked-address insertion through public APIs and returns editing focus. Touch
selection remains native, with boundary deletion supported via beforeinput.
Native regressions use actual header commands, dialog submissions and keyboard
split/join/selection; recovery tests retain the multiple-document contracts.

Document status now occupies a native header popover button with explicit
local/Pod/busy/attention icons, accessible names and exact message on activation.
Routine text is removed from the editor area; failure announcements and dialog
errors remain available. The current focus surface/outline is retained after
explicit maintainer approval. Regression checks inspect actual icons and native
popover open/Escape alongside persistence and conditional-save failure states.


Preferred-picker correction removes Notebook's URL form and invokes browse via
the shared capability presenter. Existing managed routing and standalone public
WorkspaceBroker use the user's browseProvider; Files is only the default.
Open/save modes and suggestedName are documented and validated in the existing
experimental contract. Files reuses its model/navigation and exposes filename
selection only for save requests, refusing path separators and listed names.
Notebook conditionally creates native RDF at the returned destination and
preserves old document/remote bytes on cancellation or a late collision. Recent
notebooks retain device-only recovery access through a clock tool. No new npm
dependency, transport, HTTP path or local JSON-in-Turtle is introduced.

Unit checks cover request validation and new destination selection/refusal.
Native tests configure a distinct preferred Files route in profile-linked
preferences, exercise real embedded capability calls, navigate subfolders,
create separate files, cancel Open/Save As, refuse filename/path collisions and
retain both sides of a race. Generic picker reflow checks count visible controls;
the save form also exercises input/button containment at 320px and 200% text.
EVD201 records exact final check results and delivery limits.


Contextual toolbar correction adds muzeSolidNotebookBlockTools and a separate
muzeSolidNotebookRichTextTools feature. The editable runtime API registry keys
controls by adapter getType(); shared native buttons use current feature commands
and state actions. SimplyFlow renders floating controls or the header projection;

Selection or Ctrl+Space opens floating tools, with native selection preserved and

Native browser checks cover reveal/dismissal, focus preservation, formatting in
both placements, header state when switching blocks, a fixture alternative type
and command target, document preservation, narrow-screen/enlarged-text bounds and
existing editing/recovery workflows. Fixture media tools only demonstrate runtime

Transition hardening invalidates the toolbar context on document projection so
old rows cannot be queried without an active adapter definition. Changing

after Escape from docked tools. Regression checks preserve the range, verify
actual pointer hit targets after scrolling/placement, wait for final screenshot

The subsequent user review adds explicit first-block focus for opening/New and
selected-text Bold recovery. Project accepts a focusFirst option for document

with Recent selection waiting for its dialog to close. Structural and title/link
focus contracts remain in place. Floating controls now retain a measurable hidden

text and toggling off, and require initial/New/Recent editing focus. Clipboard

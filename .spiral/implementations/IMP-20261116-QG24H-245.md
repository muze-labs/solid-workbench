# Independent Preferences implementation

CYC242, verified branch spiral/CYC-20261116-QG24H-242-independent-preferences.
Implements the confirmed goal and app-hosted execution boundary in SRC243/DES244.
Records remain uncommitted; no upstream commit identifiers are invented.

Preferences accepts arbitrary nonempty app identifiers with existing capability
and selected-owner checks. Optional section descriptors are validated against
broker-supplied caller origin, not an asserted input origin. Native common
settings remain unchanged. No contribution means common settings only.

A local existing WorkspaceBroker owns one selected app-hosted EmbeddedView.
Provider URL checks, private ports and prepare/freeze/close contracts are reused;
no general nested permission is added to the outer broker. Failed-startup views
can be released, started providers can veto navigation, and unavailable providers
have explicit retry/discard. The app owns rendering, persistence and recovery.

Files advertises its settings view from the account-menu invocation. Its separate
build entry uses the existing PreferenceState/PreferenceDrafts, conditional
synchronization and native local state. Workspace operations pass through the
existing Workbench writer via a bridge restricted to declared supported keys,
calling workspace, selected owner and read/settings operations. There is no
second transport, writer, renderer or third-party executable import.

Runtime components remain editable SimplyFlow datasets; matching authoring assets
remain optional. Provider UI is loaded only when selected. The new browser
regression includes an independent caller/provider on a second origin without
requiring the suite UI, plus native keyboard input and phone touch navigation.

Boundary limit: Files account-menu settings migrate in this slice. The existing
standalone Preferences app selector and other built-in panels keep their legacy
composition. Do not claim every built-in import has been removed. Independent
apps and their changed descriptors require no Preferences rebuild. New independent
settings data belongs to that app; workspaceKeys is only the existing suite
workspace-setting bridge, not a general schema/form API.

Complexity review: the public metadata validator and local view owner remove the
fixed-caller requirement without a plugin runtime or protocol rewrite. Files
keeps app-specific persistence/UI decisions. Additional built-in migration may
reduce remaining duplication, but is not evidence for another generic abstraction.
No dependency changes, publication, commit, integration or acceptance inferred.


## Account chrome correction

At the maintainer's request, remove the shared task-only WebID/connection button.
Both account-menu visibility and the embedded layout marker now follow
host.embedded rather than task identity. Separate tab/window tasks retain the
normal account dropdown and title. Embedded providers retain recovery mechanisms
but use their containing app for ordinary account controls. Browser coverage
replaces the obsolete task-button assertion with absent embedded account chrome,
retained Preferences drafts across parent Account use, and a separate-window
task's actual dropdown-to-Account interaction. No CSS changes are needed.


## Content-owned embedded header spacing

Following the maintainer's review and explicit simpler-spacing direction, remove
embedded header minimum height and set embedded header margin/padding/minimum
block size to zero in the page layer, including compact layouts. Existing visible
children own their spacing/control height; an empty header naturally has no box
height. There is no content-detection or display:none rule. Remove the obsolete
recovery-specific ancestor-hiding selector; the native modal remains rendered
and can receive focus even when the surrounding header is empty. Standalone
window chrome retains its existing presentation. No persistence/API changes.

# Shared Workbench library runtime and initial live replacement path

Workbench runtime modules initialize the Metro, jaqt, oldm and Simply globals
from the installed public APIs. Runtime bootstrap imports are the dependency
boundary. Application code and shared Workbench modules call the globals
directly. View APIs carry app-specific dependencies.
The work preserves Metro clients and credential stores, SimplyFlow models,
and the selected OLDM Turtle context. SimplySolid stays in the UI graph under
`simply.solid`. The authentication callback still enters through JSFS-Solid.

The Contacts query effect resolves its named filter action for each model
evaluation. A running refresh resolves the shared `isPerson` API from its app
context. The authored versions of the action and helper are shipped by the
existing optional source-asset mechanism. The Chrome fixture reconstructs both,
switches behavior in the same app, and checks restoration, the active edit draft
and native graph identity.

## Launcher and Presenter proofs

Launcher exposes a per-app group API with an optional source descriptor.
`setShortcutGroup` resolves the current reader on that API before touching
the graph. Existing named module calls use the original group API.

Presenter's original thumbnail transformer takes the two binding arguments
and an explicit third argument for the app API. A stable registered
transformer forwards each render to the current
`api.muzeSolidPresenterRichText`, supplying the binding receiver and the
live app's API. SimplyFlow merges component and app APIs into its effective
app object. The bridge resolves that object after construction. Cobalt and
fragment validation use the existing Presenter API entries.

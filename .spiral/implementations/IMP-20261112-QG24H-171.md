# Files and shared view implementation

Files now has a responsive list/details pane that opens the viewer on selection.
The filename links to its standalone view with native modified-click behavior.
The embedded view has no default border or duplicate toolbar; loading uses the
shared Preferences presentation, and recovery controls appear only on errors.
Filename ellipses and full-name tooltips keep the list compact and let the details
heading use its available width without overflowing the viewport. Selection labels remain attached to the old
resource until its provider approves replacement. Dedicated picker UI remains.

EmbeddedView reuses the existing broker ticket/port and adds finite persistent
lifecycle requests. View tickets coexist with modal tasks and stay absent from
workspace snapshots. Parent closure and workspace/account transitions preserve
refused or unreachable views; explicit discard is separate. Defaults and custom
viewer choices reuse native RDF provider preferences and preserve other bindings.

The separate Resource Viewer app reads `text/*` and PNG/JPEG/GIF/WebP through
its own Metro session (anonymous Metro for public resources). HTML is shown as escaped source. SVG and other unsupported non-text media
types are refused. MIME type matching ignores case and parameters. It is useful at its own URL. Text remains escaped, images
are decoded before ready, loaded content survives refresh errors and offline
refresh, and appearance changes preserve content. Runtime views hold no secrets
or serialized content in RDF. Editable feature datasets remain available.

No external dependency was added. The existing workspace SimplyFlow events
package supplies app event declarations. Build now includes seven apps; shared
capability infrastructure remains experimental. No Presenter, editor, widget,
semantic ranking or full Weblets compatibility is claimed. Both authorized
cycles remain on independent branches and await human acceptance; no commits,
merges or pushes have been made.

Automatic selection exposed a same-provider reopening issue: SimplyFlow can
coalesce closing to about:blank and opening the same URL, leaving the old frame
alive. Each opening now carries its existing generation in the already-used
solid-apps-task query parameter. Existing consumers check its presence and the
broker removes it for configured-provider comparison. This causes a fresh native
navigation without manual rendering, a new query field or extra HTTP requests.
The independent cross-origin rapid-selection test covers the resulting lifecycle.

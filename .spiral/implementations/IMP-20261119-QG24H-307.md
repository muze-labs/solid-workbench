# Add the dockable read-only app inspector

The shared Account dropdown exposes Inspect alongside Preferences when
the app is top-level. The standalone Account app uses its own Inspect
button. Each app supplies its live definition after mounting. The
inspector controller and panel load on the first open.

The controller selects a control by pointer or keyboard and shows a
crosshair during picking. Dimming and the pick hint identify
embedded frames as outside the current document’s inspection. It reads
SimplyFlow's binding path and template marker in the owning app and looks
up the originating component and active command. Parents with these
relationships can be inspected in place. A data link opens the template
containing the authored binding and labels it with the runtime path.
Breadcrumbs record the path taken from the picked element and restore
an earlier selection when activated. Chevrons separate compact entries.
Long labels show an ellipsis while preserving their full text.
The Data preview reads the current value from the inspected app with
SimplyFlow's binding-path resolver. It displays ordinary values as
formatted JSON and OLDM values through the existing Turtle writer.
Named-node previews show the selected subject. Standalone RDF terms
use a preview-only subject with `rdf:value` so the result remains
valid [RDF 1.1 Turtle](https://www.w3.org/TR/turtle/).
It includes authored source when there is a definition
or source file to show. Other relationships without a source remain
readable as text, and parent navigation is still available.
Source starts closed for each inspection. On request, the panel renders
escaped source and its origin directly under the activating entry in a
dedicated SimplyFlow instance. One preview stays open at a time. The
source area scrolls independently and the preview close button returns
focus to its trigger. Activating the trigger again also closes the preview.
The inspector uses icon-only shared toolbar
controls beside the title and the shared dialog X. The Account dropdown
follows its trigger when the dock changes the app's layout.
The optional authoring modules also expose the original component
declaration. Runtime template and command definitions remain available
when their optional sources cannot be loaded.

The sidebar and popup load the same panel. The inspected app owns the
current selection. A panel can connect through its same-origin owner
when its window is the registered dock frame or popup. The native popup
request runs directly on activation. Blocked or disconnected windows
leave an available dock and explain the failure. The presentation toggle
stores the selected mode on this Workbench origin. Dismissing the panel
with its own X or closing the browser window preserves that choice for
the next Inspect action. If the controller has yet to load, the Inspect
click reserves the popup before loading it. Successful popup and dock
transitions have no status announcement. On wide screens the dock
reserves space beside the app. On narrow screens the user can
temporarily dismiss the panel to pick an element.

On larger viewports the dock has a focusable left-edge separator. Drag
or arrow keys change the width and the space reserved in the app.
Home and End move to the width limits. The input behavior is a reusable
internal helper and loads with the inspector. The separator follows
[WAI-ARIA 1.2](https://www.w3.org/TR/wai-aria-1.2/#separator) for its
current range and [the window splitter pattern](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)
for vertical orientation, labeling and keyboard sizing.
The panel follows the host's light or dark preference and mixes the
Workbench surface and chrome colors to distinguish its background.

Workbench uses published SimplyFlow 0.10.7. Its pinned dependencies are
app 0.10.6, bind 0.10.4, model 0.10.4, and state 0.10.3.
